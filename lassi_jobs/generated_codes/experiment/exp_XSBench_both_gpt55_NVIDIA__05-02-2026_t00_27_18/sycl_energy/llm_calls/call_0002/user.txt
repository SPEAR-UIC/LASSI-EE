## 1. Overall algorithm and GPU resource-utilization profile

### Algorithm

The program implements the event-based XSBench cross-section lookup workload. For each lookup:

1. Generate a deterministic pseudo-random particle energy using a 64-bit LCG.
2. Generate a pseudo-random material ID.
3. Compute macroscopic cross sections for that material by:
   - locating the relevant energy interval in either a unionized grid, per-nuclide grid, or hash grid,
   - interpolating microscopic cross sections for each nuclide in the material,
   - accumulating five macroscopic cross-section components.
4. Select the largest of the five accumulated values and write a small verification value.
5. Reduce the verification array on the device.

The baseline performs sampling and cross-section lookup in one kernel. Optimized variants split sampling from lookup and attempt to reduce divergence by launching material-specific or fuel/non-fuel-specific lookup kernels, sometimes after sorting or partitioning the sample arrays.

### Compute-bound vs memory-bound behavior

The dominant lookup kernels are expected to be memory-bound on Intel Data Center GPU Max / PVC.

Reasons:

- The main data structure, `nuclide_grid`, is large and accessed through data-dependent indices.
- The unionized and hash index grids introduce additional indirect global memory accesses.
- Binary searches over energy grids perform many unpredictable global loads.
- Adjacent work-items usually operate on different random particle energies and often different materials, so memory references are not naturally aligned across a sub-group.
- Each lookup performs some double-precision interpolation and accumulation, but the arithmetic intensity is low relative to the amount of irregular memory traffic.

PVC has strong FP64 throughput, so double-precision arithmetic itself is unlikely to be the limiting factor unless the working set becomes cache-resident. The primary energy-efficiency issue is wasted memory movement and memory-latency stalls rather than peak compute utilization.

### Access regularity

The workload combines:

- Sequential accesses:
  - sampling writes to `p_energy_samples[i]` and `mat_samples[i]`,
  - verification writes to `verification[i]`,
  - reduction reads chunks of `verification`,
  - count kernels linearly scan `mat_samples`.

- Irregular/random accesses:
  - binary search over `unionized_energy_array`,
  - binary search over per-nuclide energy grids,
  - indirect lookup through `index_grid`,
  - indirect access into `nuclide_grid`,
  - material-dependent access into `mats` and `concs`.

The cross-section lookup phase is dominated by irregular, data-dependent reads.

### Energy-efficiency opportunities

- Prefer variants that reduce divergence and improve locality, especially material-sorted or energy-sorted variants, but avoid host-side sorting because it introduces expensive device-to-host and host-to-device transfers.
- Replace the CPU sorting/partitioning helpers with device-side oneDPL or custom GPU kernels if sorting is retained.
- Consider using the hash grid mode with tuned bin count to reduce binary-search work while avoiding the extremely large unionized index grid, depending on accuracy and memory-capacity constraints.
- Consider converting high-volume double data to float if validation allows; this would reduce memory bandwidth, cache pressure, register pressure, and energy per lookup.
- Restructure `NuclideGridPoint` from array-of-structures to structure-of-arrays if profiling shows inefficient cache-line utilization or poor vector memory coalescing.
- Cache material metadata in SLM or constant/read-only cache style storage, especially for material-specific kernels.
- Avoid launching twelve full-size material kernels with mostly inactive work-items unless samples are compacted by material.

## 2. SYCL kernel launch configurations and likely occupancy on PVC

### Important observation

The code does not use explicit `sycl::nd_range`. All kernels are launched with `sycl::range<1>`, so there is no programmer-specified local work-group size.

The variables named `nthreads` and `nblocks` only determine the global range size. They do not impose CUDA-like block size or SYCL local range. Therefore, likely occupancy cannot be inferred directly from `nthreads = 32` or `nthreads = 256`.

On PVC, actual occupancy depends on:

- compiler-selected SIMD width,
- runtime-selected work-group decomposition,
- register/GRF pressure,
- private memory usage,
- SLM usage,
- memory latency,
- number of active EUs and hardware threads per EU.

Because no SLM is used and no explicit local size is requested, occupancy is mostly constrained by register pressure and memory stalls.

### Kernel launch summary

#### Baseline simulation

- Main lookup kernel:
  - Global range: rounded up to `ceil(lookups / 256) * 256`.
  - Local range: not specified.
  - One work-item per lookup.
  - Occupancy expectation: moderate. No SLM, but significant private state and inlined function bodies. Memory stalls dominate.

#### Optimization 1

- Sampling kernel:
  - Global range: `ceil(lookups / 32) * 32`.
  - Local range: not specified.
  - Occupancy expectation: high to moderate. Mostly register and integer-heavy due to LCG fast-forwarding.

- Lookup kernel:
  - Global range: `ceil(lookups / 32) * 32`.
  - Local range: not specified.
  - Occupancy expectation: moderate, memory-latency-bound, with private double arrays.

#### Optimization 2

- Sampling kernel:
  - Same as Optimization 1.

- Twelve material-specific lookup kernels:
  - Each kernel uses global range `ceil(lookups / 32) * 32`.
  - Local range: not specified.
  - Each kernel exits early for work-items whose sampled material does not match the kernel’s material.
  - Occupancy expectation: nominal occupancy may be high, but effective useful occupancy is poor because most work-items return early in each material kernel. This wastes scheduling, launch, and memory-read energy.

#### Optimization 3

- Sampling kernel:
  - Same as Optimization 1.

- Two lookup kernels:
  - Each uses global range `ceil(lookups / 32) * 32`.
  - One processes fuel material, one processes non-fuel materials.
  - Local range: not specified.
  - Occupancy expectation: better than Optimization 2 because only two passes are made, but each kernel still contains branch filtering and the non-fuel kernel still has mixed material sizes.

#### Optimization 4

- Sampling kernel:
  - Global range: `ceil(lookups / 32) * 32`.

- Twelve `count_equal_device` kernels:
  - Each global range: `lookups`.
  - Local range: not specified.
  - Uses global atomics into one counter per material count.
  - Occupancy expectation: high nominal occupancy but poor atomic efficiency due to contention.

- Host-side sort by material:
  - Copies `mat_samples` and `p_energy_samples` to host, sorts on CPU, copies back to device.
  - This is a major energy-efficiency concern.

- Twelve compacted material lookup kernels:
  - For material `m`, global range: `ceil(n_lookups_per_material[m] / 32) * 32`.
  - Local range: not specified.
  - Occupancy expectation: better effective occupancy than Optimization 2 because each kernel works mostly on matching material samples. Material-specific loop trip counts become uniform within each kernel.

#### Optimization 5

- Sampling kernel:
  - Global range: `ceil(lookups / 32) * 32`.

- One `count_equal_device` kernel:
  - Global range: `lookups`.
  - Counts fuel samples.

- Host-side partition into fuel and non-fuel:
  - Copies sample arrays to host, partitions, copies back.
  - Energy-expensive due to host/device transfers.

- Two compacted lookup kernels:
  - Fuel global range: `ceil(n_fuel_lookups / 32) * 32`.
  - Non-fuel global range: `ceil((lookups - n_fuel_lookups) / 32) * 32`.
  - Local range: not specified.
  - Occupancy expectation: fuel kernel has good material uniformity; non-fuel kernel still has mixed material loop lengths.

#### Optimization 6

- Sampling kernel:
  - Global range: `ceil(lookups / 32) * 32`.

- Twelve `count_equal_device` kernels:
  - Each global range: `lookups`.

- Host-side material sort:
  - Device-to-host and host-to-device transfers.

- Host-side energy sort within each material segment:
  - Additional device-to-host and host-to-device transfers for each segment.
  - Energy-expensive, but may improve lookup locality.

- Twelve compacted material lookup kernels:
  - Same kernel body as Optimization 4.
  - Global range per material: `ceil(n_lookups_per_material[m] / 32) * 32`.
  - Local range: not specified.
  - Occupancy expectation: best lookup coherence among the provided variants because material and energy locality are improved, but the sorting implementation is not energy-efficient.

#### Reduction kernel in `reduce_verification_device`

- Iterative reduction.
- Each pass launches global range `next_n`, where `next_n = ceil(current_n / 256)`.
- Each work-item serially sums up to 256 elements.
- Local range: not specified.
- Occupancy expectation: nominally high, but memory access is not ideal for sub-group coalescing because adjacent work-items read chunks separated by 256 elements at the same inner-loop position.

#### Count kernel in `count_equal_device`

- Global range: `n`.
- Local range: not specified.
- One global atomic increment target.
- Occupancy expectation: high nominal occupancy but poor scalability and high energy per useful count due to atomic contention.

## 3. Global USM memory access patterns and sub-group coalescing

### USM allocation model

The code uses device USM through `sycl::malloc_device`. The main GPU-resident arrays are:

- `num_nucs`
- `concs`
- `mats`
- `unionized_energy_array`
- `index_grid`
- `nuclide_grid`
- `verification`
- optional `p_energy_samples`
- optional `mat_samples`

### Coalesced or mostly coalesced accesses

The following accesses are generally coalesced for consecutive work-items in a sub-group:

- Sampling writes:
  - `p_energy_samples[i]`
  - `mat_samples[i]`

- Lookup input reads in optimized variants:
  - `p_energy_samples[i]`
  - `mat_samples[i]`

- Verification writes:
  - `verification[i]`

- Count kernel reads:
  - `mat_samples[i]`

These are linear in the global work-item ID.

### Poorly coalesced or uncoalesced accesses

The dominant lookup accesses are generally not coalesced across sub-groups:

- `unionized_energy_array` during binary search:
  - Each work-item searches for a different random energy.
  - Binary-search paths diverge.
  - Adjacent lanes are unlikely to read the same or adjacent energy locations unless energy sorting has been applied.

- `index_grid`:
  - Access pattern is based on `idx * n_isotopes + nuc`.
  - `idx` is energy-dependent and varies across work-items.
  - `nuc` follows material-specific nuclide lists.
  - Material sorting helps because lanes process the same material, but energy-dependent `idx` still varies.

- `nuclide_grid`:
  - Accessed through material nuclide ID and energy index.
  - The layout is array-of-structures, with each `NuclideGridPoint` containing six doubles.
  - Each interpolation reads a low and high grid point.
  - Across lanes, the nuclide and energy index are often different, so accesses are usually scattered.

- `mats` and `concs`:
  - In unsorted kernels, material varies across lanes, so these accesses diverge.
  - In material-specific sorted kernels, these accesses become much more coherent because all lanes use the same material and loop over the same nuclide list.

### Reduction memory pattern

The reduction kernel assigns one work-item to a chunk of 256 verification values. Each work-item reads its own chunk sequentially. However, adjacent work-items read different chunks, so at the same inner-loop iteration, adjacent sub-group lanes read locations separated by 256 elements. That is not an ideal sub-group-coalesced pattern.

A more energy-efficient reduction would use work-groups where adjacent work-items read adjacent elements and then reduce using sub-group operations and/or SLM.

### Effect of the optimized variants

- Optimization 1:
  - Adds coalesced sample arrays but does not improve lookup locality.
  - Also adds extra global writes and reads.

- Optimization 2:
  - Performs twelve full passes over the sample arrays.
  - Reads `mat_samples` coalesced, but most work-items return early.
  - Poor energy efficiency because of repeated scanning and kernel launches.

- Optimization 3:
  - Reduces full passes from twelve to two.
  - Improves energy compared with Optimization 2 but still has branch filtering.

- Optimization 4:
  - Material sorting improves coherence of `mats`, `concs`, `num_nucs`, and loop trip counts.
  - Host-side sorting is energy-expensive.

- Optimization 5:
  - Fuel/non-fuel partitioning improves the fuel-heavy path but leaves non-fuel divergence.

- Optimization 6:
  - Material plus energy sorting gives the best chance for cache reuse and more coherent binary-search paths.
  - The current host-side sort implementation likely consumes substantial energy and may dominate for smaller or moderate lookup counts.

## 4. Shared local memory / SLM usage

### Current SLM usage

No explicit SLM is used.

There are also no local accessors, no local memory tiles, and no group-level reductions.

### Current private memory usage

The lookup kernels use private per-work-item arrays:

- `macro_xs_vector[5]`
- `xs_vector[5]`

These are double arrays. They may remain in registers, but depending on compiler decisions and register pressure, they can increase GRF usage or spill to private memory.

### Potential SLM opportunities

#### Material metadata caching

The arrays `num_nucs`, `mats`, and `concs` are small compared with the grid data. In material-specific kernels, all work-items in a group use the same material. This makes them good candidates for SLM caching.

For example:

- `num_nucs[m]` is uniform.
- `mats[m, j]` is reused by every work-item processing material `m`.
- `concs[m, j]` is reused by every work-item processing material `m`.

Fuel material can have up to 321 nuclides, so caching its material list and concentrations requires only a few kilobytes, well within PVC SLM capacity.

Potential benefit:

- lower repeated global memory traffic,
- lower cache pressure,
- improved energy per lookup.

Cost:

- one group-level preload,
- one group barrier after preload,
- some SLM capacity per work-group.

Because SLM use is currently zero, moderate SLM use for material metadata is unlikely to be the primary occupancy limiter.

#### Reduction using SLM or sub-groups

The verification reduction is currently inefficient. A more energy-efficient design would:

- have adjacent work-items read adjacent verification elements,
- reduce within sub-groups,
- optionally use SLM for work-group partial sums,
- write one partial sum per work-group.

This would improve memory coalescing and reduce redundant global memory traffic.

#### Energy-grid or nuclide-grid caching

Caching the full energy or nuclide grid in SLM is generally not practical because the grids are large and accesses are random. However, after energy sorting, nearby work-items may access nearby regions. There may be limited opportunities to cache small windows of `unionized_energy_array` or `nuclide_grid`, but the benefit is less certain than material metadata caching.

## 5. Sub-group divergence and conditional branches inside kernels

### Common divergence sources

The lookup kernels contain substantial divergence from:

- bounds checks,
- material-dependent loop lengths,
- binary-search branch decisions,
- grid-type branches,
- energy boundary handling,
- max-selection branches,
- early returns in material-filtered kernels.

On PVC, this reduces SIMD efficiency. Material and energy sorting can improve branch coherence.

### Sampling kernel divergence

The sampling kernel includes:

- bounds check for `i >= lookups`,
- LCG fast-forward loop with condition based on `n`,
- branch on low bit of `n`,
- material selection loop with `roll < running`,
- early return from material selection.

The LCG fast-forward branch pattern differs by work-item index, so it can cause SIMD divergence.

### Baseline lookup kernel divergence

The baseline kernel includes:

- bounds check for `i >= lookups`,
- all sampling divergence listed above,
- grid-type branch inside macroscopic/microscopic lookup,
- binary-search branches,
- material-dependent nuclide loop length,
- interpolation boundary branches,
- max-selection branch over five cross-section components.

Because each work-item independently samples material and energy, divergence is high.

### Optimization 1 lookup divergence

The lookup kernel removes sampling from the lookup phase but still includes:

- bounds check,
- grid-type branches,
- binary-search branches,
- material-dependent loop length,
- interpolation boundary branches,
- max-selection branches.

Material and energy are still unsorted, so divergence remains high.

### Optimization 2 lookup divergence

Each of the twelve material kernels includes:

- bounds check,
- load sampled material,
- early return if sampled material does not match the kernel’s material,
- all lookup divergence for active work-items.

This reduces material-loop divergence among active work-items but wastes energy because most lanes are inactive in each material pass.

### Optimization 3 lookup divergence

Each of the two fuel/non-fuel kernels includes:

- bounds check,
- fuel/non-fuel condition,
- all lookup divergence for active work-items.

The fuel kernel is relatively coherent because material 0 dominates a long uniform loop. The non-fuel kernel still mixes many materials with different nuclide counts.

### Optimization 4 lookup divergence

After material sorting, each material-specific kernel includes:

- bounds check against that material’s compacted count,
- a material equality check that should normally be true after sorting,
- lookup divergence.

This is more SIMD-friendly because the material and loop length are uniform within each material kernel.

### Optimization 5 lookup divergence

After fuel/non-fuel partitioning:

- the fuel kernel has uniform material behavior,
- the non-fuel kernel still has mixed material behavior,
- both kernels retain energy-search divergence.

### Optimization 6 lookup divergence

After material and energy sorting:

- material loop divergence is reduced,
- energy-search paths are more coherent among neighboring work-items,
- cache locality should improve,
- remaining divergence comes from binary-search comparisons, interpolation boundary cases, and max-selection branches.

This is likely the best lookup-kernel structure for SIMD efficiency, but the current host-side sorting implementation is energy-inefficient.

### Reduction kernel divergence

The reduction kernel includes:

- end-of-chunk bounds clamp,
- loop over chunk elements.

Only the final chunk is shorter, so divergence is limited.

### Count kernel divergence

The count kernel includes:

- comparison against the target material,
- atomic increment only for matching work-items.

The branch is data-dependent. The atomic target is highly contended.

## 6. Data types and double-precision operations that may be replaceable with float

### Double-heavy data structures

The following high-volume or frequently used values are double precision:

- `NuclideGridPoint.energy`
- `NuclideGridPoint.total_xs`
- `NuclideGridPoint.elastic_xs`
- `NuclideGridPoint.absorbtion_xs`
- `NuclideGridPoint.fission_xs`
- `NuclideGridPoint.nu_fission_xs`
- `concs`
- `unionized_energy_array`
- `p_energy_samples`
- local `macro_xs_vector`
- local `xs_vector`
- interpolation factor `f`
- sampled particle energy `p_energy`

These dominate memory traffic in the lookup phase.

### Candidate float conversions

If validation and checksum requirements allow, the best candidates for conversion to float are:

- particle energies,
- unionized energy grid,
- nuclide energy values,
- cross-section values,
- concentrations,
- interpolation arithmetic,
- macroscopic and microscopic XS vectors.

Potential benefits on PVC:

- roughly half the memory traffic for these arrays,
- better cache residency,
- reduced register footprint,
- reduced private-memory pressure,
- lower energy per lookup.

### Values that should remain integer or 64-bit

The LCG seed arithmetic should remain 64-bit integer because it defines the deterministic random sequence.

Index and length types should be changed only with great care. Some unionized-grid configurations can produce very large `index_grid` sizes, so 64-bit length arithmetic may be required even if individual per-nuclide indices fit in 32 bits.

### Validation caution

Changing double to float can change:

- binary-search decisions near equal energies,
- interpolation results,
- max-index selection,
- final verification checksum.

Therefore, float conversion is an energy-efficiency opportunity only if the required numerical behavior permits it.

## 8. Unusual loop bounds or comparison operators — INTENTIONAL, preserve verbatim

The following constructs appear unusual or delicate. They should be treated as INTENTIONAL and preserved verbatim unless there is a validated algorithmic change.

### INTENTIONAL: material sampling accumulation in `pick_mat`

The material picker accumulates probabilities using an inner loop that starts from the current material index and decrements while the index is greater than zero. This excludes the zero-th distribution element from the running sum. Material 0 is returned by the final fallback path.

This is unusual, but it affects the deterministic material distribution and checksum. Preserve verbatim.

### INTENTIONAL: binary-search termination condition

Both grid-search routines use a loop that continues while the interval length is greater than one and then returns the lower limit.

This exact lower-bound behavior is used by later interpolation logic. Preserve verbatim.

### INTENTIONAL: binary-search comparison direction

The search compares the examined energy against the quarry energy using a strict greater-than test and updates either the upper or lower limit.

This determines the selected lower energy index. Preserve verbatim.

### INTENTIONAL: unionized-grid boundary handling

The microscopic lookup checks whether the index-grid value equals the last grid point and then backs up by one element when needed.

This prevents selecting an invalid high point during interpolation. Preserve verbatim.

### INTENTIONAL: hash-grid upper-bin handling

The hash-grid path checks whether the hash bin index is the last bin and uses the final nuclide grid point as the upper bound in that case.

Preserve verbatim.

### INTENTIONAL: hash-grid energy boundary comparisons

The hash-grid path uses less-than-or-equal and greater-than-or-equal comparisons against the low and high bin energies.

These comparisons control whether the code clamps to the beginning or end of the nuclide grid rather than performing a search. Preserve verbatim.

### INTENTIONAL: lower-index final-point handling

After finding a lower index, the code checks whether that index equals the final grid point and backs up by one before interpolation.

This is needed so that `high = low + 1` remains valid. Preserve verbatim.

### INTENTIONAL: unionized-grid initialization uses index plus one

During unionized-grid initialization, the high-energy tracker starts from the second grid point of each nuclide.

This pairs with the later `n_gridpoints - 2` stopping condition. Preserve verbatim.

### INTENTIONAL: unionized-grid initialization stops incrementing at `n_gridpoints - 2`

The initialization logic stops increasing `idx_low` when it reaches the second-to-last grid point.

This ensures later interpolation has a valid high neighbor. Preserve verbatim.

### INTENTIONAL: XXL gridpoint assignment uses a floating multiplier

The XXL input path assigns the gridpoint count using a multiplication by 2.1 before storing into the integer gridpoint field.

This is unusual because it involves floating-to-integer conversion, but it defines the benchmark size used by this source. Preserve verbatim.

### INTENTIONAL: fuel/non-fuel condition in Optimization 3

The Optimization 3 lookup condition maps one kernel launch to fuel material and the other to non-fuel materials using a compound boolean expression.

The logic is somewhat easy to misread because the launch argument names and conditions interact. Preserve verbatim.

## Additional PVC-focused energy-efficiency notes

### Host-side sorting is a major concern

The sorting and partitioning helpers copy full sample arrays to the host, use CPU algorithms, and copy data back to the GPU. On PVC systems this can consume substantial energy and time, especially for large lookup counts.

If sorting is beneficial, perform it on the device using oneDPL or custom GPU kernels.

### Atomic material counting is inefficient

`count_equal_device` launches one full scan per material and uses a single contended global atomic counter. Optimization 4 and 6 perform twelve full scans.

More energy-efficient alternatives include:

- one pass that computes all twelve material counts,
- per-work-group histograms in SLM,
- sub-group reductions,
- device-side prefix sums for compaction.

### Device memory release is incomplete

The release routine frees several major arrays but does not free `index_grid`. The optional sample arrays allocated in optimized variants are also not explicitly freed. Program termination may reclaim memory, but for repeated runs or library integration this would waste device memory and energy.

### Explicit `nd_range` may improve control

Using explicit `nd_range` would allow tuning of local size for PVC. Good candidates to evaluate are local sizes such as 128 or 256 work-items, with attention to register pressure and SIMD width. However, the current code does not specify local size, so the runtime decides.

### Best likely optimization direction

For energy efficiency on PVC, the most promising direction is:

1. Keep lookup work material-coherent.
2. Sort or compact samples on the GPU, not the CPU.
3. Cache material metadata in SLM for material-specific kernels.
4. Use sub-group or work-group reductions for verification.
5. Consider float storage/arithmetic if scientifically valid.
6. Improve layout of `NuclideGridPoint` if profiling confirms poor cache-line utilization.

unsigned long reduce_verification_device(unsigned long * data, int n, sycl::queue& q)
{
	unsigned long * current = data;
	int current_n = n;
	bool current_owned = false;

	while(current_n > 1)
	{
		int chunk = 256;
		int next_n = (current_n + chunk - 1) / chunk;
		unsigned long * next = sycl::malloc_device<unsigned long>(next_n, q);

		q.submit([&](sycl::handler& h){
			h.parallel_for(sycl::range<1>(next_n), [=](sycl::id<1> tid){
				int gid = (int)tid[0];
				int start = gid * chunk;
				int end = start + chunk;
				if(end > current_n)
					end = current_n;
				unsigned long sum = 0;
				for(int i = start; i < end; i++)
					sum += current[i];
				next[gid] = sum;
			});
		}).wait();

		if(current_owned)
			sycl::free(current, q);
		current = next;
		current_n = next_n;
		current_owned = true;
	}

	unsigned long result = 0;
	q.memcpy(&result, current, sizeof(unsigned long)).wait();

	if(current_owned)
		sycl::free(current, q);

	return result;
}

int count_equal_device(int * data, int n, int value, sycl::queue& q)
{
	int * count_dev = sycl::malloc_device<int>(1, q);
	q.memset(count_dev, 0, sizeof(int)).wait();

	q.submit([&](sycl::handler& h){
		h.parallel_for(sycl::range<1>(n), [=](sycl::id<1> tid){
			int i = (int)tid[0];
			if(data[i] == value)
			{
				sycl::atomic_ref<int, sycl::memory_order::relaxed, sycl::memory_scope::device, sycl::access::address_space::global_space> atomic_count(count_dev[0]);
				atomic_count.fetch_add(1);
			}
		});
	}).wait();

	int result = 0;
	q.memcpy(&result, count_dev, sizeof(int)).wait();
	sycl::free(count_dev, q);
	return result;
}

void sort_by_key_int_double_device(int * keys, double * vals, int n, sycl::queue& q)
{
	if(n <= 0)
		return;

	std::vector<int> hkeys(n);
	std::vector<double> hvals(n);
	q.memcpy(hkeys.data(), keys, n * sizeof(int)).wait();
	q.memcpy(hvals.data(), vals, n * sizeof(double)).wait();

	std::vector<std::pair<int,double>> pairs(n);
	for(int i = 0; i < n; i++)
		pairs[i] = std::make_pair(hkeys[i], hvals[i]);

	std::sort(pairs.begin(), pairs.end(), [](const std::pair<int,double>& a, const std::pair<int,double>& b){
		return a.first < b.first;
	});

	for(int i = 0; i < n; i++)
	{
		hkeys[i] = pairs[i].first;
		hvals[i] = pairs[i].second;
	}

	q.memcpy(keys, hkeys.data(), n * sizeof(int)).wait();
	q.memcpy(vals, hvals.data(), n * sizeof(double)).wait();
}

void partition_fuel_device(int * keys, double * vals, int n, sycl::queue& q)
{
	if(n <= 0)
		return;

	std::vector<double> hvals(n);

	q.memcpy(hvals.data(), vals, n * sizeof(double)).wait();

	q.memcpy(vals, hvals.data(), n * sizeof(double)).wait();

int main( int argc, char* argv[] )
{
	int version = 20;
	int mype = 0;
	double omp_start, omp_end;
	int nprocs = 1;
	unsigned long long verification = 0;

	Inputs in = read_CLI( argc, argv );

	if( mype == 0 )
		print_inputs( in, nprocs, version );

	SimulationData SD;

	if( in.binary_mode == READ )
		SD = binary_read(in);
	else
		SD = grid_init_do_not_profile( in, mype );

	if( in.binary_mode == WRITE && mype == 0 )
		binary_write(in, SD);

	SimulationData GSD = move_simulation_data_to_device( in, mype, SD, q );

	if( mype == 0 )
	{
		printf("\n");
		border_print();
		center_print("SIMULATION", 79);
		border_print();
	}

	omp_start = get_time();

	if( in.simulation_method == EVENT_BASED )
	{
		if( in.kernel_id == 0 )
			verification = run_event_based_simulation_baseline(in, GSD, mype, q);
		else if( in.kernel_id == 1 )
			verification = run_event_based_simulation_optimization_1(in, GSD, mype, q);
		else if( in.kernel_id == 2 )
			verification = run_event_based_simulation_optimization_2(in, GSD, mype, q);
		else if( in.kernel_id == 3 )
			verification = run_event_based_simulation_optimization_3(in, GSD, mype, q);
		else if( in.kernel_id == 4 )
			verification = run_event_based_simulation_optimization_4(in, GSD, mype, q);
		else if( in.kernel_id == 5 )
			verification = run_event_based_simulation_optimization_5(in, GSD, mype, q);
		else if( in.kernel_id == 6 )
			verification = run_event_based_simulation_optimization_6(in, GSD, mype, q);
		else
		{
			printf("Error: No kernel ID %d found!\n", in.kernel_id);
			exit(1);
		}
	}
	else
	{
		printf("History-based simulation not implemented in CUDA code. Instead,\nuse the event-based method with \"-m event\" argument.\n");
		exit(1);
	}

	if( mype == 0)
	{
		printf("\n" );
		printf("Simulation complete.\n" );
	}

	omp_end = get_time();

	release_device_memory(GSD, q);

	verification = verification % 999983;

	int is_invalid_result = print_results( in, mype, omp_end-omp_start, nprocs, verification );

	return is_invalid_result;
}

int print_results( Inputs in, int mype, double runtime, int nprocs, unsigned long long vhash )
{
	int lookups = 0;
	if( in.simulation_method == HISTORY_BASED )
		lookups = in.lookups * in.particles;
	else if( in.simulation_method == EVENT_BASED )
		lookups = in.lookups;
	int lookups_per_sec = (int) ((double) lookups / runtime);

	int is_invalid_result = 1;

	if( mype == 0 )
	{
		border_print();
		center_print("RESULTS", 79);
		border_print();

		printf("NOTE: Timings are estimated -- use nvprof/nsys/iprof/rocprof for formal analysis\n");
		printf("Runtime:     %.3lf seconds\n", runtime);
		printf("Lookups:     "); fancy_int(lookups);
		printf("Lookups/s:   ");
		fancy_int(lookups_per_sec);
	}

	unsigned long long large = 0;
	unsigned long long small = 0;
	if( in.simulation_method == EVENT_BASED )
	{
		small = 945990;
		large = 952131;
	}
	else if( in.simulation_method == HISTORY_BASED )
	{
		small = 941535;
		large = 954318;
	}
	if( strcmp(in.HM, "large") == 0 )
	{
		if( vhash == large )
			is_invalid_result = 0;
	}
	else if( strcmp(in.HM, "small") == 0 )
	{
		if( vhash == small )
			is_invalid_result = 0;
	}

	if(mype == 0 )
	{
		if( is_invalid_result )
			printf("Verification checksum: %llu (WARNING - INAVALID CHECKSUM!)\n", vhash);
		else
			printf("Verification checksum: %llu (Valid)\n", vhash);
		border_print();
	}

	return is_invalid_result;
}

void fancy_int( long a )
{
    if( a < 1000 )
        printf("%ld\n",a);

    else if( a >= 1000 && a < 1000000 )
        printf("%ld,%03ld\n", a / 1000, a % 1000);

    else if( a >= 1000000 && a < 1000000000 )
        printf("%ld,%03ld,%03ld\n",a / 1000000,(a % 1000000) / 1000,a % 1000 );

    else if( a >= 1000000000 )
        printf("%ld,%03ld,%03ld,%03ld\n",
               a / 1000000000,
               (a % 1000000000) / 1000000,
               (a % 1000000) / 1000,
               a % 1000 );
    else
        printf("%ld\n",a);
}

Inputs read_CLI( int argc, char * argv[] )
{
	Inputs input;

	input.simulation_method = HISTORY_BASED;
	input.nthreads = 1;
	input.n_isotopes = 355;
	input.n_gridpoints = 11303;
	input.particles = 500000;
	input.lookups = 34;
	input.grid_type = UNIONIZED;
	input.hash_bins = 10000;
	input.binary_mode = NONE;
	input.kernel_id = 0;

	input.HM = (char *) malloc( 6 * sizeof(char) );
	input.HM[0] = 'l' ;
	input.HM[1] = 'a' ;
	input.HM[2] = 'r' ;
	input.HM[3] = 'g' ;
	input.HM[4] = 'e' ;
	input.HM[5] = '\0';

	int user_g = 0;

	int default_lookups = 1;
	int default_particles = 1;

	for( int i = 1; i < argc; i++ )
	{
		char * arg = argv[i];

		if( strcmp(arg, "-g") == 0 )
		{
			if( ++i < argc )
			{
				user_g = 1;
				input.n_gridpoints = atol(argv[i]);
			}
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-m") == 0 )
		{
			char * sim_type;
			if( ++i < argc )
				sim_type = argv[i];
			else
				print_CLI_error();

			if( strcmp(sim_type, "history") == 0 )
				input.simulation_method = HISTORY_BASED;
			else if( strcmp(sim_type, "event") == 0 )
			{
				input.simulation_method = EVENT_BASED;
				if( default_lookups && default_particles )
				{
					input.lookups =  input.lookups * input.particles;
					input.particles = 0;
				}
			}
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-l") == 0 )
		{
			if( ++i < argc )
			{
				input.lookups = atoi(argv[i]);
				default_lookups = 0;
			}
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-h") == 0 )
		{
			if( ++i < argc )
				input.hash_bins = atoi(argv[i]);
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-p") == 0 )
		{
			if( ++i < argc )
			{
				input.particles = atoi(argv[i]);
				default_particles = 0;
			}
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-s") == 0 )
		{
			if( ++i < argc )
				input.HM = argv[i];
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-G") == 0 )
		{
			char * grid_type;
			if( ++i < argc )
				grid_type = argv[i];
			else
				print_CLI_error();

			if( strcmp(grid_type, "unionized") == 0 )
				input.grid_type = UNIONIZED;
			else if( strcmp(grid_type, "nuclide") == 0 )
				input.grid_type = NUCLIDE;
			else if( strcmp(grid_type, "hash") == 0 )
				input.grid_type = HASH;
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-b") == 0 )
		{
			char * binary_mode;
			if( ++i < argc )
				binary_mode = argv[i];
			else
				print_CLI_error();

			if( strcmp(binary_mode, "read") == 0 )
				input.binary_mode = READ;
			else if( strcmp(binary_mode, "write") == 0 )
				input.binary_mode = WRITE;
			else
				print_CLI_error();
		}
		else if( strcmp(arg, "-k") == 0 )
		{
			if( ++i < argc )
			{
				input.kernel_id = atoi(argv[i]);
			}
			else
				print_CLI_error();
		}
		else
			print_CLI_error();
	}

	if( input.nthreads < 1 )
		print_CLI_error();
	if( input.n_isotopes < 1 )
		print_CLI_error();
	if( input.n_gridpoints < 1 )
		print_CLI_error();
	if( input.lookups < 1 )
		print_CLI_error();
	if( input.hash_bins < 1 )
		print_CLI_error();

	if( strcasecmp(input.HM, "small") != 0 &&
		strcasecmp(input.HM, "large") != 0 &&
		strcasecmp(input.HM, "XL") != 0 &&
		strcasecmp(input.HM, "XXL") != 0 )
		print_CLI_error();

	if( strcasecmp(input.HM, "small") == 0 )
		input.n_isotopes = 68;
	else if( strcasecmp(input.HM, "XL") == 0 && user_g == 0 )
		input.n_gridpoints = 238847;
	else if( strcasecmp(input.HM, "XXL") == 0 && user_g == 0 )
		input.n_gridpoints = 238847 * 2.1;

	return input;
}

	SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int));
	SD.unionized_energy_array = (double *) malloc( SD.length_unionized_energy_array * sizeof(double));

	fread(SD.num_nucs,       sizeof(int), SD.length_num_nucs, fp);
	fread(SD.concs,          sizeof(double), SD.length_concs, fp);
	fread(SD.mats,           sizeof(int), SD.length_mats, fp);
	fread(SD.nuclide_grid,   sizeof(NuclideGridPoint), SD.length_nuclide_grid, fp);
	fread(SD.index_grid, sizeof(int), SD.length_index_grid, fp);
	fread(SD.unionized_energy_array, sizeof(double), SD.length_unionized_energy_array, fp);

	fclose(fp);

	return SD;
}

SimulationData move_simulation_data_to_device( Inputs in, int mype, SimulationData SD, sycl::queue& q )
{
	if(mype == 0) printf("Allocating and moving simulation data to GPU memory space...\n");

	size_t sz;
	size_t total_sz = 0;

	SimulationData GSD = SD;

	sz = GSD.length_num_nucs * sizeof(int);
	GSD.num_nucs = sycl::malloc_device<int>(GSD.length_num_nucs, q);
	q.memcpy(GSD.num_nucs, SD.num_nucs, sz).wait();
	total_sz += sz;

	sz = GSD.length_concs * sizeof(double);
	GSD.concs = sycl::malloc_device<double>(GSD.length_concs, q);
	q.memcpy(GSD.concs, SD.concs, sz).wait();
	total_sz += sz;

	sz = GSD.length_mats * sizeof(int);
	GSD.mats = sycl::malloc_device<int>(GSD.length_mats, q);
	q.memcpy(GSD.mats, SD.mats, sz).wait();
	total_sz += sz;

	sz = GSD.length_unionized_energy_array * sizeof(double);
	if(GSD.length_unionized_energy_array > 0)
	{
		GSD.unionized_energy_array = sycl::malloc_device<double>(GSD.length_unionized_energy_array, q);
		q.memcpy(GSD.unionized_energy_array, SD.unionized_energy_array, sz).wait();
	}
	else
		GSD.unionized_energy_array = nullptr;
	total_sz += sz;

	sz = GSD.length_index_grid * sizeof(int);
	if(GSD.length_index_grid > 0)
	{
		GSD.index_grid = sycl::malloc_device<int>((size_t)GSD.length_index_grid, q);
		q.memcpy(GSD.index_grid, SD.index_grid, sz).wait();
	}
	else
		GSD.index_grid = nullptr;
	total_sz += sz;

	sz = GSD.length_nuclide_grid * sizeof(NuclideGridPoint);
	GSD.nuclide_grid = sycl::malloc_device<NuclideGridPoint>(GSD.length_nuclide_grid, q);
	q.memcpy(GSD.nuclide_grid, SD.nuclide_grid, sz).wait();
	total_sz += sz;

	sz = in.lookups * sizeof(unsigned long);
	GSD.verification = sycl::malloc_device<unsigned long>(in.lookups, q);
	total_sz += sz;
	GSD.length_verification = in.lookups;

	q.wait();

	if(mype == 0 ) printf("GPU Intialization complete. Allocated %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0 );

	return GSD;
}

void release_device_memory(SimulationData GSD, sycl::queue& q) {
	sycl::free(GSD.num_nucs, q);
	sycl::free(GSD.concs, q);
	sycl::free(GSD.mats, q);
	sycl::free(GSD.unionized_energy_array, q);
	sycl::free(GSD.nuclide_grid, q);
	sycl::free(GSD.verification, q);
}

SimulationData grid_init_do_not_profile( Inputs in, int mype )
{
	SimulationData SD;
	SD.unionized_energy_array = nullptr;
	SD.index_grid = nullptr;
	SD.verification = nullptr;
	SD.p_energy_samples = nullptr;
	SD.mat_samples = nullptr;

	size_t nbytes = 0;

	uint64_t seed = 42;

	if(mype == 0) printf("Intializing nuclide grids...\n");

	SD.length_nuclide_grid = in.n_isotopes * in.n_gridpoints;
	SD.nuclide_grid     = (NuclideGridPoint *) malloc( SD.length_nuclide_grid * sizeof(NuclideGridPoint));
	assert(SD.nuclide_grid != NULL);
	nbytes += SD.length_nuclide_grid * sizeof(NuclideGridPoint);
	for( int i = 0; i < SD.length_nuclide_grid; i++ )
	{
		SD.nuclide_grid[i].energy        = LCG_random_double(&seed);
		SD.nuclide_grid[i].total_xs      = LCG_random_double(&seed);
		SD.nuclide_grid[i].elastic_xs    = LCG_random_double(&seed);
		SD.nuclide_grid[i].absorbtion_xs = LCG_random_double(&seed);
		SD.nuclide_grid[i].fission_xs    = LCG_random_double(&seed);
		SD.nuclide_grid[i].nu_fission_xs = LCG_random_double(&seed);
	}

	for( int i = 0; i < in.n_isotopes; i++ )
		qsort( &SD.nuclide_grid[i*in.n_gridpoints], in.n_gridpoints, sizeof(NuclideGridPoint), NGP_compare);

	if( in.grid_type == NUCLIDE )
	{
		SD.length_unionized_energy_array = 0;
		SD.length_index_grid = 0;
		SD.unionized_energy_array = nullptr;
		SD.index_grid = nullptr;
	}

	if( in.grid_type == UNIONIZED )
	{
		if(mype == 0) printf("Intializing unionized grid...\n");

		SD.length_unionized_energy_array = in.n_isotopes * in.n_gridpoints;
		SD.unionized_energy_array = (double *) malloc( SD.length_unionized_energy_array * sizeof(double));
		assert(SD.unionized_energy_array != NULL );
		nbytes += SD.length_unionized_energy_array * sizeof(double);

		for( int i = 0; i < SD.length_unionized_energy_array; i++ )
			SD.unionized_energy_array[i] = SD.nuclide_grid[i].energy;

		qsort( SD.unionized_energy_array, SD.length_unionized_energy_array, sizeof(double), double_compare);

		SD.length_index_grid = SD.length_unionized_energy_array * in.n_isotopes;
		SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int));
		assert(SD.index_grid != NULL);
		nbytes += SD.length_index_grid * sizeof(int);

		int * idx_low = (int *) calloc( in.n_isotopes, sizeof(int));
		assert(idx_low != NULL );
		double * energy_high = (double *) malloc( in.n_isotopes * sizeof(double));
		assert(energy_high != NULL );

		for( int i = 0; i < in.n_isotopes; i++ )
			energy_high[i] = SD.nuclide_grid[i * in.n_gridpoints + 1].energy;

		for( long e = 0; e < SD.length_unionized_energy_array; e++ )
		{
			double unionized_energy = SD.unionized_energy_array[e];
			for( long i = 0; i < in.n_isotopes; i++ )
			{
				if( unionized_energy < energy_high[i]  )
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
				else if( idx_low[i] == in.n_gridpoints - 2 )
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
				else
				{
					idx_low[i]++;
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
					energy_high[i] = SD.nuclide_grid[i * in.n_gridpoints + idx_low[i] + 1].energy;
				}
			}
		}

		free(idx_low);
		free(energy_high);
	}

	if( in.grid_type == HASH )
	{
		if(mype == 0) printf("Intializing hash grid...\n");
		SD.length_unionized_energy_array = 0;
		SD.unionized_energy_array = nullptr;
		SD.length_index_grid  = in.hash_bins * in.n_isotopes;
		SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int));
		assert(SD.index_grid != NULL);
		nbytes += SD.length_index_grid * sizeof(int);

		double du = 1.0 / in.hash_bins;

		for( long e = 0; e < in.hash_bins; e++ )
		{
			double energy = e * du;

			for( long i = 0; i < in.n_isotopes; i++ )
			{
				SD.index_grid[e * in.n_isotopes + i] = grid_search_nuclide( in.n_gridpoints, energy, SD.nuclide_grid + i * in.n_gridpoints, 0, in.n_gridpoints-1);
			}
		}
	}

	if(mype == 0) printf("Intializing material data...\n");

	SD.num_nucs  = load_num_nucs(in.n_isotopes);
	SD.length_num_nucs = 12;

	SD.mats = load_mats(SD.num_nucs, in.n_isotopes, &SD.max_num_nucs);
	SD.length_mats = SD.length_num_nucs * SD.max_num_nucs;

	SD.concs = load_concs(SD.num_nucs, SD.max_num_nucs);
	SD.length_concs = SD.length_mats;

	if(mype == 0) printf("Intialization complete. Allocated %.0lf MB of data on CPU.\n", nbytes/1024.0/1024.0 );

	return SD;
}

unsigned long long run_event_based_simulation_baseline(Inputs in, SimulationData GSD, int mype, sycl::queue& q)
{
	if( mype == 0)	printf("Running baseline event-based simulation...\n");

	int nthreads = 256;
	int nblocks = ceil( (double) in.lookups / (double) nthreads);

	q.submit([&](sycl::handler& h){
		h.parallel_for(sycl::range<1>(nblocks * nthreads), [=](sycl::id<1> tid){
			int i = (int)tid[0];
			xs_lookup_kernel_baseline(in, GSD, i);
		});
	}).wait();

	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = reduce_verification_device(GSD.verification, in.lookups, q);
	q.wait();

	return verification_scalar;
}

inline void xs_lookup_kernel_baseline(Inputs in, SimulationData GSD, int i)
{
	if( i >= in.lookups )
		return;

	uint64_t seed = STARTING_SEED;

	seed = fast_forward_LCG(seed, 2*i);

	double p_energy = LCG_random_double(&seed);
	int mat         = pick_mat(&seed);

	double macro_xs_vector[5] = {0};

	calculate_macro_xs(
			p_energy,
			mat,
			in.n_isotopes,
			in.n_gridpoints,
			GSD.num_nucs,
			GSD.concs,
			GSD.unionized_energy_array,
			GSD.index_grid,
			GSD.nuclide_grid,
			GSD.mats,
			macro_xs_vector,
			in.grid_type,
			in.hash_bins,
			GSD.max_num_nucs
			);

	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}

inline void calculate_micro_xs(double p_energy, int nuc, long n_isotopes, long n_gridpoints, double * egrid, int * index_data, NuclideGridPoint * nuclide_grids, long idx, double * xs_vector, int grid_type, int hash_bins)
{
	double f;
	NuclideGridPoint * low;
	NuclideGridPoint * high;

	if( grid_type == NUCLIDE )
	{
		idx = grid_search_nuclide( n_gridpoints, p_energy, &nuclide_grids[nuc*n_gridpoints], 0, n_gridpoints-1);

		if( idx == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + idx - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + idx];
	}
	else if( grid_type == UNIONIZED)
	{
		if( index_data[idx * n_isotopes + nuc] == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + index_data[idx * n_isotopes + nuc] - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + index_data[idx * n_isotopes + nuc]];
	}
	else
	{
		int u_low = index_data[idx * n_isotopes + nuc];

		int u_high;
		if( idx == hash_bins - 1 )
			u_high = n_gridpoints - 1;
		else
			u_high = index_data[(idx+1)*n_isotopes + nuc] + 1;

		double e_low  = nuclide_grids[nuc*n_gridpoints + u_low].energy;
		double e_high = nuclide_grids[nuc*n_gridpoints + u_high].energy;
		int lower;
		if( p_energy <= e_low )
			lower = 0;
		else if( p_energy >= e_high )
			lower = n_gridpoints - 1;
		else
			lower = grid_search_nuclide( n_gridpoints, p_energy, &nuclide_grids[nuc*n_gridpoints], u_low, u_high);

		if( lower == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + lower - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + lower];
	}

	high = low + 1;

	f = (high->energy - p_energy) / (high->energy - low->energy);

	xs_vector[0] = high->total_xs - f * (high->total_xs - low->total_xs);
	xs_vector[1] = high->elastic_xs - f * (high->elastic_xs - low->elastic_xs);
	xs_vector[2] = high->absorbtion_xs - f * (high->absorbtion_xs - low->absorbtion_xs);
	xs_vector[3] = high->fission_xs - f * (high->fission_xs - low->fission_xs);
	xs_vector[4] = high->nu_fission_xs - f * (high->nu_fission_xs - low->nu_fission_xs);
}

inline void calculate_macro_xs(double p_energy, int mat, long n_isotopes, long n_gridpoints, int * num_nucs, double * concs, double * egrid, int * index_data, NuclideGridPoint * nuclide_grids, int * mats, double * macro_xs_vector, int grid_type, int hash_bins, int max_num_nucs)
{
	int p_nuc;
	long idx = -1;
	double conc;

	for( int k = 0; k < 5; k++ )
		macro_xs_vector[k] = 0;

	if( grid_type == UNIONIZED )
		idx = grid_search( n_isotopes * n_gridpoints, p_energy, egrid);
	else if( grid_type == HASH )
	{
		double du = 1.0 / hash_bins;
		idx = p_energy / du;
	}

	for( int j = 0; j < num_nucs[mat]; j++ )
	{
		double xs_vector[5];
		p_nuc = mats[mat*max_num_nucs + j];
		conc = concs[mat*max_num_nucs + j];
		calculate_micro_xs( p_energy, p_nuc, n_isotopes,
		                    n_gridpoints, egrid, index_data,
		                    nuclide_grids, idx, xs_vector, grid_type, hash_bins );
		for( int k = 0; k < 5; k++ )
			macro_xs_vector[k] += xs_vector[k] * conc;
	}
}

inline long grid_search(long n, double quarry, double * A)
{
	long lowerLimit = 0;
	long upperLimit = n-1;
	long examinationPoint;
	long length = upperLimit - lowerLimit;

	while( length > 1 )
	{
		examinationPoint = lowerLimit + ( length / 2 );

		if( A[examinationPoint] > quarry )
			upperLimit = examinationPoint;
		else
			lowerLimit = examinationPoint;

		length = upperLimit - lowerLimit;
	}

	return lowerLimit;
}

inline long grid_search_nuclide(long n, double quarry, NuclideGridPoint * A, long low, long high)
{
	long lowerLimit = low;
	long upperLimit = high;
	long examinationPoint;
	long length = upperLimit - lowerLimit;

	while( length > 1 )
	{
		examinationPoint = lowerLimit + ( length / 2 );

		if( A[examinationPoint].energy > quarry )
			upperLimit = examinationPoint;
		else
			lowerLimit = examinationPoint;

		length = upperLimit - lowerLimit;
	}

	return lowerLimit;
}

inline int pick_mat( uint64_t * seed )
{
	double dist[12];
	dist[0]  = 0.140;
	dist[1]  = 0.052;
	dist[2]  = 0.275;
	dist[3]  = 0.134;
	dist[4]  = 0.154;
	dist[5]  = 0.064;
	dist[6]  = 0.066;
	dist[7]  = 0.055;
	dist[8]  = 0.008;
	dist[9]  = 0.015;
	dist[10] = 0.025;
	dist[11] = 0.013;

	double roll = LCG_random_double(seed);

	for( int i = 0; i < 12; i++ )
	{
		double running = 0;
		for( int j = i; j > 0; j-- )
			running += dist[j];
		if( roll < running )
			return i;
	}

	return 0;
}

inline double LCG_random_double(uint64_t * seed)
{
	const uint64_t m = 9223372036854775808ULL;
	const uint64_t a = 2806196910506780709ULL;
	const uint64_t c = 1ULL;
	*seed = (a * (*seed) + c) % m;
	return (double) (*seed) / (double) m;
}

inline uint64_t fast_forward_LCG(uint64_t seed, uint64_t n)
{
	const uint64_t m = 9223372036854775808ULL;
	uint64_t a = 2806196910506780709ULL;
	uint64_t c = 1ULL;

	n = n % m;

	uint64_t a_new = 1;
	uint64_t c_new = 0;

	while(n > 0)
	{
		if(n & 1)
		{
			a_new *= a;
			c_new = c_new * a + c;
		}
		c *= (a + 1);
		a *= a;

		n >>= 1;
	}

	return (a_new * seed + c_new) % m;
}

unsigned long long run_event_based_simulation_optimization_1(Inputs in, SimulationData GSD, int mype, sycl::queue& q)
{
	const char * optimization_name = "Optimization 1 - basic sample/lookup kernel splitting";

	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);

	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	GSD.p_energy_samples = sycl::malloc_device<double>(in.lookups, q);
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	GSD.mat_samples = sycl::malloc_device<int>(in.lookups, q);
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;

	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);

	q.submit([&](sycl::handler& h){
		h.parallel_for(sycl::range<1>(nblocks * nthreads), [=](sycl::id<1> tid){
			int i = (int)tid[0];
			sampling_kernel(in, GSD, i);
		});
	}).wait();

	q.submit([&](sycl::handler& h){
		h.parallel_for(sycl::range<1>(nblocks * nthreads), [=](sycl::id<1> tid){
			int i = (int)tid[0];

inline void sampling_kernel(Inputs in, SimulationData GSD, int i)
{
	if( i >= in.lookups )
		return;

	uint64_t seed = STARTING_SEED;

	seed = fast_forward_LCG(seed, 2*i);

	double p_energy = LCG_random_double(&seed);
	int mat         = pick_mat(&seed);

	GSD.p_energy_samples[i] = p_energy;
	GSD.mat_samples[i] = mat;
}

int double_compare(const void * a, const void * b)
{
	double A = *((double *) a);
	double B = *((double *) b);

	if( A > B )
		return 1;
	else if( A < B )
		return -1;
	else
		return 0;
}

int NGP_compare(const void * a, const void * b)
{
	NuclideGridPoint A = *((NuclideGridPoint *) a);
	NuclideGridPoint B = *((NuclideGridPoint *) b);

	if( A.energy > B.energy )
		return 1;
	else if( A.energy < B.energy )
		return -1;
	else
		return 0;
}

double rn_v(void)
{
	static unsigned long seed = 1337;
	double ret;
	unsigned long n1;
	unsigned long a = 16807;
	unsigned long m = 2147483647;
	n1 = ( a * (seed) ) % m;
	seed = n1;
	ret = (double) n1 / m;
	return ret;
}

size_t estimate_mem_usage( Inputs in )
{
	size_t single_nuclide_grid = in.n_gridpoints * sizeof( NuclideGridPoint );
	size_t all_nuclide_grids   = in.n_isotopes * single_nuclide_grid;
	size_t size_UEG            = in.n_isotopes*in.n_gridpoints*sizeof(double) + in.n_isotopes*in.n_gridpoints*in.n_isotopes*sizeof(int);
	size_t size_hash_grid      = in.hash_bins * in.n_isotopes * sizeof(int);
	size_t memtotal;

	if( in.grid_type == UNIONIZED )
		memtotal          = all_nuclide_grids + size_UEG;
	else if( in.grid_type == NUCLIDE )
		memtotal          = all_nuclide_grids;
	else
		memtotal          = all_nuclide_grids + size_hash_grid;

	memtotal          = ceil(memtotal / (1024.0*1024.0));
	return memtotal;
}

double get_time(void)
{
	unsigned long us_since_epoch = std::chrono::high_resolution_clock::now().time_since_epoch() / std::chrono::microseconds(1);
	return (double) us_since_epoch / 1.0e6;
}
