- **Memory access coalescing**
  - Make warp lanes access consecutive global memory locations whenever possible: thread `i` should read/write `base + i`.
  - Prefer struct-of-arrays over array-of-structs when each thread reads the same field from different elements.
  - Avoid strided per-thread patterns such as `arr[threadIdx.x * N + j]`; transpose/layout data so accesses become `arr[j * blockDim.x + threadIdx.x]`.
  - **Most impactful when:** the kernel is memory-bound or shows poor global-load efficiency in Nsight Compute. On A100, reducing HBM2e transactions can substantially reduce both time and DRAM energy.

- **Shared memory use**
  - Use shared memory to stage data that is reused by multiple threads in a block, replacing repeated global memory reads with low-energy on-chip accesses.
  - Load tiles cooperatively from global memory, synchronize once, then reuse from shared memory.
  - Avoid shared-memory bank conflicts; for 32-bank shared memory, avoid access strides that are multiples of 32.
  - On A100, use larger dynamic shared memory when useful, up to the architecture limits, via `cudaFuncSetAttribute`.
  - **Most impactful when:** threads in the same block repeatedly access overlapping or nearby global-memory regions, such as tiled stencils, matrix operations, reductions, or shared lookup data.

- **Occupancy optimization**
  - Aim for enough active warps to hide memory latency without causing register spilling or excessive shared-memory use.
  - Use block sizes that are multiples of 32; 128–256 threads per block is a strong starting point on A100.
  - Watch register pressure and shared-memory allocation, since both can limit active blocks per SM.
  - Use `cudaOccupancyMaxPotentialBlockSize` and Nsight Compute occupancy metrics to tune.
  - Avoid register spilling to local memory because it often becomes expensive DRAM traffic.
  - Consider `__launch_bounds__` to guide register allocation.
  - **Most impactful when:** latency hiding is poor, SM occupancy is low, or kernels stall on memory latency. However, maximum occupancy is not always optimal if it increases spilling or reduces cache/shared-memory reuse.

- **Warp divergence reduction**
  - Reduce branches where threads within a warp take different paths.
  - Use branchless selection or predication for short conditional code.
  - Keep branch bodies small so the compiler can predicate them.
  - If possible, reorder or group inputs so warps process similar control-flow paths.
  - **Most impactful when:** branch conditions vary randomly across threads, causing warps to serialize multiple paths and waste active cycles.

- **Kernel fusion**
  - Combine consecutive kernels that operate on the same data when dependencies and launch configurations allow.
  - Keep intermediate values in registers or shared memory instead of writing them to global memory and reading them back.
  - Fusion also reduces kernel launch overhead.
  - Avoid over-fusion if it greatly increases register pressure, lowers occupancy, or harms cache behavior.
  - **Most impactful when:** multiple simple kernels are memory-bound and exchange intermediate arrays through global memory.

- **Read-only cache with `__ldg` / `const __restrict__`**
  - Mark read-only kernel inputs as `const __restrict__` so the compiler can optimize loads and potentially use the read-only path.
  - Use `__ldg(&arr[i])` explicitly for read-only data when beneficial.
  - This can reduce L2 and DRAM pressure for repeated or spatially local reads.
  - **Most impactful when:** large input arrays are read-only and have spatial or temporal locality. It can also help random-read workloads if cache lines are reused.

- **Arithmetic precision tradeoffs**
  - Use `float` instead of `double` where numerical requirements allow.
  - Lower precision reduces data movement, register use, shared-memory use, and instruction cost.
  - Use fast math intrinsics such as `__expf`, `__logf`, `__sinf`, `__cosf`, or `__fdividef` only when their reduced precision is acceptable.
  - Use fused multiply-add where appropriate; FMA is usually faster and more energy-efficient than separate multiply and add.
  - **Most impactful when:** the kernel is compute-bound, uses FP64 heavily, or moves large arrays of double-precision data. Always verify numerical correctness.

- **Synchronization minimization**
  - Remove unnecessary `__syncthreads()` calls and move barriers out of loops when data dependencies allow.
  - Use warp-level synchronization and collectives such as `__syncwarp`, `__ballot_sync`, or `__reduce_sync` when only threads within a warp need to coordinate.
  - Reduce high-contention atomics by doing block-level or warp-level reductions first, then issuing fewer global atomics.
  - **Most impactful when:** kernels contain frequent barriers, reductions, producer-consumer shared-memory phases, or many atomics to the same address.

- **Prefetching / memory-transfer control**
  - Keep data resident on the GPU across multiple kernels to avoid repeated host-device transfers.
  - Prefer explicit `cudaMalloc`/`cudaMemcpy` when possible to avoid unexpected Unified Memory page migrations.
  - If Unified Memory is used, prefetch data to the GPU before kernel execution with `cudaMemPrefetchAsync`.
  - Use pinned host memory and asynchronous copies with streams when transfers are necessary, so transfers can overlap with computation.
  - **Most impactful when:** runtime includes significant CPU-GPU data movement, Unified Memory page faults, or repeated transfers around short kernels.

## 1. Overall algorithm and GPU resource utilization profile

### Algorithm
- The profiled computation is an event-based XSBench-style macroscopic cross-section lookup.
- Each lookup:
  1. Generates or reads a sampled neutron energy.
  2. Generates or reads a sampled material ID.
  3. For every nuclide in that material, performs a microscopic cross-section lookup.
  4. Interpolates five cross-section channels.
  5. Accumulates them into a five-element macroscopic cross-section vector.
  6. Writes a small verification value.
- The main workload is in `calculate_macro_xs()` and `calculate_micro_xs()`, which perform repeated lookups into large nuclide/energy grids.

### Resource profile
- The dominant kernels are primarily memory-latency-bound and control-flow-bound, not pure compute-bound.
- Although there are many double-precision operations, the expensive part is irregular access to large global-memory tables:
  - `nuclide_grid`
  - `index_grid`
  - `unionized_energy_array`
  - `mats`
  - `concs`
- On an A100, FP64 throughput is high, so the random global-memory behavior and branch divergence are likely more limiting than raw arithmetic throughput.
- The workload has poor temporal locality in baseline and early optimized variants because each thread samples independent random energies and materials.
- `NUCLIDE` grid mode is especially branch- and memory-latency-heavy because each nuclide lookup performs a binary search.
- `UNIONIZED` mode reduces per-nuclide binary search cost but introduces very large random accesses to `index_grid`.
- `HASH` mode reduces search range but still has random per-thread access patterns.

### Energy-efficiency opportunities
- Reduce random global-memory traffic by grouping lookups by material and energy, as done in optimizations 4–6.
- Optimization 6 has the best energy-efficiency potential because material and energy sorting improves warp coherence, cache locality, and binary-search path similarity.
- Avoid unnecessary kernel launches and full-array passes when the sorting or partitioning overhead exceeds the locality benefit.
- Move small read-only tables such as material distributions, `num_nucs`, `mats`, and possibly `concs` into constant memory or shared memory to reduce repeated global loads.
- Consider cooperative warp-level or block-level processing for fuel material lookups, where one thread currently performs hundreds of nuclide lookups serially.
- Consider replacing many double-precision quantities with single precision if benchmark accuracy and checksum requirements allow.

## 2. CUDA kernel launch configurations and A100 occupancy assessment

### Baseline
- Kernel: `xs_lookup_kernel_baseline`
- Launch configuration:
  - Threads per block: 256
  - Blocks: `ceil(in.lookups / 256)`
- A100 occupancy assessment:
  - 256-thread blocks correspond to 8 warps per block.
  - Theoretical occupancy can be high on A100 if register usage is not excessive.
  - The kernel uses several local arrays and inlined device functions, so register pressure may reduce occupancy.
  - Even with good occupancy, memory latency and divergence are likely dominant.

### Optimization 1
- Kernels:
  - `sampling_kernel`
  - `xs_lookup_kernel_optimization_1`
- Launch configuration for both:
  - Threads per block: 32
  - Blocks: `ceil(in.lookups / 32)`
- A100 occupancy assessment:
  - 32-thread blocks contain exactly one warp.
  - A100 has a maximum block residency limit per SM; one-warp blocks can hit the block limit before reaching the maximum 64 resident warps.
  - Maximum theoretical warp occupancy is likely around 50% if limited to 32 resident blocks per SM.
  - Sampling is simple and likely not occupancy-sensitive.
  - Lookup kernel may suffer because memory-latency hiding is weaker than with larger blocks.

### Optimization 2
- Kernels:
  - `sampling_kernel`
  - `xs_lookup_kernel_optimization_2`, launched once per material, 12 total launches.
- Launch configuration:
  - `sampling_kernel`: 32 threads per block, `ceil(in.lookups / 32)` blocks.
  - Each material lookup kernel: 32 threads per block, `ceil(in.lookups / 32)` blocks.
- A100 occupancy assessment:
  - Same one-warp-block occupancy limitation as Optimization 1.
  - Each material kernel scans the full lookup set and exits early for nonmatching material.
  - This wastes energy because many threads only load `mat_samples[i]` and return.
  - Occupancy may appear adequate, but useful occupancy is low for rare materials.

### Optimization 3
- Kernels:
  - `sampling_kernel`
  - `xs_lookup_kernel_optimization_3`, launched twice: once for non-fuel and once for fuel.
- Launch configuration:
  - `sampling_kernel`: 32 threads per block, `ceil(in.lookups / 32)` blocks.
  - Lookup kernels: 32 threads per block, `ceil(in.lookups / 32)` blocks.
- A100 occupancy assessment:
  - Same one-warp-block limitation.
  - Less launch and scan overhead than Optimization 2.
  - Still scans the full lookup array twice.
  - Better energy profile than Optimization 2, but still performs many inactive-thread checks.

### Optimization 4
- Kernels:
  - `sampling_kernel`
  - `xs_lookup_kernel_optimization_4`, launched once per material after material sorting.
- Launch configuration:
  - `sampling_kernel`: 32 threads per block, `ceil(in.lookups / 32)` blocks.
  - Each material lookup kernel:
    - Threads per block: 32
    - Blocks: `ceil(n_lookups_per_material[m] / 32)`
- A100 occupancy assessment:
  - One-warp blocks limit maximum resident warps per SM.
  - Because each material kernel processes only the relevant compacted material range, useful occupancy is much better than Optimization 2.
  - Rare materials may launch small grids, which can underutilize the full GPU.
  - Sorting cost is substantial but can be worthwhile for large lookup counts.

### Optimization 5
- Kernels:
  - `sampling_kernel`
  - `xs_lookup_kernel_optimization_5`, launched twice after fuel/non-fuel partitioning.
- Launch configuration:
  - `sampling_kernel`: 32 threads per block, `ceil(in.lookups / 32)` blocks.
  - Fuel lookup kernel:
    - Threads per block: 32
    - Blocks: `ceil(n_fuel_lookups / 32)`
  - Non-fuel lookup kernel:
    - Threads per block: 32
    - Blocks: `ceil((in.lookups - n_fuel_lookups) / 32)`
- A100 occupancy assessment:
  - Same one-warp-block occupancy limit.
  - Better useful work density than Optimization 3 because fuel and non-fuel ranges are compacted.
  - Non-fuel range still mixes materials, so divergence remains.
  - Lower sorting overhead than full material sort, so this may be energy-efficient when full sorting is too expensive.

### Optimization 6
- Kernels:
  - `sampling_kernel`
  - `xs_lookup_kernel_optimization_4`, reused after material sort and per-material energy sort.
- Launch configuration:
  - `sampling_kernel`: 32 threads per block, `ceil(in.lookups / 32)` blocks.
  - Each material lookup kernel:
    - Threads per block: 32
    - Blocks: `ceil(n_lookups_per_material[m] / 32)`
- A100 occupancy assessment:
  - One-warp-block limit remains.
  - Despite lower theoretical occupancy than the baseline, this variant likely has much better memory efficiency and lower divergence.
  - Energy efficiency can improve substantially because sorted energies cause nearby threads to traverse similar binary-search paths and access nearby grid locations.
  - The main tradeoff is the cost of multiple Thrust sorting operations.

### Thrust operations
- The code also invokes Thrust reductions, counts, sorts, and partitions.
- Their internal launch configurations are not explicitly visible in the source.
- They introduce additional global-memory passes and synchronization points.
- Energy efficiency depends heavily on whether improved lookup locality amortizes the sorting/partitioning cost.

## 3. Global memory access patterns by kernel

### `xs_lookup_kernel_baseline`
- Verification writes:
  - `GSD.verification[i]` is consecutive across consecutive threads.
  - This store is coalesced.
- Sampling:
  - Energy and material are generated inside the kernel; no sample-array global loads.
- Main lookup data:
  - `unionized_energy_array` binary-search reads are irregular across threads.
  - `index_grid` accesses are scattered because `idx` and `nuc` vary by thread.
  - `nuclide_grid` accesses are scattered because both sampled energy and material vary by thread.
  - `mats` and `concs` accesses are small-table reads but are divergent because material differs by thread.
- Overall:
  - Poorly coalesced for the dominant data structures.
  - Memory access is random/scattered at warp scale.

### `sampling_kernel`
- Writes:
  - `GSD.p_energy_samples[i]` is consecutive across threads: coalesced.
  - `GSD.mat_samples[i]` is consecutive across threads: coalesced.
- Reads:
  - No large global-memory reads besides structure metadata.
- Overall:
  - Mostly coalesced and efficient.
  - Arithmetic includes RNG fast-forwarding, which is integer-heavy but localized.

### `xs_lookup_kernel_optimization_1`
- Sample reads:
  - `GSD.p_energy_samples[i]` is coalesced.
  - `GSD.mat_samples[i]` is coalesced.
- Verification writes:
  - `GSD.verification[i]` is coalesced.
- Main lookup data:
  - Same scattered behavior as baseline.
- Overall:
  - Adds coalesced sample-array traffic but does not improve lookup locality by itself.
  - Likely worse energy efficiency than baseline unless later grouping is used.

### `xs_lookup_kernel_optimization_2`
- Sample reads:
  - Coalesced across the full lookup array.
- Material filtering:
  - Every material kernel scans the entire lookup set.
  - Most threads return early for most material kernels.
- Verification writes:
  - Only active threads write.
  - Active lanes within a warp are often sparse, so stores are only partially coalesced.
- Main lookup data:
  - For active threads, material is uniform within a kernel, which helps loop trip count and material-table locality.
  - Energies are still random, so `nuclide_grid`, `index_grid`, and `unionized_energy_array` remain scattered.
- Overall:
  - Reduces material divergence among active threads but wastes global-memory reads and scheduling energy on inactive threads.

### `xs_lookup_kernel_optimization_3`
- Sample reads:
  - Coalesced.
- Fuel/non-fuel filtering:
  - Each of two kernels scans the full lookup set.
  - Many inactive threads return early.
- Verification writes:
  - Active-thread stores may be sparse within warps, especially in the fuel kernel.
- Main lookup data:
  - Fuel kernel improves uniformity for the expensive fuel material.
  - Non-fuel kernel still mixes materials and loop lengths.
- Overall:
  - Better than Optimization 2 in launch count and scan overhead.
  - Still has wasted work from full-array scanning.

### `xs_lookup_kernel_optimization_4`
- Input arrays:
  - After sorting by material, each material kernel reads a compact contiguous segment.
  - `p_energy_samples` and `mat_samples` reads are coalesced.
- Verification writes:
  - `GSD.verification[i]` writes are contiguous within each material segment and generally coalesced.
- Main lookup data:
  - Material is uniform within the kernel, improving access to `mats`, `concs`, and `num_nucs`.
  - Energies are not sorted in Optimization 4, so grid accesses are still largely scattered.
- Overall:
  - Much better useful memory traffic than Optimization 2.
  - Still limited by random energy-dependent accesses.

### `xs_lookup_kernel_optimization_5`
- Input arrays:
  - After fuel/non-fuel partitioning, fuel and non-fuel ranges are compact.
  - Sample reads are coalesced.
- Verification writes:
  - Coalesced within each compacted range.
- Main lookup data:
  - Fuel segment has uniform material and good loop coherence.
  - Non-fuel segment still mixes material IDs, causing divergent loop counts and scattered material-table access.
- Overall:
  - Good compromise between sorting cost and lookup coherence.
  - Less locality improvement than full material sorting.

### Optimization 6 lookup phase
- Input arrays:
  - Material-sorted and then energy-sorted within each material.
  - Sample reads are coalesced.
- Main lookup data:
  - Threads in a warp are likely to have similar material and nearby energies.
  - Binary-search paths become more similar.
  - `index_grid` and `nuclide_grid` accesses become more cache-friendly.
  - Accesses are still not perfectly coalesced because data structures are indexed indirectly, but locality is substantially improved.
- Overall:
  - Best global-memory behavior among the provided variants.
  - Highest potential for energy efficiency if sort overhead is amortized.

## 4. Shared memory usage

### Current shared memory usage
- No explicit shared memory is used.
- There are no `__shared__` allocations.
- All main lookup tables reside in global memory.
- Small per-thread arrays such as:
  - `macro_xs_vector[5]`
  - `xs_vector[5]`
  - `dist[12]`
  are local to each thread and may occupy registers or spill to local memory depending on compiler decisions.

### Potential shared-memory or constant-memory opportunities
- The material distribution table used in `pick_mat()` should be moved out of per-thread local storage.
  - It is read-only and identical for all threads.
  - Constant memory is a strong candidate.
- `num_nucs` is tiny and read-only.
  - Constant memory is appropriate.
- `mats` and `concs` are small relative to the nuclide grid.
  - For material-specific kernels, the relevant material’s `mats` and `concs` rows could be staged in shared memory once per block.
  - This is especially useful for fuel material, which has many nuclides.
- For sorted-by-material kernels, constant memory may perform well because all threads access the same material index and often the same loop iteration.
- `nuclide_grid` is too large for shared memory, but energy-sorted lookups can improve cache reuse.
- If redesigning the kernel, warp- or block-level cooperative processing of a single material lookup could use shared memory for partial reductions of the five cross-section channels.

## 5. Warp divergence

### Kernel-level branches

#### `xs_lookup_kernel_baseline`
- Boundary check: thread returns if lookup index is outside `in.lookups`.
- Verification maximum search contains a conditional update for each of five channels.
- Divergence sources:
  - Different materials per thread.
  - Different numbers of nuclides per material.
  - Different binary-search paths.
  - Different grid-type branches, although grid type itself is uniform for a run.

#### `sampling_kernel`
- Boundary check: thread returns if lookup index is outside `in.lookups`.
- `pick_mat()` contains divergent material-selection control flow.
- `fast_forward_LCG()` contains a loop with a branch depending on bits of `n`.

#### `xs_lookup_kernel_optimization_1`
- Boundary check.
- Verification maximum conditional.
- Same lookup divergence as baseline, except sampling has been separated.

#### `xs_lookup_kernel_optimization_2`
- Boundary check.
- Material filter branch: threads return if `mat != m`.
- Verification maximum conditional.
- Active threads in a material-specific kernel have uniform material, but many threads are inactive.

#### `xs_lookup_kernel_optimization_3`
- Boundary check.
- Fuel/non-fuel conditional branch.
- Verification maximum conditional inside active branch.
- Fuel kernel improves coherence for expensive fuel lookups; non-fuel kernel still diverges by material.

#### `xs_lookup_kernel_optimization_4`
- Boundary check against `n_lookups`.
- Redundant material check after sorting.
- Verification maximum conditional.
- Material divergence is largely removed.
- Energy divergence remains unless using Optimization 6.

#### `xs_lookup_kernel_optimization_5`
- Boundary check against `n_lookups`.
- Verification maximum conditional.
- Fuel partition removes fuel/non-fuel imbalance, but non-fuel segment still has material divergence.

### Device-function divergence
- `calculate_macro_xs()`:
  - Branches on grid type: unionized, hash, or nuclide.
  - Loop trip count depends on `num_nucs[mat]`, causing major divergence when materials differ within a warp.
- `calculate_micro_xs()`:
  - Branches on grid type.
  - Boundary checks for final grid point.
  - Hash-grid path has multiple edge-case branches.
- `grid_search()` and `grid_search_nuclide()`:
  - Binary-search comparison diverges by sampled energy.
  - Threads with different energies take different search paths.
- `pick_mat()`:
  - Material-selection loop diverges based on random roll.
- `fast_forward_LCG()`:
  - Branch on low bit of `n` can diverge across threads.

### Main divergence-reduction opportunities
- Sort or partition by material to reduce loop-trip-count divergence.
- Sort by energy to align binary-search paths.
- Use warp-level cooperative processing for high-nuclide-count fuel lookups.
- Avoid launching kernels that scan full arrays and immediately return for most threads.

## 8. Unusual loop bounds and comparison operators — INTENTIONAL, preserve verbatim

The following constructs appear unusual or easy to “correct” incorrectly. They should be treated as INTENTIONAL and MUST be preserved verbatim unless the benchmark specification is intentionally changed.

### Material selection in `pick_mat()`
- The inner accumulation loop sums from the current material index down to greater than zero, excluding index zero.
- This means the fuel material probability is effectively handled by the final default return path rather than by the first loop iteration.
- This is unusual but INTENTIONAL and MUST be preserved verbatim.
- The comparison using `roll < running` is also part of the benchmark behavior and MUST be preserved verbatim.

### Verification maximum comparison
- The maximum search uses a strict greater-than comparison.
- Equal values do not update the index.
- This affects tie-breaking and therefore verification behavior.
- INTENTIONAL; MUST be preserved verbatim.

### Binary-search termination condition
- Both binary search routines terminate when the search interval length is greater than one.
- They return the lower bounding index.
- The comparison structure determines exact lower-index behavior.
- INTENTIONAL; MUST be preserved verbatim.

### Binary-search comparison direction
- The comparison checks whether the examined energy is greater than the quarry energy.
- This determines lower/upper bound updates and must not be inverted or changed to greater-than-or-equal without changing results.
- INTENTIONAL; MUST be preserved verbatim.

### Hash-grid edge comparisons
- The hash-grid path checks sampled energy against lower and upper energy bounds using less-than-or-equal and greater-than-or-equal comparisons.
- These boundary comparisons influence edge-bin behavior.
- INTENTIONAL; MUST be preserved verbatim.

### End-of-grid handling in `calculate_micro_xs()`
- When the located index equals the last grid point, the code uses the previous point as the low point.
- This prevents reading past the end when `high = low + 1`.
- INTENTIONAL; MUST be preserved verbatim.

### Optimization 3 launch parameter behavior
- The lookup kernel parameter is named as a fuel indicator, and the two launches cover non-fuel and fuel cases.
- The compound condition inside the kernel determines which lookups are processed.
- The logic is easy to misread but covers both categories.
- INTENTIONAL; MUST be preserved verbatim.

### Optimization 4 material check after sorting
- After material sorting and per-material launch ranges, the kernel still checks whether the material matches the kernel material.
- This may appear redundant, but it protects correctness if counts, offsets, or sorting assumptions are violated.
- INTENTIONAL; MUST be preserved verbatim.

### XXL gridpoint assignment
- The XXL configuration multiplies an integer value by a floating-point constant before assigning to an integer-like field.
- This is unusual because it implies truncation.
- INTENTIONAL; MUST be preserved verbatim.

## 9. Summary of highest-impact energy-efficiency opportunities

1. Prefer material and energy grouping for large workloads.
   - Optimization 6 has the best locality and divergence profile.
   - Optimization 5 may be a better energy/performance compromise when full sorting overhead is too high.

2. Increase lookup kernel block size beyond 32 threads where appropriate.
   - One-warp blocks limit A100 occupancy because of the maximum resident block limit.
   - 128- or 256-thread blocks may improve latency hiding, especially for memory-bound lookup kernels.

3. Use constant memory or shared memory for small read-only tables.
   - Material distributions, `num_nucs`, `mats`, and possibly `concs` are good candidates.

4. Avoid per-thread construction of the material probability table.
   - The `dist[12]` array inside `pick_mat()` is identical for all threads and should not consume per-thread register/local storage.

5. Consider mixed precision.
   - Single precision for cross sections, concentrations, sampled energies, and interpolation can reduce memory bandwidth and FP64 energy cost.
   - Only safe if checksum and accuracy requirements allow.

6. Consider cooperative processing for fuel material.
   - Fuel has hundreds of nuclides and dominates work.
   - A warp or block could cooperatively process one lookup and reduce the five cross-section channels, improving SIMD utilization and reducing per-thread serial work.

7. Reevaluate full-array scanning kernels.
   - Optimization 2 and 3 launch kernels that read every lookup and return early for many threads.
   - This wastes energy unless the divergence reduction outweighs the scanning cost.

	if( input.lookups < 1 )
		print_CLI_error();

	// Validate Hash Bins 
	if( input.hash_bins < 1 )
		print_CLI_error();
	
	// Validate HM size
	if( strcasecmp(input.HM, "small") != 0 &&
		strcasecmp(input.HM, "large") != 0 &&
		strcasecmp(input.HM, "XL") != 0 &&
		strcasecmp(input.HM, "XXL") != 0 )
		print_CLI_error();
	
	// Set HM size specific parameters
	// (defaults to large)
	if( strcasecmp(input.HM, "small") == 0 )
		input.n_isotopes = 68;
	else if( strcasecmp(input.HM, "XL") == 0 && user_g == 0 )
		input.n_gridpoints = 238847; // sized to make 120 GB XS data
	else if( strcasecmp(input.HM, "XXL") == 0 && user_g == 0 )
		input.n_gridpoints = 238847 * 2.1; // 252 GB XS data

	// Return input struct
	return input;
}

// Moves all required data structures to the GPU's memory space
SimulationData move_simulation_data_to_device( Inputs in, int mype, SimulationData SD )
{
	if(mype == 0) printf("Allocating and moving simulation data to GPU memory space...\n");

	////////////////////////////////////////////////////////////////////////////////
	// SUMMARY: Simulation Data Structure Manifest for "SD" Object
	// Here we list all heap arrays (and lengths) in SD that would need to be
	// offloaded manually if using an accelerator with a seperate memory space
	////////////////////////////////////////////////////////////////////////////////
	// int * num_nucs;                     // Length = length_num_nucs;
	// double * concs;                     // Length = length_concs
	// int * mats;                         // Length = length_mats
	// double * unionized_energy_array;    // Length = length_unionized_energy_array
	// int * index_grid;                   // Length = length_index_grid
	// NuclideGridPoint * nuclide_grid;    // Length = length_nuclide_grid
	// 
	// Note: "unionized_energy_array" and "index_grid" can be of zero length
	//        depending on lookup method.
	//
	// Note: "Lengths" are given as the number of objects in the array, not the
	//       number of bytes.
	////////////////////////////////////////////////////////////////////////////////
	size_t sz;
	size_t total_sz = 0;

	// Shallow copy of CPU simulation data to GPU simulation data
	SimulationData GSD = SD;

	// Move data to GPU memory space
	sz = GSD.length_num_nucs * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.num_nucs, sz) );
	gpuErrchk( cudaMemcpy(GSD.num_nucs, SD.num_nucs, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_concs * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.concs, sz) );
	gpuErrchk( cudaMemcpy(GSD.concs, SD.concs, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_mats * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mats, sz) );
	gpuErrchk( cudaMemcpy(GSD.mats, SD.mats, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;
	
	sz = GSD.length_unionized_energy_array * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.unionized_energy_array, sz) );
	gpuErrchk( cudaMemcpy(GSD.unionized_energy_array, SD.unionized_energy_array, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_index_grid * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.index_grid, sz) );
	gpuErrchk( cudaMemcpy(GSD.index_grid, SD.index_grid, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_nuclide_grid * sizeof(NuclideGridPoint);
	gpuErrchk( cudaMalloc((void **) &GSD.nuclide_grid, sz) );
	gpuErrchk( cudaMemcpy(GSD.nuclide_grid, SD.nuclide_grid, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;
	
	// Allocate verification array on device. This structure is not needed on CPU, so we don't
	// have to copy anything over.
	sz = in.lookups * sizeof(unsigned long);
	gpuErrchk( cudaMalloc((void **) &GSD.verification, sz) );
	total_sz += sz;
	GSD.length_verification = in.lookups;
	
	// Synchronize
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	if(mype == 0 ) printf("GPU Intialization complete. Allocated %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0 );

	return GSD;

}

// Release device memory
void release_device_memory(SimulationData GSD) {
	cudaFree(GSD.num_nucs);
	cudaFree(GSD.concs);
	cudaFree(GSD.mats);
	cudaFree(GSD.unionized_energy_array);
	cudaFree(GSD.nuclide_grid);
	cudaFree(GSD.verification);
}

SimulationData grid_init_do_not_profile( Inputs in, int mype )
{
	// Structure to hold all allocated simuluation data arrays
	SimulationData SD;

	// Keep track of how much data we're allocating
	size_t nbytes = 0;
	
	// Set the initial seed value
	uint64_t seed = 42;	

	////////////////////////////////////////////////////////////////////
	// Initialize Nuclide Grids
	////////////////////////////////////////////////////////////////////
	
	if(mype == 0) printf("Intializing nuclide grids...\n");

	// First, we need to initialize our nuclide grid. This comes in the form
	// of a flattened 2D array that hold all the information we need to define
	// the cross sections for all isotopes in the simulation. 
	// The grid is composed of "NuclideGridPoint" structures, which hold the
	// energy level of the grid point and all associated XS data at that level.
	// An array of structures (AOS) is used instead of
	// a structure of arrays, as the grid points themselves are accessed in 
	// a random order, but all cross section interaction channels and the
	// energy level are read whenever the gridpoint is accessed, meaning the
	// AOS is more cache efficient.
	
	// Initialize Nuclide Grid
	SD.length_nuclide_grid = in.n_isotopes * in.n_gridpoints;
	SD.nuclide_grid     = (NuclideGridPoint *) malloc( SD.length_nuclide_grid * sizeof(NuclideGridPoint));
	assert(SD.nuclide_grid != NULL);
	nbytes += SD.length_nuclide_grid * sizeof(NuclideGridPoint);
	for( int i = 0; i < SD.length_nuclide_grid; i++ )
	{
		SD.nuclide_grid[i].energy        = LCG_random_double(&seed);
		SD.nuclide_grid[i].total_xs      = LCG_random_double(&seed);
		SD.nuclide_grid[i].elastic_xs    = LCG_random_double(&seed);
		SD.nuclide_grid[i].absorbtion_xs = LCG_random_double(&seed);
		SD.nuclide_grid[i].fission_xs    = LCG_random_double(&seed);
		SD.nuclide_grid[i].nu_fission_xs = LCG_random_double(&seed);
	}

	// Sort so that each nuclide has data stored in ascending energy order.
	for( int i = 0; i < in.n_isotopes; i++ )
		qsort( &SD.nuclide_grid[i*in.n_gridpoints], in.n_gridpoints, sizeof(NuclideGridPoint), NGP_compare);
	
	// error debug check
	/*
	for( int i = 0; i < in.n_isotopes; i++ )
	{
		printf("NUCLIDE %d ==============================\n", i);
		for( int j = 0; j < in.n_gridpoints; j++ )
			printf("E%d = %lf\n", j, SD.nuclide_grid[i * in.n_gridpoints + j].energy);
	}
	*/
	

	////////////////////////////////////////////////////////////////////
	// Initialize Acceleration Structure
	////////////////////////////////////////////////////////////////////
	
	if( in.grid_type == NUCLIDE )
	{
		SD.length_unionized_energy_array = 0;
		SD.length_index_grid = 0;
	}
	
	if( in.grid_type == UNIONIZED )
	{
		if(mype == 0) printf("Intializing unionized grid...\n");

		// Allocate space to hold the union of all nuclide energy data
		SD.length_unionized_energy_array = in.n_isotopes * in.n_gridpoints;
		SD.unionized_energy_array = (double *) malloc( SD.length_unionized_energy_array * sizeof(double));
		assert(SD.unionized_energy_array != NULL );
		nbytes += SD.length_unionized_energy_array * sizeof(double);

		// Copy energy data over from the nuclide energy grid
		for( int i = 0; i < SD.length_unionized_energy_array; i++ )
			SD.unionized_energy_array[i] = SD.nuclide_grid[i].energy;

		// Sort unionized energy array
		qsort( SD.unionized_energy_array, SD.length_unionized_energy_array, sizeof(double), double_compare);

		// Allocate space to hold the acceleration grid indices
		SD.length_index_grid = SD.length_unionized_energy_array * in.n_isotopes;
		SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int));
		assert(SD.index_grid != NULL);
		nbytes += SD.length_index_grid * sizeof(int);

		// Generates the double indexing grid
		int * idx_low = (int *) calloc( in.n_isotopes, sizeof(int));
		assert(idx_low != NULL );
		double * energy_high = (double *) malloc( in.n_isotopes * sizeof(double));
		assert(energy_high != NULL );

		for( int i = 0; i < in.n_isotopes; i++ )
			energy_high[i] = SD.nuclide_grid[i * in.n_gridpoints + 1].energy;

		for( long e = 0; e < SD.length_unionized_energy_array; e++ )
		{
			double unionized_energy = SD.unionized_energy_array[e];
			for( long i = 0; i < in.n_isotopes; i++ )
			{
				if( unionized_energy < energy_high[i]  )
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
				else if( idx_low[i] == in.n_gridpoints - 2 )
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
				else
				{
					idx_low[i]++;
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
					energy_high[i] = SD.nuclide_grid[i * in.n_gridpoints + idx_low[i] + 1].energy;	
				}
			}
		}

		free(idx_low);
		free(energy_high);
	}

	if( in.grid_type == HASH )
	{
		if(mype == 0) printf("Intializing hash grid...\n");
		SD.length_unionized_energy_array = 0;
		SD.length_index_grid  = in.hash_bins * in.n_isotopes;
		SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int)); 
		assert(SD.index_grid != NULL);
		nbytes += SD.length_index_grid * sizeof(int);

		double du = 1.0 / in.hash_bins;

		// For each energy level in the hash table
		for( long e = 0; e < in.hash_bins; e++ )
		{
			double energy = e * du;

			// We need to determine the bounding energy levels for all isotopes
			for( long i = 0; i < in.n_isotopes; i++ )
			{
				SD.index_grid[e * in.n_isotopes + i] = grid_search_nuclide( in.n_gridpoints, energy, SD.nuclide_grid + i * in.n_gridpoints, 0, in.n_gridpoints-1);
			}
		}
	}

	////////////////////////////////////////////////////////////////////
	// Initialize Materials and Concentrations
	////////////////////////////////////////////////////////////////////
	if(mype == 0) printf("Intializing material data...\n");
	
	// Set the number of nuclides in each material
	SD.num_nucs  = load_num_nucs(in.n_isotopes);
	SD.length_num_nucs = 12; // There are always 12 materials in XSBench

	// Intialize the flattened 2D grid of material data. The grid holds
	// a list of nuclide indices for each of the 12 material types. The
	// grid is allocated as a full square grid, even though not all
	// materials have the same number of nuclides.
	SD.mats = load_mats(SD.num_nucs, in.n_isotopes, &SD.max_num_nucs);
	SD.length_mats = SD.length_num_nucs * SD.max_num_nucs;

	// Intialize the flattened 2D grid of nuclide concentration data. The grid holds
	// a list of nuclide concentrations for each of the 12 material types. The
	// grid is allocated as a full square grid, even though not all
	// materials have the same number of nuclides.
	SD.concs = load_concs(SD.num_nucs, SD.max_num_nucs);
	SD.length_concs = SD.length_mats;

	if(mype == 0) printf("Intialization complete. Allocated %.0lf MB of data on CPU.\n", nbytes/1024.0/1024.0 );

	return SD;
}

int * load_num_nucs(long n_isotopes)
{
	int * num_nucs = (int*)malloc(12*sizeof(int));
	
	// Material 0 is a special case (fuel). The H-M small reactor uses

	if( n_isotopes == 68 )
		num_nucs[0]  = 34; // HM Small is 34, H-M Large is 321

	num_nucs[6]  = 21;

	num_nucs[8]  = 21;
	num_nucs[9]  = 21;
	num_nucs[10] = 9;
	num_nucs[11] = 9;

	return num_nucs;

// Assigns an array of nuclide ID's to each material

			*max_num_nucs = num_nucs[m];
	}
	int * mats = (int *) malloc( num_mats * (*max_num_nucs) * sizeof(int) );

	// Small H-M has 34 fuel nuclides
	int mats0_Sml[] =  { 58, 59, 60, 61, 40, 42, 43, 44, 45, 46, 1, 2, 3, 7,
	                 8, 9, 10, 29, 57, 47, 48, 0, 62, 15, 33, 34, 52, 53,

	// Large H-M has 300 fuel nuclides
	int mats0_Lrg[321] =  { 58, 59, 60, 61, 40, 42, 43, 44, 45, 46, 1, 2, 3, 7,
	                 8, 9, 10, 29, 57, 47, 48, 0, 62, 15, 33, 34, 52, 53,
	                 54, 55, 56, 18, 23, 41 }; //fuel
	for( int i = 0; i < 321-34; i++ )

	// These are the non-fuel materials	
	int mats1[] =  { 63, 64, 65, 66, 67 }; // cladding

	                 49, 50, 51, 11, 12, 13, 14 }; // lower radial reflector
	int mats6[] =  { 24, 41, 4, 5, 19, 20, 21, 22, 35, 36, 37, 38, 39, 25,

	memcpy( mats + *max_num_nucs * 1,  mats1,  num_nucs[1]  * sizeof(int) );

// Randomizes the concentrations of all nuclides in a variety of materials
double * load_concs( int * num_nucs, int max_num_nucs )
{
	uint64_t seed = STARTING_SEED * STARTING_SEED;
	double * concs = (double *) malloc( 12 * max_num_nucs * sizeof( double ) );
	
	for( int i = 0; i < 12; i++ )
		for( int j = 0; j < num_nucs[i]; j++ )
			concs[i * max_num_nucs + j] = LCG_random_double(&seed);

	// test
	/*
	for( int i = 0; i < 12; i++ )
		for( int j = 0; j < num_nucs[i]; j++ )
			printf("concs[%d][%d] = %lf\n", i, j, concs[i][j] );
	*/

	return concs;
}

// All "baseline" code is at the top of this file. The baseline code is a simple

// optimizations made. Following these functions are a number of optimized variants,
// which each deploy a different combination of optimizations strategies. By
// default, XSBench will only run the baseline implementation. Optimized variants
// must be specifically selected using the "-k <optimized variant ID>" command
// line argument.

unsigned long long run_event_based_simulation_baseline(Inputs in, SimulationData GSD, int mype)
{
	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Running baseline event-based simulation...\n");

	int nthreads = 256;
	int nblocks = ceil( (double) in.lookups / (double) nthreads);

	xs_lookup_kernel_baseline<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

// In this kernel, we perform a single lookup with each thread. Threads within a warp
// do not really have any relation to each other, and divergence due to high nuclide count fuel
// material lookups are costly. This kernel constitutes baseline performance.
__global__ void xs_lookup_kernel_baseline(Inputs in, SimulationData GSD )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;

	// Set the initial seed value
	uint64_t seed = STARTING_SEED;	

	// Forward seed to lookup index (we need 2 samples per lookup)
	seed = fast_forward_LCG(seed, 2*i);

	// Randomly pick an energy and material for the particle
	double p_energy = LCG_random_double(&seed);
	int mat         = pick_mat(&seed); 
		
	double macro_xs_vector[5] = {0};
		
	// Perform macroscopic Cross Section Lookup
	calculate_macro_xs(
			p_energy,        // Sampled neutron energy (in lethargy)
			mat,             // Sampled material type index neutron is in
			in.n_isotopes,   // Total number of isotopes in simulation
			in.n_gridpoints, // Number of gridpoints per isotope in simulation
			GSD.num_nucs,     // 1-D array with number of nuclides per material
			GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
			GSD.unionized_energy_array, // 1-D Unionized energy array
			GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
			GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
			GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)
			GSD.max_num_nucs  // Maximum number of nuclides present in any material
			);

	// For verification, and to prevent the compiler from optimizing
	// all work out, we interrogate the returned macro_xs_vector array
	// to find its maximum value index, then increment the verification
	// value by that index. In this implementation, we have each thread
	// write to its thread_id index in an array, which we will reduce
	// with a thrust reduction kernel after the main simulation kernel.
	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}

// Calculates the microscopic cross section for a given nuclide & energy
__device__ void calculate_micro_xs(   double p_energy, int nuc, long n_isotopes,
                           long n_gridpoints,
                           double * __restrict__ egrid, int * __restrict__ index_data,
                           NuclideGridPoint * __restrict__ nuclide_grids,
                           long idx, double * __restrict__ xs_vector, int grid_type, int hash_bins ){
	// Variables
	double f;
	NuclideGridPoint * low, * high;

	// If using only the nuclide grid, we must perform a binary search
	// to find the energy location in this particular nuclide's grid.
	if( grid_type == NUCLIDE )
	{
		// Perform binary search on the Nuclide Grid to find the index
		idx = grid_search_nuclide( n_gridpoints, p_energy, &nuclide_grids[nuc*n_gridpoints], 0, n_gridpoints-1);

		// pull ptr from nuclide grid and check to ensure that
		// we're not reading off the end of the nuclide's grid
		if( idx == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + idx - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + idx];
	}
	else if( grid_type == UNIONIZED) // Unionized Energy Grid - we already know the index, no binary search needed.
	{
		// pull ptr from energy grid and check to ensure that
		// we're not reading off the end of the nuclide's grid
		if( index_data[idx * n_isotopes + nuc] == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + index_data[idx * n_isotopes + nuc] - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + index_data[idx * n_isotopes + nuc]];
	}
	else // Hash grid
	{
		// load lower bounding index
		int u_low = index_data[idx * n_isotopes + nuc];

		// Determine higher bounding index
		int u_high;
		if( idx == hash_bins - 1 )
			u_high = n_gridpoints - 1;
		else
			u_high = index_data[(idx+1)*n_isotopes + nuc] + 1;

		// Check edge cases to make sure energy is actually between these
		// Then, if things look good, search for gridpoint in the nuclide grid
		// within the lower and higher limits we've calculated.
		double e_low  = nuclide_grids[nuc*n_gridpoints + u_low].energy;
		double e_high = nuclide_grids[nuc*n_gridpoints + u_high].energy;
		int lower;
		if( p_energy <= e_low )
			lower = 0;
		else if( p_energy >= e_high )
			lower = n_gridpoints - 1;
		else
			lower = grid_search_nuclide( n_gridpoints, p_energy, &nuclide_grids[nuc*n_gridpoints], u_low, u_high);

		if( lower == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + lower - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + lower];
	}
	
	high = low + 1;
	
	// calculate the re-useable interpolation factor
	f = (high->energy - p_energy) / (high->energy - low->energy);

	// Total XS
	xs_vector[0] = high->total_xs - f * (high->total_xs - low->total_xs);
	
	// Elastic XS
	xs_vector[1] = high->elastic_xs - f * (high->elastic_xs - low->elastic_xs);
	
	// Absorbtion XS
	xs_vector[2] = high->absorbtion_xs - f * (high->absorbtion_xs - low->absorbtion_xs);
	
	// Fission XS
	xs_vector[3] = high->fission_xs - f * (high->fission_xs - low->fission_xs);
	
	// Nu Fission XS
	xs_vector[4] = high->nu_fission_xs - f * (high->nu_fission_xs - low->nu_fission_xs);
}

// Calculates macroscopic cross section based on a given material & energy 
__device__ void calculate_macro_xs( double p_energy, int mat, long n_isotopes,
                         long n_gridpoints, int * __restrict__ num_nucs,
                         double * __restrict__ concs,
                         double * __restrict__ egrid, int * __restrict__ index_data,
                         NuclideGridPoint * __restrict__ nuclide_grids,
                         int * __restrict__ mats,
                         double * __restrict__ macro_xs_vector, int grid_type, int hash_bins, int max_num_nucs ){
	int p_nuc; // the nuclide we are looking up
	long idx = -1;	
	double conc; // the concentration of the nuclide in the material

	// cleans out macro_xs_vector
	for( int k = 0; k < 5; k++ )
		macro_xs_vector[k] = 0;

	// If we are using the unionized energy grid (UEG), we only
	// need to perform 1 binary search per macroscopic lookup.
	// If we are using the nuclide grid search, it will have to be
	// done inside of the "calculate_micro_xs" function for each different
	// nuclide in the material.
	if( grid_type == UNIONIZED )
		idx = grid_search( n_isotopes * n_gridpoints, p_energy, egrid);	
	else if( grid_type == HASH )
	{
		double du = 1.0 / hash_bins;
		idx = p_energy / du;
	}
	
	// Once we find the pointer array on the UEG, we can pull the data
	// from the respective nuclide grids, as well as the nuclide
	// concentration data for the material
	// Each nuclide from the material needs to have its micro-XS array
	// looked up & interpolatied (via calculate_micro_xs). Then, the
	// micro XS is multiplied by the concentration of that nuclide
	// in the material, and added to the total macro XS array.
	// (Independent -- though if parallelizing, must use atomic operations
	//  or otherwise control access to the xs_vector and macro_xs_vector to
	//  avoid simulataneous writing to the same data structure)
	for( int j = 0; j < num_nucs[mat]; j++ )
	{
		double xs_vector[5];
		p_nuc = mats[mat*max_num_nucs + j];
		conc = concs[mat*max_num_nucs + j];
		calculate_micro_xs( p_energy, p_nuc, n_isotopes,
		                    n_gridpoints, egrid, index_data,
		                    nuclide_grids, idx, xs_vector, grid_type, hash_bins );
		for( int k = 0; k < 5; k++ )
			macro_xs_vector[k] += xs_vector[k] * conc;
	}
}


// binary search for energy on unionized energy grid
// returns lower index
__device__ long grid_search( long n, double quarry, double * __restrict__ A)
{
	long lowerLimit = 0;
	long upperLimit = n-1;
	long examinationPoint;
	long length = upperLimit - lowerLimit;

	while( length > 1 )
	{
		examinationPoint = lowerLimit + ( length / 2 );
		
		if( A[examinationPoint] > quarry )
			upperLimit = examinationPoint;
		else
			lowerLimit = examinationPoint;
		
		length = upperLimit - lowerLimit;
	}
	
	return lowerLimit;
}

// binary search for energy on nuclide energy grid
__host__ __device__ long grid_search_nuclide( long n, double quarry, NuclideGridPoint * A, long low, long high)
{
	long lowerLimit = low;
	long upperLimit = high;
	long examinationPoint;
	long length = upperLimit - lowerLimit;

	while( length > 1 )
	{
		examinationPoint = lowerLimit + ( length / 2 );
		
		if( A[examinationPoint].energy > quarry )
			upperLimit = examinationPoint;
		else
			lowerLimit = examinationPoint;
		
		length = upperLimit - lowerLimit;
	}
	
	return lowerLimit;
}

// picks a material based on a probabilistic distribution
__device__ int pick_mat( uint64_t * seed )
{
	// I have a nice spreadsheet supporting these numbers. They are
	// the fractions (by volume) of material in the core. Not a 
	// *perfect* approximation of where XS lookups are going to occur,
	// but this will do a good job of biasing the system nonetheless.

	// Also could be argued that doing fractions by weight would be 
	// a better approximation, but volume does a good enough job for now.

	double dist[12];
	dist[0]  = 0.140;	// fuel
	dist[1]  = 0.052;	// cladding
	dist[2]  = 0.275;	// cold, borated water
	dist[3]  = 0.134;	// hot, borated water
	dist[4]  = 0.154;	// RPV
	dist[5]  = 0.064;	// Lower, radial reflector
	dist[6]  = 0.066;	// Upper reflector / top plate
	dist[7]  = 0.055;	// bottom plate
	dist[8]  = 0.008;	// bottom nozzle
	dist[9]  = 0.015;	// top nozzle
	dist[10] = 0.025;	// top of fuel assemblies
	dist[11] = 0.013;	// bottom of fuel assemblies
	
	double roll = LCG_random_double(seed);

	// makes a pick based on the distro
	for( int i = 0; i < 12; i++ )
	{
		double running = 0;
		for( int j = i; j > 0; j-- )
			running += dist[j];
		if( roll < running )
			return i;
	}

	return 0;
}

__host__ __device__ double LCG_random_double(uint64_t * seed)
{
	// LCG parameters
	const uint64_t m = 9223372036854775808ULL; // 2^63
	const uint64_t a = 2806196910506780709ULL;
	const uint64_t c = 1ULL;
	*seed = (a * (*seed) + c) % m;
	return (double) (*seed) / (double) m;
}	

__device__ uint64_t fast_forward_LCG(uint64_t seed, uint64_t n)
{
	// LCG parameters
	const uint64_t m = 9223372036854775808ULL; // 2^63
	uint64_t a = 2806196910506780709ULL;
	uint64_t c = 1ULL;

	n = n % m;

	uint64_t a_new = 1;
	uint64_t c_new = 0;

	while(n > 0) 
	{
		if(n & 1)
		{
			a_new *= a;
			c_new = c_new * a + c;
		}
		c *= (a + 1);
		a *= a;

		n >>= 1;
	}

	return (a_new * seed + c_new) % m;
}

////////////////////////////////////////////////////////////////////////////////////
// Optimization 1 -- Basic kernel splitting of sampling & lookup routines
////////////////////////////////////////////////////////////////////////////////////
// This optimization requires a little extra data to store all material IDs and 
// energies for the sampled particles between kernel calls. By itself, this
// optimization is likely actually a bit of a slowdown compared to the baseline
// kernel. However, it will be used by better optimization kernels down the line.
////////////////////////////////////////////////////////////////////////////////////
unsigned long long run_event_based_simulation_optimization_1(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 1 - basic sample/lookup kernel splitting";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	xs_lookup_kernel_optimization_1<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

__global__ void sampling_kernel(Inputs in, SimulationData GSD )
{
	// The lookup ID.
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;

	// Set the initial seed value
	uint64_t seed = STARTING_SEED;	

	// Forward seed to lookup index (we need 2 samples per lookup)
	seed = fast_forward_LCG(seed, 2*i);

	// Randomly pick an energy and material for the particle
	double p_energy = LCG_random_double(&seed);
	int mat         = pick_mat(&seed); 

	// Store sample data in state array
	GSD.p_energy_samples[i] = p_energy;
	GSD.mat_samples[i] = mat;
}

__global__ void xs_lookup_kernel_optimization_1(Inputs in, SimulationData GSD )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;
		
	double macro_xs_vector[5] = {0};
		
	// Perform macroscopic Cross Section Lookup
	calculate_macro_xs(
			GSD.p_energy_samples[i],        // Sampled neutron energy (in lethargy)
			GSD.mat_samples[i],             // Sampled material type index neutron is in
			in.n_isotopes,   // Total number of isotopes in simulation
			in.n_gridpoints, // Number of gridpoints per isotope in simulation
			GSD.num_nucs,     // 1-D array with number of nuclides per material
			GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
			GSD.unionized_energy_array, // 1-D Unionized energy array
			GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
			GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
			GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)
			GSD.max_num_nucs  // Maximum number of nuclides present in any material
			);

	// For verification, and to prevent the compiler from optimizing
	// all work out, we interrogate the returned macro_xs_vector array
	// to find its maximum value index, then increment the verification
	// value by that index. In this implementation, we have each thread
	// write to its thread_id index in an array, which we will reduce
	// with a thrust reduction kernel after the main simulation kernel.
	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}

////////////////////////////////////////////////////////////////////////////////////

__global__ void xs_lookup_kernel_optimization_3(Inputs in, SimulationData GSD, int is_fuel )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;
	
	int mat = GSD.mat_samples[i];

	// If this is the fuel kernel, AND this is a fuel lookup, then perform a lookup
	// OR if this is not the fuel kernel, AND this is not a fuel lookup, then perform the lookup
	if( ((is_fuel == 1) && (mat == 0)) || ((is_fuel == 0) && (mat != 0 ) ))
	{
		double macro_xs_vector[5] = {0};
			
		// Perform macroscopic Cross Section Lookup
		calculate_macro_xs(
				GSD.p_energy_samples[i],        // Sampled neutron energy (in lethargy)
				mat,             // Sampled material type index neutron is in
				in.n_isotopes,   // Total number of isotopes in simulation
				in.n_gridpoints, // Number of gridpoints per isotope in simulation
				GSD.num_nucs,     // 1-D array with number of nuclides per material
				GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
				GSD.unionized_energy_array, // 1-D Unionized energy array
				GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
				GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
				GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
				macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
				in.grid_type,    // Lookup type (nuclide, hash, or unionized)
				in.hash_bins,    // Number of hash bins used (if using hash lookup type)
				GSD.max_num_nucs  // Maximum number of nuclides present in any material
				);

		// For verification, and to prevent the compiler from optimizing
		// all work out, we interrogate the returned macro_xs_vector array
		// to find its maximum value index, then increment the verification
		// value by that index. In this implementation, we have each thread
		// write to its thread_id index in an array, which we will reduce
		// with a thrust reduction kernel after the main simulation kernel.
		double max = -1.0;
		int max_idx = 0;
		for(int j = 0; j < 5; j++ )
		{
			if( macro_xs_vector[j] > max )
			{
				max = macro_xs_vector[j];
				max_idx = j;
			}
		}
		GSD.verification[i] = max_idx+1;
	}
}


////////////////////////////////////////////////////////////////////////////////////
// Optimization 4 -- Kernel Splitting + All Material Lookups + Full Sort
////////////////////////////////////////////////////////////////////////////////////
// This optimization builds on optimization 2, adding in a full sort before
// hand so that the warps should be densely packed together. This should maximize
// SIMD efficiency of the kernel, but may incur an added cost for the sort.
////////////////////////////////////////////////////////////////////////////////////
unsigned long long run_event_based_simulation_optimization_4(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 4 - All Material Lookup Kernels + Material Sort";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Count the number of fuel material lookups that need to be performed (fuel id = 0)
	int n_lookups_per_material[12];
	for( int m = 0; m < 12; m++ )
		n_lookups_per_material[m] = thrust::count(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, m);

	// Sort materials
	thrust::sort_by_key(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, GSD.p_energy_samples);
	
	// Launch all material kernels individually
	int offset = 0;
	for( int m = 0; m < 12; m++ )
	{
		nthreads = 32;
		nblocks = ceil((double) n_lookups_per_material[m] / (double) nthreads);
		xs_lookup_kernel_optimization_4<<<nblocks, nthreads>>>( in, GSD, m, n_lookups_per_material[m], offset );
		offset += n_lookups_per_material[m];
	}
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

__global__ void xs_lookup_kernel_optimization_4(Inputs in, SimulationData GSD, int m, int n_lookups, int offset )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= n_lookups )
		return;

	i += offset;

	// Check that our material type matches the kernel material
	int mat = GSD.mat_samples[i];
	if( mat != m )
		return;

	double macro_xs_vector[5] = {0};
		
	// Perform macroscopic Cross Section Lookup
	calculate_macro_xs(
			GSD.p_energy_samples[i],        // Sampled neutron energy (in lethargy)
			mat,             // Sampled material type index neutron is in
			in.n_isotopes,   // Total number of isotopes in simulation
			in.n_gridpoints, // Number of gridpoints per isotope in simulation
			GSD.num_nucs,     // 1-D array with number of nuclides per material
			GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
			GSD.unionized_energy_array, // 1-D Unionized energy array
			GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
			GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
			GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)
			GSD.max_num_nucs  // Maximum number of nuclides present in any material
			);

	// For verification, and to prevent the compiler from optimizing
	// all work out, we interrogate the returned macro_xs_vector array
	// to find its maximum value index, then increment the verification
	// value by that index. In this implementation, we have each thread
	// write to its thread_id index in an array, which we will reduce
	// with a thrust reduction kernel after the main simulation kernel.
	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}

////////////////////////////////////////////////////////////////////////////////////
// Optimization 5 -- Kernel Splitting + Fuel/Other Lookups + Fuel/Other Partition
////////////////////////////////////////////////////////////////////////////////////
// This optimization is similar to optimization 4, but instead of sorting
// fully by material, we just sort by fuel or not fuel. Similarly, instead of
// launching kernels for all materials, similar to optimization 3 we only launch
// kernels for the fuel and other mateirals.
////////////////////////////////////////////////////////////////////////////////////

// Comparator for partitioning stage
struct is_mat_fuel{
	__host__ __device__
		bool operator()(const int & a)
		{
			return a == 0;
		}
};

unsigned long long run_event_based_simulation_optimization_5(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 5 - Fuel/No Fuel Lookup Kernels + Fuel/No Fuel Sort";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Count the number of fuel material lookups that need to be performed (fuel id = 0)
	int n_fuel_lookups = thrust::count(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, 0);

	// Partition fuel into the first part of the array
	thrust::partition(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, GSD.p_energy_samples, is_mat_fuel());

	// Launch all material kernels individually (asynchronous is allowed)
	nblocks = ceil( (double) n_fuel_lookups / (double) nthreads);
	xs_lookup_kernel_optimization_5<<<nblocks, nthreads>>>( in, GSD, n_fuel_lookups, 0 );

	nblocks = ceil( (double) (in.lookups - n_fuel_lookups) / (double) nthreads);
	xs_lookup_kernel_optimization_5<<<nblocks, nthreads>>>( in, GSD, in.lookups-n_fuel_lookups, n_fuel_lookups );

	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

////////////////////////////////////////////////////////////////////////////////////
// Optimization 6 -- Kernel Splitting + All Material Lookups + Full Sort
//                   + Energy Sort
////////////////////////////////////////////////////////////////////////////////////
// This optimization builds on optimization 4, adding in a second sort by energy.
// It is extremely fast, as now most of the threads within a warp will be hitting
// the same indices in the lookup grids. This greatly reduces thread divergence and
// greatly improves cache efficiency and re-use.
//
// However, it is unlikely that this exact optimization would be possible in a real
// application like OpenMC. One major difference is that particle objects are quite
// large, often having 50+ variable fields, such that sorting them in memory becomes
// rather expensive. Instead, the best possible option would probably be to create
// intermediate indexing (per Hamilton et. al 2019), and run the kernels indirectly.
////////////////////////////////////////////////////////////////////////////////////
unsigned long long run_event_based_simulation_optimization_6(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 6 - Material & Energy Sorts + Material-specific Kernels";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Count the number of fuel material lookups that need to be performed (fuel id = 0)
	int n_lookups_per_material[12];
	for( int m = 0; m < 12; m++ )
		n_lookups_per_material[m] = thrust::count(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, m);

	// Sort by material first
	thrust::sort_by_key(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, GSD.p_energy_samples);

	// Now, sort each material by energy
	int offset = 0;
	for( int m = 0; m < 12; m++ )
	{
		thrust::sort_by_key(thrust::device, GSD.p_energy_samples + offset, GSD.p_energy_samples + offset + n_lookups_per_material[m], GSD.mat_samples + offset);
		offset += n_lookups_per_material[m];
	}
	
	// Launch all material kernels individually
	offset = 0;
	for( int m = 0; m < 12; m++ )
	{
		nthreads = 32;
		nblocks = ceil((double) n_lookups_per_material[m] / (double) nthreads);
		xs_lookup_kernel_optimization_4<<<nblocks, nthreads>>>( in, GSD, m, n_lookups_per_material[m], offset );
		offset += n_lookups_per_material[m];
	}
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

int double_compare(const void * a, const void * b)
{
	double A = *((double *) a);
	double B = *((double *) b);

	if( A > B )
		return 1;
	else if( A < B )
		return -1;
	else
		return 0;
}

int NGP_compare(const void * a, const void * b)
{
	NuclideGridPoint A = *((NuclideGridPoint *) a);
	NuclideGridPoint B = *((NuclideGridPoint *) b);

	if( A.energy > B.energy )
		return 1;
	else if( A.energy < B.energy )
		return -1;
	else
		return 0;
}


// RNG Used for Verification Option.
// This one has a static seed (must be set manually in source).
// Park & Miller Multiplicative Conguential Algorithm
// From "Numerical Recipes" Second Edition
double rn_v(void)
{
	static unsigned long seed = 1337;
	double ret;
	unsigned long n1;
	unsigned long a = 16807;
	unsigned long m = 2147483647;
	n1 = ( a * (seed) ) % m;
	seed = n1;
	ret = (double) n1 / m;
	return ret;
}


size_t estimate_mem_usage( Inputs in )
{
	size_t single_nuclide_grid = in.n_gridpoints * sizeof( NuclideGridPoint );
	size_t all_nuclide_grids   = in.n_isotopes * single_nuclide_grid;
	size_t size_UEG            = in.n_isotopes*in.n_gridpoints*sizeof(double) + in.n_isotopes*in.n_gridpoints*in.n_isotopes*sizeof(int);
	size_t size_hash_grid      = in.hash_bins * in.n_isotopes * sizeof(int);
	size_t memtotal;

	if( in.grid_type == UNIONIZED )
		memtotal          = all_nuclide_grids + size_UEG;
	else if( in.grid_type == NUCLIDE )
		memtotal          = all_nuclide_grids;
	else
		memtotal          = all_nuclide_grids + size_hash_grid;

	memtotal          = ceil(memtotal / (1024.0*1024.0));
	return memtotal;
}

double get_time(void)
{
	#ifdef MPI
	return MPI_Wtime();
	#endif

	#ifdef OPENMP
	return omp_get_wtime();
	#endif

	// If using C++, we can do this:
	unsigned long us_since_epoch = std::chrono::high_resolution_clock::now().time_since_epoch() / std::chrono::microseconds(1);
	return (double) us_since_epoch / 1.0e6;
}
