## Key CUDA Energy-Efficiency Techniques for NVIDIA A100### 1. Memory access coalescingMake warp threads access consecutive global memory addresses whenever possible. Prefer struct-of-arrays layouts over array-of-structs, and avoid strided per-thread access patterns such as `arr[threadIdx.x * N + j]`.**Most impactful when:** the kernel is memory-bound or has high DRAM traffic. On A100, reducing uncoalesced HBM2e transactions can significantly reduce both runtime and DRAM energy.---### 2. Shared memory useUse shared memory to stage global-memory data that is reused by multiple threads in the same block. Load tiles cooperatively from global memory once, then reuse them from on-chip SRAM. Avoid shared-memory bank conflicts by ensuring neighboring threads do not repeatedly access the same bank.**Most impactful when:** threads in a block reuse the same or nearby data, such as tiled stencil, matrix, reduction, lookup, or grid-search patterns.---### 3. Occupancy optimizationTune block size, register use, and shared-memory allocation to keep enough active warps resident on each SM. For A100, 128–256 threads per block is often a good starting point. Use occupancy tools or `cudaOccupancyMaxPotentialBlockSize`. Avoid register spilling, since spilled local memory often goes to DRAM.**Most impactful when:** the kernel has memory latency to hide or suffers from low active-warp occupancy due to excessive registers, shared memory, or poor block sizing.---### 4. Warp divergence reductionMinimize branches where threads in the same warp take different paths. Use branchless arithmetic, predication-friendly short branches, or reorder/sort work so threads in a warp follow similar control flow.**Most impactful when:** branch bodies are large, data-dependent, or frequently cause different warp lanes to execute different paths.---### 5. Kernel fusionFuse consecutive kernels that operate on the same data so intermediate results stay in registers or shared memory instead of being written to and reread from global memory. This also reduces kernel launch overhead.**Most impactful when:** multiple kernels form a pipeline with compatible launch configurations and intermediate arrays are used only between adjacent stages.---### 6. Read-only cache with `__ldg`, `const`, and `__restrict__`Mark read-only input arrays as `const __restrict__`, or explicitly use `__ldg()` for read-only loads. This can route accesses through the read-only/texture cache path and reduce L2 and DRAM pressure.**Most impactful when:** arrays are read-only within the kernel and exhibit spatial or temporal locality. It can still help for irregular read-only lookup tables by improving cache behavior.---### 7. Arithmetic precision tradeoffsUse the lowest precision that preserves correctness. Prefer `float` over `double` when acceptable, since double uses more bandwidth, registers, and lower-throughput FP64 units. Use FMA and fast-math intrinsics such as `__expf`, `__sinf`, or `__fdividef` only when their numerical accuracy is sufficient.**Most impactful when:** the kernel is compute-bound, register-limited, or moving large floating-point arrays through memory.---### 8. Synchronization minimizationUse `__syncthreads()` only when required by true block-wide data dependencies. Move barriers out of loops when possible, use warp-level primitives such as `__syncwarp()` or warp reductions when only intra-warp coordination is needed, and reduce high-contention atomics by doing block-level reductions first.**Most impactful when:** kernels contain frequent barriers, reductions, producer-consumer shared-memory phases, or many contended atomics.---### 9. Prefetching and data movement controlKeep data resident on the GPU across multiple kernel launches, minimize host-device transfers, use pinned host memory for necessary transfers, and overlap transfers with computation using streams and `cudaMemcpyAsync`. Avoid implicit Unified Memory page migrations when predictable explicit copies are possible.**Most impactful when:** the application repeatedly transfers data between host and device, uses Unified Memory with page faults, or has independent computation that can overlap with transfers.---### Practical priority on A100For energy reduction, first profile the kernel. If it is memory-bound, prioritize coalescing, reducing DRAM traffic, shared-memory reuse, read-only caching, and kernel fusion. If it is compute-bound, prioritize precision reduction, FMA/fast math where valid, divergence reduction, and instruction-count reduction. In all cases, tune occupancy and remove unnecessary synchronization.
