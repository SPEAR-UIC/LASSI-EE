- **Memory access coalescing**  - Arrange data so consecutive threads in a warp access consecutive memory addresses.  - Prefer Structure-of-Arrays over Array-of-Structs when each thread reads the same field from different elements.  - Avoid strided patterns such as `arr[threadIdx.x * N + j]`; use layouts like `arr[j * blockDim.x + threadIdx.x]`.  - **Most impactful when:** the kernel is memory-bound and performs large global-memory reads/writes. On A100, reducing HBM2e transactions can significantly reduce both runtime and DRAM energy.- **Shared memory use**  - Use shared memory to stage data that is reused by multiple threads in a block.  - Load global memory once per tile, synchronize, then reuse the tile from shared memory.  - Avoid shared-memory bank conflicts by ensuring warp threads do not repeatedly access addresses mapping to the same bank.  - On A100, use larger shared-memory allocations when beneficial, but watch the occupancy tradeoff.  - **Most impactful when:** there is spatial or temporal reuse within a block, such as stencil codes, reductions, tiled matrix operations, or repeated lookups of nearby data.- **Occupancy optimization**  - Use block sizes that are multiples of 32; 128–256 threads per block is often a good starting point on A100.  - Tune register use, shared-memory use, and block size to keep enough active warps per SM to hide memory latency.  - Avoid register spilling, because spilled “local” memory usually goes to global memory and increases energy.  - Use `cudaOccupancyMaxPotentialBlockSize`, Nsight Compute, and possibly `__launch_bounds__` to guide tuning.  - **Most impactful when:** the kernel is latency-bound or has low active-warp occupancy due to excessive registers, shared memory, or poor block sizing. Do not maximize occupancy blindly if it increases spilling or reduces data reuse.- **Warp divergence reduction**  - Keep threads within a warp on the same control-flow path whenever possible.  - Replace short divergent branches with predication or branchless arithmetic.  - Group or sort input data so threads in the same warp process similar work.  - Keep branch bodies short so the compiler can predicate them efficiently.  - **Most impactful when:** branch decisions vary significantly across threads in a warp and the branch bodies contain meaningful work.- **Kernel fusion**  - Fuse consecutive kernels that operate on the same data and have compatible dependencies.  - Keep intermediate values in registers or shared memory instead of writing them to global memory and reading them back.  - Also reduces kernel-launch overhead.  - **Most impactful when:** multiple small or bandwidth-bound kernels are chained together and intermediate arrays are written only to be consumed by the next kernel.- **Read-only cache / `__ldg` / `const __restrict__`**  - Mark read-only kernel inputs as `const __restrict__` so the compiler can optimize loads.  - Use `__ldg()` for explicitly read-only data when appropriate.  - This can reduce pressure on normal global-memory paths and improve cache reuse.  - **Most impactful when:** arrays are read-only and have spatial or temporal locality. It can still help modestly for irregular read-only access patterns, but benefits are smaller when accesses are completely random and miss cache.- **Arithmetic precision tradeoffs**  - Use the lowest precision that preserves correctness: prefer `float` over `double` when acceptable.  - On A100, FP64 has far lower throughput and doubles memory traffic compared with FP32.  - Consider FP16, BF16, or TF32/Tensor Cores for suitable dense linear algebra or ML-style workloads.  - Use FMA where possible; the compiler often emits it automatically.  - Use fast-math intrinsics such as `__expf`, `__sinf`, or `__fdividef` only when the accuracy loss is acceptable.  - **Most impactful when:** the kernel is compute-bound, uses many FP64 operations, or moves large floating-point arrays through memory.- **Synchronization minimization**  - Remove unnecessary `__syncthreads()`.  - Move barriers out of loops when data dependencies allow.  - Use warp-level primitives such as `__syncwarp`, `__ballot_sync`, or warp reductions when only intra-warp synchronization is needed.  - Reduce high-contention atomics by performing per-block reductions in shared memory and issuing fewer global atomics.  - **Most impactful when:** kernels contain frequent barriers, reductions, or atomics that serialize execution and leave SM resources idle.- **Prefetching**  - For predictable tiled access patterns, prefetch the next tile while computing on the current tile.  - On A100, consider asynchronous global-to-shared copies, such as `cp.async` or CUDA pipeline abstractions, to overlap memory movement with computation.  - For Unified Memory, use `cudaMemPrefetchAsync` to move data to the GPU before kernels run and avoid page-fault-driven migration.  - For host-device transfers, use pinned memory and `cudaMemcpyAsync` with streams to overlap transfers with computation.  - **Most impactful when:** memory access is predictable and there is enough independent work to hide latency. It is much less effective for highly random access patterns with little reuse.
