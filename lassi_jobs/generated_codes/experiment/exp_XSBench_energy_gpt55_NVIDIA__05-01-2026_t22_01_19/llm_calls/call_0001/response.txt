- **Memory access coalescing:** Arrange global memory accesses so adjacent threads in a warp read/write adjacent addresses. Prefer structure-of-arrays over array-of-structures when each thread reads the same field from different elements. This reduces the number of HBM2e transactions and is often the highest-impact optimization for memory-bound A100 kernels.- **Shared memory use:** Cache data in shared memory when multiple threads in a block reuse the same or nearby global-memory data. Load tiles cooperatively, reuse them on-chip, and avoid bank conflicts by choosing layouts/strides that do not map many threads to the same bank. Most impactful when there is block-level spatial or temporal reuse and global memory traffic can be reduced.- **Occupancy optimization:** Use enough active warps per SM to hide memory latency without causing register spilling or excessive shared-memory pressure. On A100, 128–256 threads per block is often a good starting point; use occupancy tools and Nsight metrics to tune. Most impactful for latency-bound or memory-bound kernels where more resident warps improve throughput, but avoid chasing occupancy if it increases spills or reduces cache/shared-memory efficiency.- **Warp divergence reduction:** Restructure branches so threads in the same warp follow the same path when possible. Use predication or branchless selection for short conditionals, and group/sort work so warps process similar cases. Most impactful when branches are data-dependent and expensive, causing warps to serialize multiple execution paths.- **Kernel fusion:** Combine consecutive kernels that operate on the same data and have compatible dependencies so intermediate values stay in registers or shared memory instead of being written to and reread from global memory. Most impactful when kernels are memory-bound, produce large intermediate arrays, or launch overhead is significant relative to kernel runtime.- **Read-only cache / `__ldg`:** Mark read-only input pointers as `const __restrict__` or explicitly use `__ldg()` for read-only loads. This can route accesses through the read-only/texture cache path and reduce L2/HBM pressure. Most impactful for read-only arrays with spatial or temporal locality, and still useful for some irregular read-heavy workloads.- **Arithmetic precision tradeoffs:** Use the lowest precision that preserves correctness: prefer `float` over `double` when acceptable, use FMA where possible, and consider CUDA fast-math intrinsics only if their accuracy is sufficient. Most impactful for compute-bound kernels and memory-bound kernels where lower precision also halves data movement and register/shared-memory footprint.- **Synchronization minimization:** Remove unnecessary `__syncthreads()`, move barriers outside loops when possible, and use warp-level primitives such as `__syncwarp()` or warp reductions when only intra-warp coordination is needed. Reduce high-contention atomics by performing block-level reductions and issuing fewer global atomics. Most impactful when barriers or atomics cause frequent stalls or serialization.- **Prefetching / data movement control:** Keep data resident on the GPU across kernel launches, avoid unnecessary host-device transfers, use pinned memory and asynchronous copies when transfers are required, and avoid unmanaged page migrations when possible. For managed memory, explicitly prefetch data to the GPU before use if Unified Memory is used. Most impactful when data transfer or page migration time contributes noticeably to total runtime and energy.
