[CONTEXT KNOWLEDGE]
- **Coalesce global memory accesses**
  - Arrange data and indexing so consecutive threads in a warp access consecutive addresses.
  - Prefer Struct-of-Arrays over Array-of-Structs when each thread reads the same field from different elements.
  - Avoid strided patterns such as `arr[threadIdx.x * N + j]`; prefer layouts like `arr[j * blockDim.x + threadIdx.x]`.
  - **Most impactful when:** the kernel is memory-bound and performs large amounts of global memory traffic. On A100, reducing HBM2e transactions directly reduces both runtime and DRAM energy.

- **Use shared memory for reused data**
  - Load reusable tiles from global memory into shared memory once per block, then have threads reuse the on-chip copy.
  - Avoid shared-memory bank conflicts; for 32-bank shared memory, avoid access strides that are multiples of 32.
  - On A100, consider using larger dynamic shared memory allocations when beneficial, up to the architecture limit.
  - **Most impactful when:** multiple threads in a block access overlapping or nearby data, such as stencil, tiling, reductions, matrix-like operations, or repeated table lookups with block-level locality.

- **Tune occupancy**
  - Use block sizes that are multiples of 32; 128–256 threads per block are often a good starting point on A100.
  - Balance occupancy against register usage and shared-memory usage.
  - Avoid excessive register pressure that causes spills to local memory, because local memory resides in DRAM.
  - Use tools such as `cudaOccupancyMaxPotentialBlockSize`, Nsight Compute, and `__launch_bounds__` where appropriate.
  - **Most impactful when:** the kernel has latency from memory operations or long instruction dependencies and needs enough active warps to hide stalls. It is also important when register or shared-memory usage limits active blocks per SM.

- **Reduce warp divergence**
  - Minimize branches where threads in the same warp take different paths.
  - Use branchless selection or predication for short conditional code.
  - Group or sort work so that threads in the same warp follow similar control-flow paths when possible.
  - Keep divergent regions small.
  - **Most impactful when:** branch bodies are long, branches are data-dependent, or different threads in a warp frequently execute different paths, causing serialized execution.

- **Fuse kernels when possible**
  - Combine consecutive kernels that operate on the same data and have compatible dependencies.
  - Keep intermediate values in registers or shared memory instead of writing them to global memory and reading them back.
  - Reduce kernel-launch overhead and global-memory round trips.
  - **Most impactful when:** kernels are bandwidth-bound, produce intermediate arrays, or are small enough that launch overhead is a meaningful fraction of runtime.

- **Use read-only cache paths with `__ldg` or `const __restrict__`**
  - Mark read-only input arrays as `const __restrict__`.
  - Use `__ldg(&arr[i])` for explicit read-only loads when appropriate.
  - This can reduce L2 and DRAM pressure by improving caching of immutable data.
  - **Most impactful when:** arrays are read-only within the kernel and have spatial or temporal locality. It can also help for irregular read-only table lookups by using the texture/read-only cache path.

- **Choose arithmetic precision carefully**
  - Use `float` instead of `double` when the application’s accuracy requirements allow it.
  - Lower precision reduces data movement, register usage, shared-memory usage, and arithmetic cost.
  - Use fast math intrinsics such as `__expf`, `__logf`, `__sinf`, `__cosf`, or `__fdividef` only when their reduced precision is acceptable.
  - Use FMA, e.g. `fmaf`, where appropriate; it reduces instruction count and often improves accuracy.
  - **Most impactful when:** the kernel is compute-bound, uses many double-precision operations, or stores/loads large floating-point arrays where halving data size reduces memory traffic.

- **Minimize synchronization**
  - Remove unnecessary `__syncthreads()`.
  - Move barriers out of loops when possible.
  - Use warp-level primitives such as `__syncwarp`, `__ballot_sync`, or warp reductions when synchronization is only needed within a warp.
  - Reduce high-contention atomics by doing block-level reductions in shared memory and issuing fewer global atomics.
  - **Most impactful when:** barriers occur inside loops, atomics are highly contended, or synchronization stalls many warps within a block.

- **Prefetch and manage data movement explicitly**
  - Keep data resident on the GPU across multiple kernel launches when possible.
  - Minimize host-device transfers.
  - Use pinned host memory and asynchronous copies with streams when transfers are unavoidable.
  - For Unified Memory, avoid unexpected page migration; prefer explicit `cudaMalloc`/`cudaMemcpy` for predictable energy behavior, or prefetch managed data to the GPU before use.
  - **Most impactful when:** the application repeatedly transfers data between CPU and GPU, uses Unified Memory with page faults, or has kernels whose runtime is comparable to data-transfer overhead.

## 1. Overall algorithm and GPU resource-utilization profile

### Algorithm summary
- The program implements the XSBench event-based macroscopic cross-section lookup workload.
- Each lookup:
  1. Generates a pseudo-random neutron energy.
  2. Selects a material using a probability distribution.
  3. Computes a macroscopic cross-section vector by iterating over all nuclides in that material.
  4. For each nuclide, performs a microscopic cross-section lookup and interpolation.
  5. Writes a small verification value, later reduced with Thrust.

### Lookup modes
The microscopic lookup path depends on `in.grid_type`:

- `UNIONIZED`
  - Performs one binary search over the unionized energy grid per macroscopic lookup.
  - Uses the resulting index to access `index_grid`, then accesses the nuclide grid.
  - Avoids a binary search per nuclide but uses a very large, irregularly accessed index table.

- `NUCLIDE`
  - Performs a binary search in each nuclide grid for each nuclide in the material.
  - More compute and branch-heavy than unionized lookup.
  - Avoids the large unionized index grid.

- `HASH`
  - Uses a hash bin to restrict the search range, then performs a bounded search in the nuclide grid.
  - Reduces search length and memory footprint relative to the unionized grid.
  - Still contains irregular global memory access.

### Compute-bound vs memory-bound
- The dominant behavior is memory-bound and latency-bound, not compute-bound.
- Reasons:
  - The main data structures are large and mostly read with random or semi-random access patterns.
  - Binary searches cause divergent control flow and irregular memory references.
  - Each microscopic lookup loads two `NuclideGridPoint` records, each containing six `double` fields.
  - Arithmetic per loaded byte is modest: a few double-precision interpolations and accumulations per pair of grid points.
- There is also nontrivial integer arithmetic in the random-number generator, especially `fast_forward_LCG`, but for large material lookups the cross-section table traffic dominates.

### Access locality
- Baseline and early optimization kernels have poor warp-level locality because each thread processes an independent random lookup.
- Optimization 4 improves material locality by sorting by material.
- Optimization 6 further improves locality by sorting by both material and energy; this is the best variant for cache reuse and energy efficiency, although the sorting cost may dominate for smaller lookup counts.

### Energy-efficiency opportunities
- Reduce random global-memory traffic:
  - Prefer sorted/material-grouped execution when lookup count is large enough to amortize sorting.
  - Energy sorting, as in Optimization 6, improves cache reuse substantially.
- Reduce precision and memory footprint where acceptable:
  - Many `double` fields could likely become `float` if application accuracy permits.
- Reduce redundant verification traffic:
  - The code writes one verification value per lookup and then performs a full-device Thrust reduction. A hierarchical reduction or per-block reduction could reduce global memory traffic.
- Improve occupancy of one-warp kernels:
  - Most optimized variants use 32-thread blocks, which can limit occupancy on A100 because of the resident-block limit.
- Move small read-only data to constant memory or shared memory:
  - Material composition arrays, concentration arrays, `num_nucs`, and the material probability distribution are small and repeatedly used.

## 2. CUDA kernel launch configurations and A100 occupancy expectations

### Baseline
#### `xs_lookup_kernel_baseline`
- Launch configuration:
  - Threads per block: `256`
  - Blocks: `ceil(in.lookups / 256.0)`
- Occupancy expectation on A100:
  - 256 threads/block = 8 warps/block.
  - If register usage is moderate, this can reach high theoretical occupancy: up to 8 resident blocks/SM, 64 resident warps/SM.
  - Actual occupancy may be reduced by register pressure from:
    - Local arrays such as `macro_xs_vector[5]` and `xs_vector[5]`.
    - Inlined device functions.
    - Double-precision temporaries.
  - Likely better occupancy than the 32-thread optimized kernels, but with worse warp divergence and memory locality.

### Optimization 1
#### `sampling_kernel`
- Launch configuration:
  - Threads per block: `32`
  - Blocks: `ceil(in.lookups / 32.0)`

#### `xs_lookup_kernel_optimization_1`
- Launch configuration:
  - Threads per block: `32`
  - Blocks: `ceil(in.lookups / 32.0)`

#### A100 occupancy expectation
- 32 threads/block = 1 warp/block.
- A100 supports up to 64 resident warps/SM but has a resident block limit of 32 blocks/SM.
- Therefore, even with low register usage, one-warp blocks can reach only about 32 resident warps/SM, or roughly 50% theoretical warp occupancy.
- This may be insufficient to hide memory latency for this irregular memory-bound workload.
- Energy concern:
  - Splitting sampling and lookup adds extra global memory writes and reads for `p_energy_samples` and `mat_samples`.

### Optimization 2
#### `sampling_kernel`
- Same as Optimization 1:
  - Threads per block: `32`
  - Blocks: `ceil(in.lookups / 32.0)`

#### `xs_lookup_kernel_optimization_2`
- Launched 12 times, once per material.
- Launch configuration for each material:
  - Threads per block: `32`
  - Blocks: `ceil(in.lookups / 32.0)`

#### A100 occupancy expectation
- Same 32-thread block limitation: likely capped near 50% theoretical warp occupancy.
- Additional issue:
  - Every material-specific kernel scans the entire lookup array.
  - Most threads return early because `mat != m`.
  - This wastes instruction issue, memory bandwidth for reading `mat_samples`, and launch overhead.
- Energy concern:
  - Twelve full-array passes are expensive unless the material-specific reduction in divergence compensates.

### Optimization 3
#### `sampling_kernel`
- Threads per block: `32`
- Blocks: `ceil(in.lookups / 32.0)`

#### `xs_lookup_kernel_optimization_3`
- Launched twice:
  - First with `is_fuel = 0`
  - Second with `is_fuel = 1`
- Launch configuration for each:
  - Threads per block: `32`
  - Blocks: `ceil(in.lookups / 32.0)`

#### A100 occupancy expectation
- Same one-warp block limitation.
- Better than Optimization 2 in launch count and full-array scan count.
- Still performs full-array scans for both fuel and non-fuel categories.
- Non-fuel kernel still contains material-count divergence because non-fuel materials have different numbers of nuclides.

### Optimization 4
#### `sampling_kernel`
- Threads per block: `32`
- Blocks: `ceil(in.lookups / 32.0)`

#### Thrust operations
- `thrust::count` called 12 times.
- `thrust::sort_by_key` called once.
- Internal kernel launch configurations are not visible in the source.

#### `xs_lookup_kernel_optimization_4`
- Launched once per material, 12 launches total.
- Per-material launch configuration:
  - Threads per block: `32`
  - Blocks: `ceil(n_lookups_per_material[m] / 32.0)`

#### A100 occupancy expectation
- One-warp block occupancy limitation remains.
- However, sorting by material allows each kernel to process a compact region of active lookups.
- This avoids most early-return waste and greatly reduces material-count divergence.
- Energy tradeoff:
  - Sorting costs extra global memory traffic and Thrust kernel launches.
  - For large lookup counts, the improved SIMD efficiency and locality may outweigh sorting cost.

### Optimization 5
#### `sampling_kernel`
- Threads per block: `32`
- Blocks: `ceil(in.lookups / 32.0)`

#### Thrust operations
- `thrust::count` called once.
- `thrust::partition` called once.
- Internal kernel launch configurations are not visible in the source.

#### `xs_lookup_kernel_optimization_5`
- Launched twice:
  1. Fuel region:
     - Threads per block: `32`
     - Blocks: `ceil(n_fuel_lookups / 32.0)`
  2. Non-fuel region:
     - Threads per block: `32`
     - Blocks: `ceil((in.lookups - n_fuel_lookups) / 32.0)`

#### A100 occupancy expectation
- One-warp block limitation remains.
- Lower sorting overhead than full material sort.
- Better grouping than baseline, but non-fuel work still mixes different material sizes.

### Optimization 6
#### `sampling_kernel`
- Threads per block: `32`
- Blocks: `ceil(in.lookups / 32.0)`

#### Thrust operations
- `thrust::count` called 12 times.
- `thrust::sort_by_key` by material called once.
- `thrust::sort_by_key` by energy called once per material, 12 additional sorts.
- Internal kernel launch configurations are not visible in the source.

#### `xs_lookup_kernel_optimization_4`
- Reused as the lookup kernel.
- Launched once per material.
- Per-material launch configuration:
  - Threads per block: `32`
  - Blocks: `ceil(n_lookups_per_material[m] / 32.0)`

#### A100 occupancy expectation
- Same one-warp block limitation.
- Best memory locality and least warp divergence among the explicit variants.
- Energy tradeoff:
  - Most expensive preprocessing.
  - Likely worthwhile only for sufficiently large `in.lookups`.
  - Improves cache behavior by making threads in a warp access similar energy regions.

### General launch-configuration opportunity
- The 32-thread lookup blocks in Optimizations 1–6 may underutilize A100 because of the resident-block limit.
- Using 128 or 256 threads per block for the sorted/material-grouped kernels could improve latency hiding while preserving material locality.
- The baseline 256-thread block configuration is more occupancy-friendly, but it suffers from much worse divergence and memory randomness.

## 3. Global memory access patterns by kernel

### `sampling_kernel`
- Reads:
  - No large global data reads.
- Writes:
  - `GSD.p_energy_samples[i]`
  - `GSD.mat_samples[i]`
- Access pattern:
  - Consecutive thread IDs write consecutive addresses.
  - Stores are coalesced.
- Energy profile:
  - Efficient global stores.
  - Main cost is computation in `fast_forward_LCG`, `LCG_random_double`, and divergent `pick_mat`.

### `xs_lookup_kernel_baseline`
- Reads/writes:
  - Writes `GSD.verification[i]`: coalesced.
  - Reads `num_nucs[mat]`: random over 12 materials, likely cache-friendly.
  - Reads `mats[mat * max_num_nucs + j]`: mostly sequential within a thread, scattered across a warp.
  - Reads `concs[mat * max_num_nucs + j]`: mostly sequential within a thread, scattered across a warp.
  - Reads `unionized_energy_array` during binary search: divergent and increasingly scattered.
  - Reads `index_grid`: scattered.
  - Reads `nuclide_grid`: scattered, with two adjacent grid points per microscopic lookup.
- Coalescing:
  - Verification writes are coalesced.
  - Most physics-data reads are not coalesced.
- Energy concern:
  - Random double-precision global loads dominate.

### `xs_lookup_kernel_optimization_1`
- Reads:
  - `GSD.p_energy_samples[i]`: coalesced.
  - `GSD.mat_samples[i]`: coalesced.
  - Cross-section data: same irregular pattern as baseline.
- Writes:
  - `GSD.verification[i]`: coalesced.
- Coalescing:
  - Sample-array accesses are coalesced.
  - Main lookup arrays remain scattered.
- Energy concern:
  - Adds extra sample-array memory traffic compared with baseline.

### `xs_lookup_kernel_optimization_2`
- Reads:
  - `GSD.mat_samples[i]`: coalesced full-array scan in each of 12 launches.
  - For matching material, reads `GSD.p_energy_samples[i]`: coalesced among active lanes, but active lanes may be sparse.
  - Cross-section data: better material uniformity among active threads, but still random by energy.
- Writes:
  - `GSD.verification[i]`: sparse, masked stores.
- Coalescing:
  - Initial material scan is coalesced.
  - Active lookup work is not densely packed because the array is not sorted.
- Energy concern:
  - Many lanes return early.
  - Twelve passes over `mat_samples` waste energy.

### `xs_lookup_kernel_optimization_3`
- Reads:
  - `GSD.mat_samples[i]`: coalesced in both launches.
  - `GSD.p_energy_samples[i]`: coalesced among active lanes, but active lanes may be sparse.
  - Cross-section data: fuel launch is material-uniform; non-fuel launch still mixes materials.
- Writes:
  - `GSD.verification[i]`: sparse, masked stores.
- Coalescing:
  - Better than Optimization 2 in number of scans.
  - Still not densely packed.
- Energy concern:
  - Two full-array scans.
  - Non-fuel divergence remains.

### `xs_lookup_kernel_optimization_4`
- Input arrays are sorted by material before launch.
- Reads:
  - `GSD.mat_samples[i]`: coalesced and material-uniform.
  - `GSD.p_energy_samples[i]`: coalesced.
  - `mats` and `concs`: same material for all threads in a launch, improving cache reuse.
  - `index_grid` and `nuclide_grid`: still irregular by energy, unless energies are also sorted.
- Writes:
  - `GSD.verification[i]`: coalesced over the sorted compact material segment.
- Coalescing:
  - Sample and verification accesses are coalesced.
  - Material metadata reuse is improved.
  - Cross-section grid accesses remain largely scattered.
- Energy profile:
  - More efficient than unsorted material-specific kernels.
  - Sorting overhead must be amortized.

### `xs_lookup_kernel_optimization_5`
- Input arrays are partitioned into fuel and non-fuel regions.
- Reads:
  - `GSD.mat_samples[i]`: coalesced.
  - `GSD.p_energy_samples[i]`: coalesced.
  - Fuel region has uniform material.
  - Non-fuel region mixes materials.
- Writes:
  - `GSD.verification[i]`: coalesced within each compact partition.
- Coalescing:
  - Better than Optimizations 2 and 3.
  - Less precise grouping than Optimization 4.
- Energy profile:
  - Good compromise when full material sort is too expensive.

### Optimization 6 lookup path
- Uses `xs_lookup_kernel_optimization_4` after sorting by material and energy.
- Reads:
  - Sample arrays: coalesced.
  - Material arrays: material-uniform and cache-friendly.
  - Energy-grid and nuclide-grid accesses: substantially improved locality.
- Coalescing:
  - Not necessarily strictly coalesced for `index_grid`, because adjacent energy indices map to addresses separated by `n_isotopes`.
  - However, nearby or identical energy indices across a warp improve L1/L2 cache reuse and reduce random DRAM transactions.
- Energy profile:
  - Best lookup-kernel energy behavior.
  - Highest preprocessing cost.

### `calculate_macro_xs`
- Accesses:
  - `num_nucs[mat]`: small, cache-friendly.
  - `mats[mat * max_num_nucs + j]`: sequential within each thread.
  - `concs[mat * max_num_nucs + j]`: sequential within each thread.
- Coalescing:
  - Poor when adjacent threads have different materials.
  - Better when kernels are material-specific or input is sorted by material.

### `calculate_micro_xs`
- Accesses:
  - `index_grid`: scattered, especially for random energies.
  - `nuclide_grid`: scattered across nuclides and energy indices.
  - `unionized_energy_array`: binary-search pattern, divergent after early search levels.
- Coalescing:
  - Generally poor.
  - Optimization 6 improves locality but does not guarantee consecutive-thread-to-consecutive-address coalescing.

## 4. Shared memory usage

### Current shared memory usage
- No CUDA kernel explicitly uses shared memory.
- There are no `__shared__` allocations.
- There are no `extern __shared__` allocations.

### Potential shared-memory or constant-memory opportunities
- Small read-only data:
  - `num_nucs[12]`
  - material nuclide lists in `mats`
  - concentration values in `concs`
  - material probability distribution in `pick_mat`
- These are repeatedly accessed and small enough to consider:
  - Constant memory for broadcast-style access.
  - Shared memory per block for material-specific kernels.
- For material-specific kernels, loading the current material’s `mats` and `concs` into shared memory could reduce repeated global loads.
- Maximum material size is up to 321 nuclides for fuel in the large case:
  - `mats`: about 321 integers.

- For all materials combined:
  - `mats` and `concs` are also modest in size, though storing all concentrations as `double` consumes more shared memory.
- The large cross-section grids and index grids are not good shared-memory candidates because accesses are random and the structures are too large.
- Optimization 6’s energy-sorted access pattern could enable small tiled or cache-oriented staging for nearby energy regions, but this would require a more invasive redesign.

### Energy-efficiency opportunity
- Replacing per-thread local `dist[12]` initialization in `pick_mat` with constant memory or precomputed thresholds would reduce register/local memory pressure and repeated instruction overhead.

## 5. Warp divergence

### Kernel-level divergence

#### `xs_lookup_kernel_baseline`
- `if (i >= in.lookups) return;`
  - Divergence only in the final partial block.
- `pick_mat`
  - Divergent because different threads generate different random rolls and return at different loop iterations.
- `calculate_macro_xs`
  - Divergent loop bound: `j < num_nucs[mat]`.
  - Materials have very different nuclide counts.
  - Fuel material has far more work than most other materials.
- `calculate_micro_xs`
  - Divergence from grid-type branches is likely uniform across the grid because `in.grid_type` is the same for all threads.
  - Divergence from edge cases and binary-search comparisons is significant.

#### `sampling_kernel`
- `if (i >= in.lookups) return;`
- `pick_mat` divergent return behavior.
- `fast_forward_LCG`
  - `while (n > 0)` has different iteration counts for different lookup indices.
  - `if (n & 1)` diverges according to the bits of `n`.

#### `xs_lookup_kernel_optimization_1`
- `if (i >= in.lookups) return;`
- Divergence in `calculate_macro_xs` remains because materials are unsorted and mixed.
- Divergence in binary searches remains.

#### `xs_lookup_kernel_optimization_2`
- `if (i >= in.lookups) return;`
- `if (mat != m) return;`
  - Major divergence and lane underutilization because material samples are not sorted.
- Within active lanes, material is uniform, so `num_nucs[mat]` loop divergence is reduced.
- Binary-search divergence remains.

#### `xs_lookup_kernel_optimization_3`
- `if (i >= in.lookups) return;`
- Branch:
  - `if (((is_fuel == 1) && (mat == 0)) || ((is_fuel == 0) && (mat != 0)))`
- Fuel kernel has uniform heavy work for active lanes.
- Non-fuel kernel still mixes materials with different nuclide counts.
- Active lanes may be sparse because input is not partitioned.

#### `xs_lookup_kernel_optimization_4`
- `if (i >= n_lookups) return;`
- `if (mat != m) return;`
  - Should rarely trigger after correct sorting and offset calculation.
  - Mostly a safety check.
- Material-specific launch greatly reduces loop-bound divergence.
- Binary-search divergence remains unless energy sorting is also used.

#### `xs_lookup_kernel_optimization_5`
- `if (i >= n_lookups) return;`
- No material-filter return branch.
- Fuel partition is uniform.
- Non-fuel partition still has material-count divergence.

#### Optimization 6 lookup path
- Same kernel as Optimization 4.
- Material divergence is strongly reduced.
- Energy sorting reduces binary-search path divergence and improves cache locality.

### Device-function divergence

#### `calculate_macro_xs`
- Branches:
  - `if (grid_type == UNIONIZED)`
  - `else if (grid_type == HASH)`
- These are likely uniform across all threads.
- Loop:
  - `for (int j = 0; j < num_nucs[mat]; j++)`
  - Major divergence when materials differ within a warp.
- Inner loop:
  - `for (int k = 0; k < 5; k++)`
  - Fixed bound; no loop-count divergence.

#### `calculate_micro_xs`
- Branches:
  - `if (grid_type == NUCLIDE)`
  - `else if (grid_type == UNIONIZED)`
  - `else`
  - Usually uniform across the kernel.
- Edge-case branches:
  - `if (idx == n_gridpoints - 1)`
  - `if (index_data[...] == n_gridpoints - 1)`
  - `if (idx == hash_bins - 1)`
  - `if (p_energy <= e_low)`
  - `else if (p_energy >= e_high)`
  - `if (lower == n_gridpoints - 1)`
- These can diverge across lanes.
- Binary searches:
  - `if (A[examinationPoint] > quarry)`
  - Highly divergent for random energies.

#### `grid_search`
- Loop:
  - `while (length > 1)`
  - For fixed `n`, the iteration count is mostly uniform.
- Branch:
  - `if (A[examinationPoint] > quarry)`
  - Divergent because `quarry` differs by thread.

#### `grid_search_nuclide`
- Loop:
  - `while (length > 1)`
  - Iteration count may vary when `low` and `high` differ, especially in hash mode.
- Branch:
  - `if (A[examinationPoint].energy > quarry)`
  - Divergent.

#### `pick_mat`
- Loop:
  - `for (int i = 0; i < 12; i++)`
- Nested loop:
  - `for (int j = i; j > 0; j--)`
- Branch:
  - `if (roll < running) return i;`
- Highly divergent because different lanes return at different iterations.

#### Verification max search
- In all lookup kernels:
  - `if (macro_xs_vector[j] > max)`
- Small fixed loop, but comparison outcome can diverge.

## 6. Data types and double-precision operations replaceable with float

### Current double-precision data
The following are stored or computed in `double`:

- `NuclideGridPoint`
  - `energy`
  - `total_xs`
  - `elastic_xs`
  - `absorbtion_xs`
  - `fission_xs`

  - `p_energy`

  - concentration `conc`
  - `du`
  - `e_low`, `e_high`
  - `dist[12]`
  - `roll`
- Random-number conversion in `LCG_random_double`.

### Candidates for `float`
If physics accuracy and verification requirements allow, the following are candidates for single precision:

- Cross-section fields in `NuclideGridPoint`.
- Energy fields in `NuclideGridPoint`.
- `unionized_energy_array`.
- `concs`.
- `p_energy_samples`.
- `macro_xs_vector` and `xs_vector`.
- Interpolation arithmetic in `calculate_micro_xs`.
- Material probability distribution in `pick_mat`.

### Energy and performance benefits of using `float`
- Halves memory footprint for major arrays.
- Reduces DRAM bandwidth and cache pressure.
- Improves effective cache capacity.
- Reduces register footprint for local arrays.
- May improve occupancy if register pressure is limiting.
- Reduces energy per arithmetic operation and per memory transaction.

### Caution
- Changing `double` to `float` will likely change the verification checksum.
- Any precision change should be treated as a numerical model decision, not a mechanical optimization.
- A mixed-precision approach may be preferable:
  - Store grids and concentrations in `float`.
  - Accumulate `macro_xs_vector` in `double` or compensated `float` if needed.
  - Keep random-number state as integer but return `float` energy samples if acceptable.

## 7. Synchronization overhead

### `__syncthreads()` count

## 9. Highest-impact energy-efficiency opportunities

### 1. Prefer material and energy grouping for large workloads
- Optimization 6 has the best lookup locality and least divergence.
- Use it when lookup count is large enough to amortize sorting overhead.
- For smaller workloads, Optimization 5 may offer a better energy/performance tradeoff.

### 2. Increase block size for sorted lookup kernels
- The 32-thread block size limits A100 occupancy to roughly 50% theoretical warp occupancy.
- For memory-latency-bound lookup kernels, 128 or 256 threads per block may improve latency hiding.
- This is especially attractive for Optimization 4 and Optimization 6, where sorted data already reduces divergence.

### 3. Reduce precision where acceptable
- Converting grid data, concentrations, sampled energies, and interpolation arithmetic from `double` to `float` could significantly reduce memory traffic and energy.
- Mixed precision should be considered if full single precision is not acceptable.

### 4. Use constant or shared memory for small read-only structures
- `num_nucs`, `mats`, `concs`, and material probability data are small and frequently reused.
- Constant memory is attractive for uniform material-specific kernels.
- Shared memory staging of per-material `mats` and `concs` could reduce repeated global loads.

### 5. Avoid full verification-array traffic
- Current design writes one global verification value per lookup and then performs a full reduction.
- A hierarchical reduction would reduce global memory traffic and eliminate the large verification array for many cases.

### 6. Replace repeated per-thread material distribution setup
- `pick_mat` initializes `dist[12]` per thread.
- Use precomputed equivalent thresholds in constant memory while preserving the exact intentional comparison behavior.

### 7. Consider hash grid for memory-footprint-sensitive runs
- The unionized grid can consume very large memory, especially because `index_grid` scales with `n_isotopes * n_gridpoints * n_isotopes`.
- Hash mode may reduce memory footprint and energy from DRAM traffic, though it introduces additional bounded searches.

### 8. Improve layout only if access grouping is also improved
- The current AoS `NuclideGridPoint` layout is reasonable when all fields are read for a point.
- However, with random warp access, coalescing remains poor regardless of AoS.
- Data-layout changes are most beneficial when combined with energy sorting or warp-cooperative lookup strategies.

	input.HM[5] = '\0';
	
	// Check if user sets these
	int user_g = 0;

	int default_lookups = 1;
	int default_particles = 1;
	
	// Collect Raw Input
	for( int i = 1; i < argc; i++ )
	{
		char * arg = argv[i];

		// n_gridpoints (-g)
		if( strcmp(arg, "-g") == 0 )
		{	
			if( ++i < argc )
			{
				user_g = 1;
				input.n_gridpoints = atol(argv[i]);
			}
			else
				print_CLI_error();
		}
		// Simulation Method (-m)
		else if( strcmp(arg, "-m") == 0 )
		{
			char * sim_type;
			if( ++i < argc )
				sim_type = argv[i];
			else
				print_CLI_error();

			if( strcmp(sim_type, "history") == 0 )
				input.simulation_method = HISTORY_BASED;
			else if( strcmp(sim_type, "event") == 0 )
			{
				input.simulation_method = EVENT_BASED;
				// Also resets default # of lookups
				if( default_lookups && default_particles )
				{
					input.lookups =  input.lookups * input.particles;
					input.particles = 0;
				}
			}
			else
				print_CLI_error();
		}
		// lookups (-l)
		else if( strcmp(arg, "-l") == 0 )
		{
			if( ++i < argc )
			{
				input.lookups = atoi(argv[i]);
				default_lookups = 0;
			}
			else
				print_CLI_error();
		}
		// hash bins (-h)
		else if( strcmp(arg, "-h") == 0 )
		{
			if( ++i < argc )
				input.hash_bins = atoi(argv[i]);
			else
				print_CLI_error();
		}
		// particles (-p)
		else if( strcmp(arg, "-p") == 0 )
		{
			if( ++i < argc )
			{
				input.particles = atoi(argv[i]);
				default_particles = 0;
			}
			else
				print_CLI_error();
		}
		// HM (-s)
		else if( strcmp(arg, "-s") == 0 )
		{	
			if( ++i < argc )
				input.HM = argv[i];
			else
				print_CLI_error();
		}
		// grid type (-G)
		else if( strcmp(arg, "-G") == 0 )
		{
			char * grid_type;
			if( ++i < argc )
				grid_type = argv[i];
			else
				print_CLI_error();

			if( strcmp(grid_type, "unionized") == 0 )
				input.grid_type = UNIONIZED;
			else if( strcmp(grid_type, "nuclide") == 0 )
				input.grid_type = NUCLIDE;
			else if( strcmp(grid_type, "hash") == 0 )
				input.grid_type = HASH;
			else
				print_CLI_error();
		}
		// binary mode (-b)
		else if( strcmp(arg, "-b") == 0 )
		{
			char * binary_mode;
			if( ++i < argc )
				binary_mode = argv[i];
			else
				print_CLI_error();

			if( strcmp(binary_mode, "read") == 0 )
				input.binary_mode = READ;
			else if( strcmp(binary_mode, "write") == 0 )
				input.binary_mode = WRITE;
			else
				print_CLI_error();
		}
		// kernel optimization selection (-k)
		else if( strcmp(arg, "-k") == 0 )
		{
			if( ++i < argc )
			{
				input.kernel_id = atoi(argv[i]);
			}
			else
				print_CLI_error();
		}
		else
			print_CLI_error();
	}

	// Validate Input
	
	// Validate nthreads
	if( input.nthreads < 1 )
		print_CLI_error();
	
	// Validate n_isotopes
	if( input.n_isotopes < 1 )
		print_CLI_error();
	
	// Validate n_gridpoints
	if( input.n_gridpoints < 1 )
		print_CLI_error();

	// Validate lookups
	if( input.lookups < 1 )
		print_CLI_error();

	// Validate Hash Bins 
	if( input.hash_bins < 1 )
		print_CLI_error();
	
	// Validate HM size
	if( strcasecmp(input.HM, "small") != 0 &&
		strcasecmp(input.HM, "large") != 0 &&
		strcasecmp(input.HM, "XL") != 0 &&
		strcasecmp(input.HM, "XXL") != 0 )
		print_CLI_error();
	
	// Set HM size specific parameters
	// (defaults to large)
	if( strcasecmp(input.HM, "small") == 0 )
		input.n_isotopes = 68;
	else if( strcasecmp(input.HM, "XL") == 0 && user_g == 0 )
		input.n_gridpoints = 238847; // sized to make 120 GB XS data
	else if( strcasecmp(input.HM, "XXL") == 0 && user_g == 0 )
		input.n_gridpoints = 238847 * 2.1; // 252 GB XS data

	// Return input struct
	return input;
}

void binary_write( Inputs in, SimulationData SD )
{
	const char * fname = "XS_data.dat";
	printf("Writing all data structures to binary file %s...\n", fname);
	FILE * fp = fopen(fname, "w");

	// Write SimulationData Object. Include pointers, even though we won't be using them.
	fwrite(&SD, sizeof(SimulationData), 1, fp);

	// Write heap arrays in SimulationData Object
	fwrite(SD.num_nucs,       sizeof(int), SD.length_num_nucs, fp);
	fwrite(SD.concs,          sizeof(double), SD.length_concs, fp);
	fwrite(SD.mats,           sizeof(int), SD.length_mats, fp);
	fwrite(SD.nuclide_grid,   sizeof(NuclideGridPoint), SD.length_nuclide_grid, fp); 
	fwrite(SD.index_grid, sizeof(int), SD.length_index_grid, fp);
	fwrite(SD.unionized_energy_array, sizeof(double), SD.length_unionized_energy_array, fp);

	fclose(fp);
}

SimulationData binary_read( Inputs in )
{
	SimulationData SD;
	
	const char * fname = "XS_data.dat";
	printf("Reading all data structures from binary file %s...\n", fname);

	FILE * fp = fopen(fname, "r");
	assert(fp != NULL);

	// Read SimulationData Object. Include pointers, even though we won't be using them.
	fread(&SD, sizeof(SimulationData), 1, fp);

	// Allocate space for arrays on heap
	SD.num_nucs = (int *) malloc(SD.length_num_nucs * sizeof(int));
	SD.concs = (double *) malloc(SD.length_concs * sizeof(double));
	SD.mats = (int *) malloc(SD.length_mats * sizeof(int));
	SD.nuclide_grid = (NuclideGridPoint *) malloc(SD.length_nuclide_grid * sizeof(NuclideGridPoint));
	SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int));
	SD.unionized_energy_array = (double *) malloc( SD.length_unionized_energy_array * sizeof(double));

	// Read heap arrays into SimulationData Object
	fread(SD.num_nucs,       sizeof(int), SD.length_num_nucs, fp);
	fread(SD.concs,          sizeof(double), SD.length_concs, fp);
	fread(SD.mats,           sizeof(int), SD.length_mats, fp);
	fread(SD.nuclide_grid,   sizeof(NuclideGridPoint), SD.length_nuclide_grid, fp); 
	fread(SD.index_grid, sizeof(int), SD.length_index_grid, fp);
	fread(SD.unionized_energy_array, sizeof(double), SD.length_unionized_energy_array, fp);

	fclose(fp);

	return SD;
}

// Moves all required data structures to the GPU's memory space
SimulationData move_simulation_data_to_device( Inputs in, int mype, SimulationData SD )
{
	if(mype == 0) printf("Allocating and moving simulation data to GPU memory space...\n");

	////////////////////////////////////////////////////////////////////////////////
	// SUMMARY: Simulation Data Structure Manifest for "SD" Object
	// Here we list all heap arrays (and lengths) in SD that would need to be
	// offloaded manually if using an accelerator with a seperate memory space
	////////////////////////////////////////////////////////////////////////////////
	// int * num_nucs;                     // Length = length_num_nucs;
	// double * concs;                     // Length = length_concs
	// int * mats;                         // Length = length_mats
	// double * unionized_energy_array;    // Length = length_unionized_energy_array
	// int * index_grid;                   // Length = length_index_grid
	// NuclideGridPoint * nuclide_grid;    // Length = length_nuclide_grid
	// 
	// Note: "unionized_energy_array" and "index_grid" can be of zero length
	//        depending on lookup method.
	//
	// Note: "Lengths" are given as the number of objects in the array, not the
	//       number of bytes.
	////////////////////////////////////////////////////////////////////////////////
	size_t sz;
	size_t total_sz = 0;

	// Shallow copy of CPU simulation data to GPU simulation data
	SimulationData GSD = SD;

	// Move data to GPU memory space
	sz = GSD.length_num_nucs * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.num_nucs, sz) );
	gpuErrchk( cudaMemcpy(GSD.num_nucs, SD.num_nucs, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_concs * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.concs, sz) );
	gpuErrchk( cudaMemcpy(GSD.concs, SD.concs, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_mats * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mats, sz) );
	gpuErrchk( cudaMemcpy(GSD.mats, SD.mats, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;
	
	sz = GSD.length_unionized_energy_array * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.unionized_energy_array, sz) );
	gpuErrchk( cudaMemcpy(GSD.unionized_energy_array, SD.unionized_energy_array, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_index_grid * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.index_grid, sz) );
	gpuErrchk( cudaMemcpy(GSD.index_grid, SD.index_grid, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;

	sz = GSD.length_nuclide_grid * sizeof(NuclideGridPoint);
	gpuErrchk( cudaMalloc((void **) &GSD.nuclide_grid, sz) );
	gpuErrchk( cudaMemcpy(GSD.nuclide_grid, SD.nuclide_grid, sz, cudaMemcpyHostToDevice) );
	total_sz += sz;
	
	// Allocate verification array on device. This structure is not needed on CPU, so we don't
	// have to copy anything over.
	sz = in.lookups * sizeof(unsigned long);
	gpuErrchk( cudaMalloc((void **) &GSD.verification, sz) );
	total_sz += sz;
	GSD.length_verification = in.lookups;
	
	// Synchronize
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	if(mype == 0 ) printf("GPU Intialization complete. Allocated %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0 );

	return GSD;

}

// Release device memory
void release_device_memory(SimulationData GSD) {
	cudaFree(GSD.num_nucs);
	cudaFree(GSD.concs);
	cudaFree(GSD.mats);
	cudaFree(GSD.unionized_energy_array);
	cudaFree(GSD.nuclide_grid);
	cudaFree(GSD.verification);
}

SimulationData grid_init_do_not_profile( Inputs in, int mype )
{
	// Structure to hold all allocated simuluation data arrays
	SimulationData SD;

	// Keep track of how much data we're allocating
	size_t nbytes = 0;
	
	// Set the initial seed value
	uint64_t seed = 42;	

	////////////////////////////////////////////////////////////////////
	// Initialize Nuclide Grids
	////////////////////////////////////////////////////////////////////
	
	if(mype == 0) printf("Intializing nuclide grids...\n");

	// First, we need to initialize our nuclide grid. This comes in the form
	// of a flattened 2D array that hold all the information we need to define
	// the cross sections for all isotopes in the simulation. 
	// The grid is composed of "NuclideGridPoint" structures, which hold the
	// energy level of the grid point and all associated XS data at that level.
	// An array of structures (AOS) is used instead of
	// a structure of arrays, as the grid points themselves are accessed in 
	// a random order, but all cross section interaction channels and the
	// energy level are read whenever the gridpoint is accessed, meaning the
	// AOS is more cache efficient.
	
	// Initialize Nuclide Grid
	SD.length_nuclide_grid = in.n_isotopes * in.n_gridpoints;
	SD.nuclide_grid     = (NuclideGridPoint *) malloc( SD.length_nuclide_grid * sizeof(NuclideGridPoint));
	assert(SD.nuclide_grid != NULL);
	nbytes += SD.length_nuclide_grid * sizeof(NuclideGridPoint);
	for( int i = 0; i < SD.length_nuclide_grid; i++ )
	{
		SD.nuclide_grid[i].energy        = LCG_random_double(&seed);
		SD.nuclide_grid[i].total_xs      = LCG_random_double(&seed);
		SD.nuclide_grid[i].elastic_xs    = LCG_random_double(&seed);
		SD.nuclide_grid[i].absorbtion_xs = LCG_random_double(&seed);
		SD.nuclide_grid[i].fission_xs    = LCG_random_double(&seed);
		SD.nuclide_grid[i].nu_fission_xs = LCG_random_double(&seed);
	}

	// Sort so that each nuclide has data stored in ascending energy order.
	for( int i = 0; i < in.n_isotopes; i++ )
		qsort( &SD.nuclide_grid[i*in.n_gridpoints], in.n_gridpoints, sizeof(NuclideGridPoint), NGP_compare);
	
	// error debug check
	/*
	for( int i = 0; i < in.n_isotopes; i++ )
	{
		printf("NUCLIDE %d ==============================\n", i);
		for( int j = 0; j < in.n_gridpoints; j++ )
			printf("E%d = %lf\n", j, SD.nuclide_grid[i * in.n_gridpoints + j].energy);
	}
	*/
	

	////////////////////////////////////////////////////////////////////
	// Initialize Acceleration Structure
	////////////////////////////////////////////////////////////////////
	
	if( in.grid_type == NUCLIDE )
	{
		SD.length_unionized_energy_array = 0;
		SD.length_index_grid = 0;
	}
	
	if( in.grid_type == UNIONIZED )
	{
		if(mype == 0) printf("Intializing unionized grid...\n");

		// Allocate space to hold the union of all nuclide energy data
		SD.length_unionized_energy_array = in.n_isotopes * in.n_gridpoints;
		SD.unionized_energy_array = (double *) malloc( SD.length_unionized_energy_array * sizeof(double));
		assert(SD.unionized_energy_array != NULL );
		nbytes += SD.length_unionized_energy_array * sizeof(double);

		// Copy energy data over from the nuclide energy grid
		for( int i = 0; i < SD.length_unionized_energy_array; i++ )
			SD.unionized_energy_array[i] = SD.nuclide_grid[i].energy;

		// Sort unionized energy array
		qsort( SD.unionized_energy_array, SD.length_unionized_energy_array, sizeof(double), double_compare);

		// Allocate space to hold the acceleration grid indices
		SD.length_index_grid = SD.length_unionized_energy_array * in.n_isotopes;
		SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int));
		assert(SD.index_grid != NULL);
		nbytes += SD.length_index_grid * sizeof(int);

		// Generates the double indexing grid
		int * idx_low = (int *) calloc( in.n_isotopes, sizeof(int));
		assert(idx_low != NULL );
		double * energy_high = (double *) malloc( in.n_isotopes * sizeof(double));
		assert(energy_high != NULL );

		for( int i = 0; i < in.n_isotopes; i++ )
			energy_high[i] = SD.nuclide_grid[i * in.n_gridpoints + 1].energy;

		for( long e = 0; e < SD.length_unionized_energy_array; e++ )
		{
			double unionized_energy = SD.unionized_energy_array[e];
			for( long i = 0; i < in.n_isotopes; i++ )
			{
				if( unionized_energy < energy_high[i]  )
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
				else if( idx_low[i] == in.n_gridpoints - 2 )
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
				else
				{
					idx_low[i]++;
					SD.index_grid[e * in.n_isotopes + i] = idx_low[i];
					energy_high[i] = SD.nuclide_grid[i * in.n_gridpoints + idx_low[i] + 1].energy;	
				}
			}
		}

		free(idx_low);
		free(energy_high);
	}

	if( in.grid_type == HASH )
	{
		if(mype == 0) printf("Intializing hash grid...\n");
		SD.length_unionized_energy_array = 0;
		SD.length_index_grid  = in.hash_bins * in.n_isotopes;
		SD.index_grid = (int *) malloc( SD.length_index_grid * sizeof(int)); 
		assert(SD.index_grid != NULL);
		nbytes += SD.length_index_grid * sizeof(int);

		double du = 1.0 / in.hash_bins;

		// For each energy level in the hash table
		for( long e = 0; e < in.hash_bins; e++ )
		{
			double energy = e * du;

			// We need to determine the bounding energy levels for all isotopes
			for( long i = 0; i < in.n_isotopes; i++ )
			{
				SD.index_grid[e * in.n_isotopes + i] = grid_search_nuclide( in.n_gridpoints, energy, SD.nuclide_grid + i * in.n_gridpoints, 0, in.n_gridpoints-1);
			}
		}
	}

	////////////////////////////////////////////////////////////////////
	// Initialize Materials and Concentrations
	////////////////////////////////////////////////////////////////////
	if(mype == 0) printf("Intializing material data...\n");
	
	// Set the number of nuclides in each material
	SD.num_nucs  = load_num_nucs(in.n_isotopes);
	SD.length_num_nucs = 12; // There are always 12 materials in XSBench

	// Intialize the flattened 2D grid of material data. The grid holds
	// a list of nuclide indices for each of the 12 material types. The
	// grid is allocated as a full square grid, even though not all
	// materials have the same number of nuclides.
	SD.mats = load_mats(SD.num_nucs, in.n_isotopes, &SD.max_num_nucs);
	SD.length_mats = SD.length_num_nucs * SD.max_num_nucs;

	// Intialize the flattened 2D grid of nuclide concentration data. The grid holds
	// a list of nuclide concentrations for each of the 12 material types. The
	// grid is allocated as a full square grid, even though not all
	// materials have the same number of nuclides.
	SD.concs = load_concs(SD.num_nucs, SD.max_num_nucs);
	SD.length_concs = SD.length_mats;

	if(mype == 0) printf("Intialization complete. Allocated %.0lf MB of data on CPU.\n", nbytes/1024.0/1024.0 );

	return SD;
}

// Material data is hard coded into the functions in this file.
// Note that there are 12 materials present in H-M (large or small)

// num_nucs represents the number of nuclides that each material contains
int * load_num_nucs(long n_isotopes)
{
	int * num_nucs = (int*)malloc(12*sizeof(int));
	
	// Material 0 is a special case (fuel). The H-M small reactor uses
	// 34 nuclides, while H-M larges uses 300.
	if( n_isotopes == 68 )
		num_nucs[0]  = 34; // HM Small is 34, H-M Large is 321
	else
		num_nucs[0]  = 321; // HM Small is 34, H-M Large is 321

	num_nucs[1]  = 5;
	num_nucs[2]  = 4;
	num_nucs[3]  = 4;
	num_nucs[4]  = 27;
	num_nucs[5]  = 21;
	num_nucs[6]  = 21;
	num_nucs[7]  = 21;
	num_nucs[8]  = 21;
	num_nucs[9]  = 21;
	num_nucs[10] = 9;
	num_nucs[11] = 9;

	return num_nucs;
}

// Assigns an array of nuclide ID's to each material
int * load_mats( int * num_nucs, long n_isotopes, int * max_num_nucs )
{
	*max_num_nucs = 0;
	int num_mats = 12;
	for( int m = 0; m < num_mats; m++ )
	{
		if( num_nucs[m] > *max_num_nucs )
			*max_num_nucs = num_nucs[m];
	}
	int * mats = (int *) malloc( num_mats * (*max_num_nucs) * sizeof(int) );

	// Small H-M has 34 fuel nuclides
	int mats0_Sml[] =  { 58, 59, 60, 61, 40, 42, 43, 44, 45, 46, 1, 2, 3, 7,
	                 8, 9, 10, 29, 57, 47, 48, 0, 62, 15, 33, 34, 52, 53, 
	                 54, 55, 56, 18, 23, 41 }; //fuel
	// Large H-M has 300 fuel nuclides
	int mats0_Lrg[321] =  { 58, 59, 60, 61, 40, 42, 43, 44, 45, 46, 1, 2, 3, 7,
	                 8, 9, 10, 29, 57, 47, 48, 0, 62, 15, 33, 34, 52, 53,
	                 54, 55, 56, 18, 23, 41 }; //fuel
	for( int i = 0; i < 321-34; i++ )
		mats0_Lrg[34+i] = 68 + i; // H-M large adds nuclides to fuel only
	
	// These are the non-fuel materials	
	int mats1[] =  { 63, 64, 65, 66, 67 }; // cladding
	int mats2[] =  { 24, 41, 4, 5 }; // cold borated water
	int mats3[] =  { 24, 41, 4, 5 }; // hot borated water
	int mats4[] =  { 19, 20, 21, 22, 35, 36, 37, 38, 39, 25, 27, 28, 29,
	                 30, 31, 32, 26, 49, 50, 51, 11, 12, 13, 14, 6, 16,
	                 17 }; // RPV
	int mats5[] =  { 24, 41, 4, 5, 19, 20, 21, 22, 35, 36, 37, 38, 39, 25,
	                 49, 50, 51, 11, 12, 13, 14 }; // lower radial reflector
	int mats6[] =  { 24, 41, 4, 5, 19, 20, 21, 22, 35, 36, 37, 38, 39, 25,
	                 49, 50, 51, 11, 12, 13, 14 }; // top reflector / plate
	int mats7[] =  { 24, 41, 4, 5, 19, 20, 21, 22, 35, 36, 37, 38, 39, 25,
	                 49, 50, 51, 11, 12, 13, 14 }; // bottom plate
	int mats8[] =  { 24, 41, 4, 5, 19, 20, 21, 22, 35, 36, 37, 38, 39, 25,
	                 49, 50, 51, 11, 12, 13, 14 }; // bottom nozzle
	int mats9[] =  { 24, 41, 4, 5, 19, 20, 21, 22, 35, 36, 37, 38, 39, 25,
	                 49, 50, 51, 11, 12, 13, 14 }; // top nozzle
	int mats10[] = { 24, 41, 4, 5, 63, 64, 65, 66, 67 }; // top of FA's
	int mats11[] = { 24, 41, 4, 5, 63, 64, 65, 66, 67 }; // bottom FA's
	
	// H-M large v small dependency
	if( n_isotopes == 68 )
		memcpy( mats,  mats0_Sml,  num_nucs[0]  * sizeof(int) );	
	else
		memcpy( mats,  mats0_Lrg,  num_nucs[0]  * sizeof(int) );
	
	// Copy other materials
	memcpy( mats + *max_num_nucs * 1,  mats1,  num_nucs[1]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 2,  mats2,  num_nucs[2]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 3,  mats3,  num_nucs[3]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 4,  mats4,  num_nucs[4]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 5,  mats5,  num_nucs[5]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 6,  mats6,  num_nucs[6]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 7,  mats7,  num_nucs[7]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 8,  mats8,  num_nucs[8]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 9,  mats9,  num_nucs[9]  * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 10, mats10, num_nucs[10] * sizeof(int) );	
	memcpy( mats + *max_num_nucs * 11, mats11, num_nucs[11] * sizeof(int) );	

	return mats;
}

// Randomizes the concentrations of all nuclides in a variety of materials
double * load_concs( int * num_nucs, int max_num_nucs )

unsigned long long run_event_based_simulation_baseline(Inputs in, SimulationData GSD, int mype)
{
	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Running baseline event-based simulation...\n");

	int nthreads = 256;
	int nblocks = ceil( (double) in.lookups / (double) nthreads);

	xs_lookup_kernel_baseline<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

// In this kernel, we perform a single lookup with each thread. Threads within a warp
// do not really have any relation to each other, and divergence due to high nuclide count fuel
// material lookups are costly. This kernel constitutes baseline performance.
__global__ void xs_lookup_kernel_baseline(Inputs in, SimulationData GSD )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;

	// Set the initial seed value
	uint64_t seed = STARTING_SEED;	

	// Forward seed to lookup index (we need 2 samples per lookup)
	seed = fast_forward_LCG(seed, 2*i);

	// Randomly pick an energy and material for the particle
	double p_energy = LCG_random_double(&seed);
	int mat         = pick_mat(&seed); 
		
	double macro_xs_vector[5] = {0};
		
	// Perform macroscopic Cross Section Lookup
	calculate_macro_xs(
			p_energy,        // Sampled neutron energy (in lethargy)
			mat,             // Sampled material type index neutron is in
			in.n_isotopes,   // Total number of isotopes in simulation
			in.n_gridpoints, // Number of gridpoints per isotope in simulation
			GSD.num_nucs,     // 1-D array with number of nuclides per material
			GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
			GSD.unionized_energy_array, // 1-D Unionized energy array
			GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
			GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
			GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)
			GSD.max_num_nucs  // Maximum number of nuclides present in any material
			);

	// For verification, and to prevent the compiler from optimizing
	// all work out, we interrogate the returned macro_xs_vector array
	// to find its maximum value index, then increment the verification
	// value by that index. In this implementation, we have each thread
	// write to its thread_id index in an array, which we will reduce
	// with a thrust reduction kernel after the main simulation kernel.
	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}

// Calculates the microscopic cross section for a given nuclide & energy
__device__ void calculate_micro_xs(   double p_energy, int nuc, long n_isotopes,
                           long n_gridpoints,
                           double * __restrict__ egrid, int * __restrict__ index_data,
                           NuclideGridPoint * __restrict__ nuclide_grids,
                           long idx, double * __restrict__ xs_vector, int grid_type, int hash_bins ){
	// Variables
	double f;
	NuclideGridPoint * low, * high;

	// If using only the nuclide grid, we must perform a binary search
	// to find the energy location in this particular nuclide's grid.
	if( grid_type == NUCLIDE )
	{
		// Perform binary search on the Nuclide Grid to find the index
		idx = grid_search_nuclide( n_gridpoints, p_energy, &nuclide_grids[nuc*n_gridpoints], 0, n_gridpoints-1);

		// pull ptr from nuclide grid and check to ensure that
		// we're not reading off the end of the nuclide's grid
		if( idx == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + idx - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + idx];
	}
	else if( grid_type == UNIONIZED) // Unionized Energy Grid - we already know the index, no binary search needed.
	{
		// pull ptr from energy grid and check to ensure that
		// we're not reading off the end of the nuclide's grid
		if( index_data[idx * n_isotopes + nuc] == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + index_data[idx * n_isotopes + nuc] - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + index_data[idx * n_isotopes + nuc]];
	}
	else // Hash grid
	{
		// load lower bounding index
		int u_low = index_data[idx * n_isotopes + nuc];

		// Determine higher bounding index
		int u_high;
		if( idx == hash_bins - 1 )
			u_high = n_gridpoints - 1;
		else
			u_high = index_data[(idx+1)*n_isotopes + nuc] + 1;

		// Check edge cases to make sure energy is actually between these
		// Then, if things look good, search for gridpoint in the nuclide grid
		// within the lower and higher limits we've calculated.
		double e_low  = nuclide_grids[nuc*n_gridpoints + u_low].energy;
		double e_high = nuclide_grids[nuc*n_gridpoints + u_high].energy;
		int lower;
		if( p_energy <= e_low )
			lower = 0;
		else if( p_energy >= e_high )
			lower = n_gridpoints - 1;
		else
			lower = grid_search_nuclide( n_gridpoints, p_energy, &nuclide_grids[nuc*n_gridpoints], u_low, u_high);

		if( lower == n_gridpoints - 1 )
			low = &nuclide_grids[nuc*n_gridpoints + lower - 1];
		else
			low = &nuclide_grids[nuc*n_gridpoints + lower];
	}
	
	high = low + 1;
	
	// calculate the re-useable interpolation factor
	f = (high->energy - p_energy) / (high->energy - low->energy);

	// Total XS
	xs_vector[0] = high->total_xs - f * (high->total_xs - low->total_xs);
	
	// Elastic XS
	xs_vector[1] = high->elastic_xs - f * (high->elastic_xs - low->elastic_xs);
	
	// Absorbtion XS
	xs_vector[2] = high->absorbtion_xs - f * (high->absorbtion_xs - low->absorbtion_xs);
	
	// Fission XS
	xs_vector[3] = high->fission_xs - f * (high->fission_xs - low->fission_xs);
	
	// Nu Fission XS
	xs_vector[4] = high->nu_fission_xs - f * (high->nu_fission_xs - low->nu_fission_xs);
}

// Calculates macroscopic cross section based on a given material & energy 
__device__ void calculate_macro_xs( double p_energy, int mat, long n_isotopes,
                         long n_gridpoints, int * __restrict__ num_nucs,
                         double * __restrict__ concs,
                         double * __restrict__ egrid, int * __restrict__ index_data,
                         NuclideGridPoint * __restrict__ nuclide_grids,
                         int * __restrict__ mats,
                         double * __restrict__ macro_xs_vector, int grid_type, int hash_bins, int max_num_nucs ){
	int p_nuc; // the nuclide we are looking up
	long idx = -1;	
	double conc; // the concentration of the nuclide in the material

	// cleans out macro_xs_vector
	for( int k = 0; k < 5; k++ )
		macro_xs_vector[k] = 0;

	// If we are using the unionized energy grid (UEG), we only
	// need to perform 1 binary search per macroscopic lookup.
	// If we are using the nuclide grid search, it will have to be
	// done inside of the "calculate_micro_xs" function for each different
	// nuclide in the material.
	if( grid_type == UNIONIZED )
		idx = grid_search( n_isotopes * n_gridpoints, p_energy, egrid);	
	else if( grid_type == HASH )
	{
		double du = 1.0 / hash_bins;
		idx = p_energy / du;
	}
	
	// Once we find the pointer array on the UEG, we can pull the data
	// from the respective nuclide grids, as well as the nuclide
	// concentration data for the material
	// Each nuclide from the material needs to have its micro-XS array
	// looked up & interpolatied (via calculate_micro_xs). Then, the
	// micro XS is multiplied by the concentration of that nuclide
	// in the material, and added to the total macro XS array.
	// (Independent -- though if parallelizing, must use atomic operations
	//  or otherwise control access to the xs_vector and macro_xs_vector to
	//  avoid simulataneous writing to the same data structure)
	for( int j = 0; j < num_nucs[mat]; j++ )
	{
		double xs_vector[5];
		p_nuc = mats[mat*max_num_nucs + j];
		conc = concs[mat*max_num_nucs + j];
		calculate_micro_xs( p_energy, p_nuc, n_isotopes,
		                    n_gridpoints, egrid, index_data,
		                    nuclide_grids, idx, xs_vector, grid_type, hash_bins );
		for( int k = 0; k < 5; k++ )
			macro_xs_vector[k] += xs_vector[k] * conc;
	}
}


// binary search for energy on unionized energy grid
// returns lower index
__device__ long grid_search( long n, double quarry, double * __restrict__ A)
{
	long lowerLimit = 0;
	long upperLimit = n-1;
	long examinationPoint;
	long length = upperLimit - lowerLimit;

	while( length > 1 )
	{
		examinationPoint = lowerLimit + ( length / 2 );
		
		if( A[examinationPoint] > quarry )
			upperLimit = examinationPoint;
		else
			lowerLimit = examinationPoint;
		
		length = upperLimit - lowerLimit;
	}
	
	return lowerLimit;
}

// binary search for energy on nuclide energy grid
__host__ __device__ long grid_search_nuclide( long n, double quarry, NuclideGridPoint * A, long low, long high)
{
	long lowerLimit = low;
	long upperLimit = high;
	long examinationPoint;
	long length = upperLimit - lowerLimit;

	while( length > 1 )
	{
		examinationPoint = lowerLimit + ( length / 2 );
		
		if( A[examinationPoint].energy > quarry )
			upperLimit = examinationPoint;
		else
			lowerLimit = examinationPoint;
		
		length = upperLimit - lowerLimit;
	}
	
	return lowerLimit;
}

// picks a material based on a probabilistic distribution
__device__ int pick_mat( uint64_t * seed )
{
	// I have a nice spreadsheet supporting these numbers. They are
	// the fractions (by volume) of material in the core. Not a 
	// *perfect* approximation of where XS lookups are going to occur,
	// but this will do a good job of biasing the system nonetheless.

	// Also could be argued that doing fractions by weight would be 
	// a better approximation, but volume does a good enough job for now.

	double dist[12];
	dist[0]  = 0.140;	// fuel
	dist[1]  = 0.052;	// cladding
	dist[2]  = 0.275;	// cold, borated water
	dist[3]  = 0.134;	// hot, borated water
	dist[4]  = 0.154;	// RPV
	dist[5]  = 0.064;	// Lower, radial reflector
	dist[6]  = 0.066;	// Upper reflector / top plate
	dist[7]  = 0.055;	// bottom plate
	dist[8]  = 0.008;	// bottom nozzle
	dist[9]  = 0.015;	// top nozzle
	dist[10] = 0.025;	// top of fuel assemblies
	dist[11] = 0.013;	// bottom of fuel assemblies
	
	double roll = LCG_random_double(seed);

	// makes a pick based on the distro
	for( int i = 0; i < 12; i++ )
	{
		double running = 0;
		for( int j = i; j > 0; j-- )
			running += dist[j];
		if( roll < running )
			return i;
	}

	return 0;
}

__host__ __device__ double LCG_random_double(uint64_t * seed)
{
	// LCG parameters
	const uint64_t m = 9223372036854775808ULL; // 2^63
	const uint64_t a = 2806196910506780709ULL;
	const uint64_t c = 1ULL;
	*seed = (a * (*seed) + c) % m;
	return (double) (*seed) / (double) m;
}	

__device__ uint64_t fast_forward_LCG(uint64_t seed, uint64_t n)
{
	// LCG parameters
	const uint64_t m = 9223372036854775808ULL; // 2^63
	uint64_t a = 2806196910506780709ULL;
	uint64_t c = 1ULL;

	n = n % m;

	uint64_t a_new = 1;
	uint64_t c_new = 0;

	while(n > 0) 
	{
		if(n & 1)
		{
			a_new *= a;
			c_new = c_new * a + c;
		}
		c *= (a + 1);
		a *= a;

		n >>= 1;
	}

	return (a_new * seed + c_new) % m;
}

__global__ void sampling_kernel(Inputs in, SimulationData GSD )
{
	// The lookup ID.
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;

	// Set the initial seed value
	uint64_t seed = STARTING_SEED;	

	// Forward seed to lookup index (we need 2 samples per lookup)
	seed = fast_forward_LCG(seed, 2*i);

	// Randomly pick an energy and material for the particle
	double p_energy = LCG_random_double(&seed);
	int mat         = pick_mat(&seed); 

	// Store sample data in state array
	GSD.p_energy_samples[i] = p_energy;
	GSD.mat_samples[i] = mat;
}

			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)

__global__ void xs_lookup_kernel_optimization_2(Inputs in, SimulationData GSD, int m )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;
	
	// Check that our material type matches the kernel material
	int mat = GSD.mat_samples[i];
	if( mat != m )
		return;

	double macro_xs_vector[5] = {0};
		
	// Perform macroscopic Cross Section Lookup
	calculate_macro_xs(
			GSD.p_energy_samples[i],        // Sampled neutron energy (in lethargy)
			mat,             // Sampled material type index neutron is in
			in.n_isotopes,   // Total number of isotopes in simulation
			in.n_gridpoints, // Number of gridpoints per isotope in simulation
			GSD.num_nucs,     // 1-D array with number of nuclides per material
			GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
			GSD.unionized_energy_array, // 1-D Unionized energy array
			GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
			GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
			GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)
			GSD.max_num_nucs  // Maximum number of nuclides present in any material
			);

	// For verification, and to prevent the compiler from optimizing
	// all work out, we interrogate the returned macro_xs_vector array
	// to find its maximum value index, then increment the verification
	// value by that index. In this implementation, we have each thread
	// write to its thread_id index in an array, which we will reduce
	// with a thrust reduction kernel after the main simulation kernel.
	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}


////////////////////////////////////////////////////////////////////////////////////
// Optimization 3 -- Kernel Splitting + Fuel or Not-Fuel Lookups
////////////////////////////////////////////////////////////////////////////////////
// This optimization alters Optimization 2. Instead of executing a kernel call for
// ALL different material types, only two different calls are made. One for fuel,
// and one for all the other materials. As the fuel material has by far the most
// isotopes, it takes much longer than the rest.
////////////////////////////////////////////////////////////////////////////////////
unsigned long long run_event_based_simulation_optimization_3(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 3 - Fuel or Other Lookup Kernels";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Launch all material kernels individually
	xs_lookup_kernel_optimization_3<<<nblocks, nthreads>>>( in, GSD, 0 );
	xs_lookup_kernel_optimization_3<<<nblocks, nthreads>>>( in, GSD, 1 );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

__global__ void xs_lookup_kernel_optimization_3(Inputs in, SimulationData GSD, int is_fuel )
{
	// The lookup ID. Used to set the seed, and to store the verification value
	const int i = blockIdx.x *blockDim.x + threadIdx.x;

	if( i >= in.lookups )
		return;
	
	int mat = GSD.mat_samples[i];

	// If this is the fuel kernel, AND this is a fuel lookup, then perform a lookup
	// OR if this is not the fuel kernel, AND this is not a fuel lookup, then perform the lookup
	if( ((is_fuel == 1) && (mat == 0)) || ((is_fuel == 0) && (mat != 0 ) ))
	{
		double macro_xs_vector[5] = {0};
			
		// Perform macroscopic Cross Section Lookup
		calculate_macro_xs(
				GSD.p_energy_samples[i],        // Sampled neutron energy (in lethargy)
				mat,             // Sampled material type index neutron is in
				in.n_isotopes,   // Total number of isotopes in simulation
				in.n_gridpoints, // Number of gridpoints per isotope in simulation
				GSD.num_nucs,     // 1-D array with number of nuclides per material
				GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
				GSD.unionized_energy_array, // 1-D Unionized energy array
				GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
				GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
				GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
				macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
				in.grid_type,    // Lookup type (nuclide, hash, or unionized)
				in.hash_bins,    // Number of hash bins used (if using hash lookup type)
				GSD.max_num_nucs  // Maximum number of nuclides present in any material
				);

		// For verification, and to prevent the compiler from optimizing
		// all work out, we interrogate the returned macro_xs_vector array
		// to find its maximum value index, then increment the verification
		// value by that index. In this implementation, we have each thread
		// write to its thread_id index in an array, which we will reduce
		// with a thrust reduction kernel after the main simulation kernel.
		double max = -1.0;
		int max_idx = 0;
		for(int j = 0; j < 5; j++ )
		{
			if( macro_xs_vector[j] > max )
			{
				max = macro_xs_vector[j];
				max_idx = j;
			}
		}
		GSD.verification[i] = max_idx+1;
	}
}


////////////////////////////////////////////////////////////////////////////////////
// Optimization 4 -- Kernel Splitting + All Material Lookups + Full Sort
////////////////////////////////////////////////////////////////////////////////////
// This optimization builds on optimization 2, adding in a full sort before
// hand so that the warps should be densely packed together. This should maximize
// SIMD efficiency of the kernel, but may incur an added cost for the sort.
////////////////////////////////////////////////////////////////////////////////////
unsigned long long run_event_based_simulation_optimization_4(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 4 - All Material Lookup Kernels + Material Sort";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Count the number of fuel material lookups that need to be performed (fuel id = 0)
	int n_lookups_per_material[12];
	for( int m = 0; m < 12; m++ )
		n_lookups_per_material[m] = thrust::count(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, m);

	// Sort materials
	thrust::sort_by_key(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, GSD.p_energy_samples);
	
	// Launch all material kernels individually
	int offset = 0;
	for( int m = 0; m < 12; m++ )
	{
		nthreads = 32;
		nblocks = ceil((double) n_lookups_per_material[m] / (double) nthreads);
		xs_lookup_kernel_optimization_4<<<nblocks, nthreads>>>( in, GSD, m, n_lookups_per_material[m], offset );
		offset += n_lookups_per_material[m];
	}
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

__global__ void xs_lookup_kernel_optimization_4(Inputs in, SimulationData GSD, int m, int n_lookups, int offset )

	// Perform macroscopic Cross Section Lookup

			mat,             // Sampled material type index neutron is in
			in.n_isotopes,   // Total number of isotopes in simulation
			in.n_gridpoints, // Number of gridpoints per isotope in simulation
			GSD.num_nucs,     // 1-D array with number of nuclides per material
			GSD.concs,        // Flattened 2-D array with concentration of each nuclide in each material
			GSD.unionized_energy_array, // 1-D Unionized energy array
			GSD.index_grid,   // Flattened 2-D grid holding indices into nuclide grid for each unionized energy level
			GSD.nuclide_grid, // Flattened 2-D grid holding energy levels and XS_data for all nuclides in simulation
			GSD.mats,         // Flattened 2-D array with nuclide indices defining composition of each type of material
			macro_xs_vector, // 1-D array with result of the macroscopic cross section (5 different reaction channels)
			in.grid_type,    // Lookup type (nuclide, hash, or unionized)
			in.hash_bins,    // Number of hash bins used (if using hash lookup type)
			GSD.max_num_nucs  // Maximum number of nuclides present in any material
			);

	// all work out, we interrogate the returned macro_xs_vector array

	// value by that index. In this implementation, we have each thread
	// write to its thread_id index in an array, which we will reduce
	// with a thrust reduction kernel after the main simulation kernel.
	double max = -1.0;
	int max_idx = 0;
	for(int j = 0; j < 5; j++ )
	{
		if( macro_xs_vector[j] > max )
		{
			max = macro_xs_vector[j];
			max_idx = j;
		}
	}
	GSD.verification[i] = max_idx+1;
}

////////////////////////////////////////////////////////////////////////////////////
// Optimization 5 -- Kernel Splitting + Fuel/Other Lookups + Fuel/Other Partition
////////////////////////////////////////////////////////////////////////////////////
// This optimization is similar to optimization 4, but instead of sorting
// fully by material, we just sort by fuel or not fuel. Similarly, instead of
// launching kernels for all materials, similar to optimization 3 we only launch
// kernels for the fuel and other mateirals.
////////////////////////////////////////////////////////////////////////////////////

// Comparator for partitioning stage
struct is_mat_fuel{
	__host__ __device__
		bool operator()(const int & a)
		{
			return a == 0;
		}
};

unsigned long long run_event_based_simulation_optimization_5(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 5 - Fuel/No Fuel Lookup Kernels + Fuel/No Fuel Sort";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");

	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Count the number of fuel material lookups that need to be performed (fuel id = 0)
	int n_fuel_lookups = thrust::count(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, 0);

	// Partition fuel into the first part of the array
	thrust::partition(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, GSD.p_energy_samples, is_mat_fuel());

	// Launch all material kernels individually (asynchronous is allowed)
	nblocks = ceil( (double) n_fuel_lookups / (double) nthreads);
	xs_lookup_kernel_optimization_5<<<nblocks, nthreads>>>( in, GSD, n_fuel_lookups, 0 );

	nblocks = ceil( (double) (in.lookups - n_fuel_lookups) / (double) nthreads);
	xs_lookup_kernel_optimization_5<<<nblocks, nthreads>>>( in, GSD, in.lookups-n_fuel_lookups, n_fuel_lookups );

	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);

	return verification_scalar;
}

////////////////////////////////////////////////////////////////////////////////////
// Optimization 6 -- Kernel Splitting + All Material Lookups + Full Sort
//                   + Energy Sort
////////////////////////////////////////////////////////////////////////////////////
// This optimization builds on optimization 4, adding in a second sort by energy.
// It is extremely fast, as now most of the threads within a warp will be hitting
// the same indices in the lookup grids. This greatly reduces thread divergence and
// greatly improves cache efficiency and re-use.
//
// However, it is unlikely that this exact optimization would be possible in a real
// application like OpenMC. One major difference is that particle objects are quite
// large, often having 50+ variable fields, such that sorting them in memory becomes
// rather expensive. Instead, the best possible option would probably be to create
// intermediate indexing (per Hamilton et. al 2019), and run the kernels indirectly.
////////////////////////////////////////////////////////////////////////////////////
unsigned long long run_event_based_simulation_optimization_6(Inputs in, SimulationData GSD, int mype)
{
	const char * optimization_name = "Optimization 6 - Material & Energy Sorts + Material-specific Kernels";
	
	if( mype == 0)	printf("Simulation Kernel:\"%s\"\n", optimization_name);
	
	////////////////////////////////////////////////////////////////////////////////
	// Allocate Additional Data Structures Needed by Optimized Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Allocating additional device data required by kernel...\n");
	size_t sz;
	size_t total_sz = 0;

	sz = in.lookups * sizeof(double);
	gpuErrchk( cudaMalloc((void **) &GSD.p_energy_samples, sz) );
	total_sz += sz;
	GSD.length_p_energy_samples = in.lookups;

	sz = in.lookups * sizeof(int);
	gpuErrchk( cudaMalloc((void **) &GSD.mat_samples, sz) );
	total_sz += sz;
	GSD.length_mat_samples = in.lookups;
	
	if( mype == 0)	printf("Allocated an additional %.0lf MB of data on GPU.\n", total_sz/1024.0/1024.0);

	////////////////////////////////////////////////////////////////////////////////
	// Configure & Launch Simulation Kernel
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Beginning optimized simulation...\n");

	int nthreads = 32;
	int nblocks = ceil( (double) in.lookups / 32.0);
	
	sampling_kernel<<<nblocks, nthreads>>>( in, GSD );
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	// Count the number of fuel material lookups that need to be performed (fuel id = 0)
	int n_lookups_per_material[12];
	for( int m = 0; m < 12; m++ )
		n_lookups_per_material[m] = thrust::count(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, m);

	// Sort by material first
	thrust::sort_by_key(thrust::device, GSD.mat_samples, GSD.mat_samples + in.lookups, GSD.p_energy_samples);

	// Now, sort each material by energy
	int offset = 0;
	for( int m = 0; m < 12; m++ )
	{
		thrust::sort_by_key(thrust::device, GSD.p_energy_samples + offset, GSD.p_energy_samples + offset + n_lookups_per_material[m], GSD.mat_samples + offset);
		offset += n_lookups_per_material[m];
	}
	
	// Launch all material kernels individually
	offset = 0;
	for( int m = 0; m < 12; m++ )
	{
		nthreads = 32;
		nblocks = ceil((double) n_lookups_per_material[m] / (double) nthreads);
		xs_lookup_kernel_optimization_4<<<nblocks, nthreads>>>( in, GSD, m, n_lookups_per_material[m], offset );
		offset += n_lookups_per_material[m];
	}
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );
	
	////////////////////////////////////////////////////////////////////////////////
	// Reduce Verification Results
	////////////////////////////////////////////////////////////////////////////////
	if( mype == 0)	printf("Reducing verification results...\n");

	unsigned long verification_scalar = thrust::reduce(thrust::device, GSD.verification, GSD.verification + in.lookups, 0);
	gpuErrchk( cudaPeekAtLastError() );
	gpuErrchk( cudaDeviceSynchronize() );

	return verification_scalar;
}

int double_compare(const void * a, const void * b)
{
	double A = *((double *) a);
	double B = *((double *) b);

	if( A > B )
		return 1;
	else if( A < B )
		return -1;
	else
		return 0;
}

int NGP_compare(const void * a, const void * b)
{
	NuclideGridPoint A = *((NuclideGridPoint *) a);
	NuclideGridPoint B = *((NuclideGridPoint *) b);

	if( A.energy > B.energy )
		return 1;
	else if( A.energy < B.energy )
		return -1;
	else
		return 0;
}


// RNG Used for Verification Option.
// This one has a static seed (must be set manually in source).
// Park & Miller Multiplicative Conguential Algorithm
// From "Numerical Recipes" Second Edition
double rn_v(void)
{
	static unsigned long seed = 1337;
	double ret;
	unsigned long n1;
	unsigned long a = 16807;
	unsigned long m = 2147483647;
	n1 = ( a * (seed) ) % m;
	seed = n1;
	ret = (double) n1 / m;
	return ret;
}


size_t estimate_mem_usage( Inputs in )
{
	size_t single_nuclide_grid = in.n_gridpoints * sizeof( NuclideGridPoint );
	size_t all_nuclide_grids   = in.n_isotopes * single_nuclide_grid;
	size_t size_UEG            = in.n_isotopes*in.n_gridpoints*sizeof(double) + in.n_isotopes*in.n_gridpoints*in.n_isotopes*sizeof(int);
	size_t size_hash_grid      = in.hash_bins * in.n_isotopes * sizeof(int);
	size_t memtotal;

	if( in.grid_type == UNIONIZED )
		memtotal          = all_nuclide_grids + size_UEG;
	else if( in.grid_type == NUCLIDE )
		memtotal          = all_nuclide_grids;
	else
		memtotal          = all_nuclide_grids + size_hash_grid;

	memtotal          = ceil(memtotal / (1024.0*1024.0));
	return memtotal;
}

double get_time(void)
{
	#ifdef MPI
	return MPI_Wtime();
	#endif

	#ifdef OPENMP
	return omp_get_wtime();
	#endif

	// If using C++, we can do this:
	unsigned long us_since_epoch = std::chrono::high_resolution_clock::now().time_since_epoch() / std::chrono::microseconds(1);
	return (double) us_since_epoch / 1.0e6;
}
