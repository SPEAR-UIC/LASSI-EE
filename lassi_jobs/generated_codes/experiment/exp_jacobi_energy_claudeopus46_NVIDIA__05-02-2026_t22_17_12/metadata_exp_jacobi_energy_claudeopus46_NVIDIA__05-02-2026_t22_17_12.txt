## Comparison Analysis

### Key Differences in the Refactored Code

**1. Larger Thread Block Dimensions (TILE_X=32, TILE_Y=16 vs 16x16)**
The refactored code uses 32×16 thread blocks (512 threads) instead of 16×16 (256 threads). This means each warp covers a full row of the tile (32 threads), which improves **global memory coalescing** since threads in a warp now access 32 consecutive addresses along the `i` dimension. The shared memory tile is also correspondingly resized to `[TILE_Y+2][TILE_X+2]` = `[18][34]`.

**2. Elimination of the Separate `swap_data` Kernel**
The source code launches a separate `swap_data` kernel every iteration to copy `f` back to `f_old`. The refactored code instead **swaps device pointers** (`float* tmp = d_f_old; d_f_old = d_f; d_f = tmp;`), completely eliminating a full kernel launch and the associated global memory reads/writes every iteration. This is a major source of energy savings.

**3. Infrequent Error Computation (Check Interval = 100)**
The source code computes and transfers the error **every single iteration**. The refactored code only computes the error every 100 iterations (`check_interval = 100`), using a lightweight `jacobi_step_no_error` kernel for the other 99 out of 100 iterations. This eliminates the `cudaMemset`, `cudaMemcpy`, warp-level reduction, and `atomicAdd` overhead for most iterations.

**4. Use of `__ldg()` Intrinsic for Read-Only Data**
All reads from `f_old` in the refactored kernels use `__ldg()` to route through the read-only texture cache, e.g., `__ldg(&f_old[IDX(i, j)])`. The source code accesses `f_old` directly without `__ldg()`.

**5. `__launch_bounds__` Annotation**
The refactored kernels use `__launch_bounds__(512, 4)` to hint the compiler about occupancy, allowing better register allocation decisions.

**6. Warp Reduction Adjusted and `#pragma unroll` Added**
The warp shuffle reduction loop starts at offset 16 (matching warp size 32) instead of 8, and uses `#pragma unroll` to unroll the reduction loops, reducing loop overhead.

**7. Removal of Implicit Synchronization via `cudaMemcpy`**
In the source code, `cudaMemcpy` of the error every iteration acts as an implicit synchronization barrier. In the refactored code, this synchronization only happens every 100 iterations, allowing the GPU to pipeline kernel launches more efficiently.
