- **Memory access coalescing:** Arrange data and indexing so the 32 threads of a warp access consecutive global-memory addresses. Prefer struct-of-arrays over array-of-structs when threads read the same field across many elements. This reduces the number of HBM2e transactions and is one of the highest-impact energy optimizations on A100, especially for memory-bound kernels.

- **Shared memory use:** Load reused global data once per block into shared memory, then have threads reuse the on-chip copy. Avoid shared-memory bank conflicts by using layouts where neighboring threads do not repeatedly hit the same bank. Most impactful when threads in a block access overlapping or nearby data, such as tiled stencils, reductions, matrix-like computations, or repeated table/grid lookups.

- **Occupancy optimization:** Use block sizes that are multiples of 32, typically 128–256 threads per block, and tune register and shared-memory usage so enough warps are resident to hide latency. Use the CUDA occupancy calculator or `cudaOccupancyMaxPotentialBlockSize`, and avoid register spilling to local memory. Most impactful when latency hiding is poor or when excessive registers/shared memory limit active warps per SM.

- **Warp divergence reduction:** Restructure control flow so threads in the same warp follow the same path. Use branchless selection or predication for short conditionals, keep branch bodies small, and group/sort inputs by execution path when possible. Most impactful when branches depend on per-thread data and large portions of a warp are inactive while other paths execute.

- **Kernel fusion:** Combine consecutive kernels that operate on the same data so intermediate values stay in registers or shared memory instead of being written to and reread from global memory. This also reduces launch overhead. Most impactful when kernels are memory-bound, have compatible launch configurations, and communicate through temporary global arrays.

- **Read-only cache / `__ldg`:** Mark read-only input arrays as `const __restrict__` and/or explicitly load them with `__ldg()` so the compiler can use the read-only/texture cache path. This can reduce L2 and DRAM pressure for repeated or spatially local reads. Most impactful for large read-only tables, lookup arrays, coefficients, and other data not modified by the kernel.

- **Arithmetic precision tradeoffs:** Use `float` instead of `double` when accuracy and verification allow, because FP32 uses less memory bandwidth, fewer registers, and much higher throughput than FP64 on A100. Use FMA where applicable and consider fast-math intrinsics only if their reduced precision is acceptable. Most impactful in compute-bound kernels or memory-bound kernels where double precision doubles data movement.

- **Synchronization minimization:** Remove unnecessary `__syncthreads()`, move barriers out of loops when possible, and use warp-level primitives such as `__syncwarp`, `__ballot_sync`, or warp reductions when synchronization is only needed within a warp. Reduce high-contention atomics by performing block-level reductions in shared memory and issuing fewer global atomics. Most impactful when barriers or atomics serialize otherwise parallel work.

- **Prefetching and transfer control:** Keep data resident on the GPU across kernel launches, use explicit `cudaMalloc`/`cudaMemcpy` where possible, and avoid unexpected Unified Memory page migrations. If Unified Memory is used, prefetch data to the GPU before kernels; otherwise use pinned memory and `cudaMemcpyAsync` with streams to overlap transfers with computation. Most impactful when host-device transfers or managed-memory migrations are visible in runtime or energy profiles.

## 1. Overall algorithm and GPU resource-utilization profile

### Algorithm
- The program solves a 2D Laplace/Jacobi relaxation problem on an `N x N` grid, with `N = 16384`.
- Two device arrays are maintained:
  - `d_f`: newly computed field.
  - `d_f_old`: previous iteration field.
- Each iteration performs:
  1. `cudaMemset(d_error, 0, 4)`
  2. `jacobi_step`: computes one Jacobi update and accumulates the squared residual/error.
  3. `swap_data`: copies the newly computed interior values from `d_f` back to `d_f_old`.
  4. `cudaMemcpy` of the scalar error from device to host.
  5. Host-side normalization and convergence test.

### Resource-utilization profile
- The computation is primarily **memory-bandwidth-bound**, not compute-bound.
- The Jacobi stencil has low arithmetic intensity:
  - Per interior point: roughly four neighbor reads, several additions, one multiply by `0.25f`, one subtraction, one square, and a store.
  - Shared memory reduces repeated global reads, but the total arithmetic per byte transferred remains low.
- The explicit `swap_data` kernel is purely a streaming memory copy for the interior of the grid and adds substantial memory traffic.
- The global error reduction uses one `atomicAdd()` per thread block into a single scalar. With over one million blocks, this creates severe atomic contention and is both performance- and energy-inefficient.
- Accesses are mostly **regular and structured**, not random.
- The main stencil and copy accesses are sequential along the `i` dimension, but the `16 x 16` block shape causes each warp to cover two half-rows rather than one full 32-element row, so memory coalescing is good but not ideal.

### Major energy-efficiency opportunities
- Replace the explicit `swap_data` copy kernel with a pointer swap between `d_f` and `d_f_old`.
  - This would eliminate one full-grid read and one full-grid write per iteration.
  - It would also remove one kernel launch per iteration.
- Replace the single-scalar `atomicAdd(error, err)` reduction with a hierarchical reduction:
  - Per-block partial sums into a temporary array.
  - Then a second-stage reduction using CUB, cooperative groups, or a custom reduction kernel.
  - This would greatly reduce global atomic contention.
- Avoid copying `d_error` to the host every iteration if exact per-iteration convergence checking is not required.
  - Checking every several iterations would reduce CPU-GPU synchronization overhead.
- Consider using CUDA Graphs if the iteration structure remains fixed.
  - The current loop launches at least two kernels and performs a device-to-host synchronization every iteration.
- Consider using a block shape with `blockDim.x = 32`, such as `32 x 8`, to improve full-warp coalescing along the contiguous `i` dimension.

## 3. Global memory access patterns in each kernel

## `jacobi_step`

### Main interior load
Each thread initially loads:

- `f_old[IDX(i,j)]`

Because `IDX(i,j) = i + j * N`, consecutive `i` values are contiguous in memory.

- Consecutive `threadIdx.x` values access consecutive addresses.
- However, with `blockDim.x = 16`, a warp spans two rows:
  - Lanes 0–15 cover one row.
  - Lanes 16–31 cover the next row.
- Therefore each warp generally issues two contiguous half-warp memory segments rather than one full 32-thread contiguous segment.
- Access pattern: **coalesced in half-warp segments, but not optimally full-warp coalesced**.

### Halo loads
The kernel loads halo values into shared memory using selected boundary threads.

#### Left halo
Condition:

- `threadIdx.x == 0 && i >= 1`

Access:

- `f_old[IDX(i-1,j)]`

Only one thread per row performs this load.

- Within a warp, only two lanes typically participate because each warp spans two rows.
- Addresses for different rows are separated by `N`.
- Access pattern: **sparse/scattered across participating lanes**, not fully coalesced.

#### Right halo
Condition:

- `threadIdx.x == 15 && i <= N-2`

Access:

- `f_old[IDX(i+1,j)]`

Similar to the left halo.

- Access pattern: **sparse/scattered across participating lanes**, not fully coalesced.

#### Bottom/top row halos
Conditions:

- `threadIdx.y == 0 && j >= 1`
- `threadIdx.y == 15 && j <= N-2`

Accesses:

- `f_old[IDX(i,j-1)]`
- `f_old[IDX(i,j+1)]`

For the participating row, consecutive `threadIdx.x` values access consecutive memory locations.

- Access pattern: **coalesced over 16 contiguous elements**, but only half-warp width due to `blockDim.x = 16`.

### Output store
Interior threads store:

- `f[IDX(i,j)]`

This follows the same layout as the main load.

- Consecutive `threadIdx.x` values store consecutive addresses.
- Warps cover two 16-element row segments.
- Access pattern: **coalesced in half-warp segments, not ideal full-warp coalescing**.

### Error atomic
Each block performs:

- `atomicAdd(error, err)`

There is one atomic update per block, so approximately:

- `1,048,576` atomics per Jacobi iteration.

All atomics target the same global memory location.

- Access pattern: **maximally contended single-address atomic**.
- This is a major performance and energy-efficiency problem.

## `swap_data`

Interior threads perform:

- Load: `f[IDX(i,j)]`
- Store: `f_old[IDX(i,j)]`

Access pattern:

- Consecutive `threadIdx.x` values access consecutive addresses.
- Each warp spans two 16-element row segments.
- Access pattern: **regular, sequential, and coalesced in half-warp segments**.

Energy note:

- This kernel reads and writes almost the entire grid every iteration.
- For `N = 16384`, each full grid is approximately 1 GiB.
- The copy therefore adds roughly 2 GiB of memory traffic per iteration, excluding cache effects and boundary exclusions.
- This is the largest avoidable memory-traffic opportunity in the program.

## 4. Shared memory usage

## Current shared memory usage in `jacobi_step`

### Stencil tile
The kernel uses:

- `__shared__ float f_old_tile[18][18];`

This stores:

- A `16 x 16` interior tile.
- One-cell halo on each side.

Purpose:

- Reduce redundant global memory loads for neighboring values.
- Improve data reuse within the block.

### Reduction buffer
The kernel also uses:

- `__shared__ float reduction_array[16];`

Size:

- `16 * sizeof(float) = 64` bytes.

Purpose:

- Store one partial error sum per row before reducing across the first row of threads.

### Total shared memory
Approximate total per block:

- `1360` bytes.

This is very small relative to A100 shared-memory capacity and should not limit occupancy.

## Potential shared-memory opportunities

### Current tiling is reasonable but may not be energy-optimal
The shared-memory tile reduces global memory traffic, but it introduces:

- Halo-loading branches.
- Two `__syncthreads()` barriers.
- Shared-memory traffic.
- More complex reduction logic.

For a simple 5-point stencil on A100, the hardware L1/L2 cache may already capture much of the neighbor reuse. It may be worth comparing:

- Current shared-memory tiled version.
- A simpler direct global-memory stencil relying on L1/L2 cache.
- A larger tile with better surface-to-volume ratio.
- A `32 x 8` tile to improve coalescing.

### Better tile shape
A `32 x 8` block may improve energy efficiency because:

- A warp can map to one full contiguous row.
- Global loads and stores become more naturally full-warp coalesced.
- Halo overhead may be comparable or lower depending on implementation.

### Reduction improvement
The shared-memory reduction is lightweight, but the global atomic strategy is not. The larger opportunity is not in shared memory itself but in replacing the one-atomic-per-block global reduction with a hierarchical reduction.

## 5. Warp divergence

## `jacobi_step`

### Halo-loading branches
The following conditionals create divergence because only selected threads in each block participate:

- `if (threadIdx.x == 0 && i >= 1)`
- `if (threadIdx.x == 15 && i <= N-2)`
- `if (threadIdx.y == 0 && j >= 1)`
- `if (threadIdx.y == 15 && j <= N-2)`

These are mostly structural divergence due to halo loading.

### Interior-domain branches
The main computation is guarded by:

- `if (j >= 1 && j <= N-2)`
- `if (i >= 1 && i <= N-2)`

For most blocks in the interior of the domain, these conditions are uniformly true.

Divergence occurs primarily in boundary blocks:

- `i = 0`
- `i = N-1`
- `j = 0`
- `j = N-1`

The fraction of boundary blocks is small, so this divergence is not the dominant cost.

### Reduction branches
The reduction contains:

- `if (threadIdx.x == 0)`
- `if (threadIdx.y == 0)`
- nested `if (threadIdx.x == 0)`

These create warp divergence because only subsets of lanes participate.

Important note:

- The code uses `__shfl_down_sync(0xffffffff, ...)` inside the `if (threadIdx.y == 0)` branch.
- Since `blockDim.x = 16`, `threadIdx.y == 0` activates only half of the first warp.
- Using a full mask, `0xffffffff`, in a partially active warp region is unusual and potentially unsafe on modern CUDA architectures.
- The behavior depends on how the compiler and warp execution handle the divergent region.
- From an energy-efficiency standpoint, this reduction structure is also not ideal because it contributes to control-flow overhead and feeds a highly contended global atomic.

## `swap_data`

The copy is guarded by:

- `if (j >= 1 && j <= N-2)`
- `if (i >= 1 && i <= N-2)`

As with `jacobi_step`, divergence occurs mainly in boundary blocks. Most interior blocks execute uniformly.

// A multiple of thread block size
#define N 16384

#define IDX(i, j) ((i) + (j) * N)

void initialize_data (float* f) {
  // Set up simple sinusoidal boundary conditions
  for (int j = 0; j < N; ++j) {
    for (int i = 0; i < N; ++i) {

      if (i == 0 || i == N-1) {
        f[IDX(i,j)] = sinf(j * 2 * M_PI / (N - 1));
      }
      else if (j == 0 || j == N-1) {
        f[IDX(i,j)] = sinf(i * 2 * M_PI / (N - 1));
      }
      else {
        f[IDX(i,j)] = 0.0f;
      }

    }
  }
}

__global__ void jacobi_step (float*__restrict__ f, 
                             const float*__restrict__ f_old, 
                             float*__restrict__ error) {
  __shared__ float f_old_tile[18][18];

  int i = threadIdx.x + blockIdx.x * blockDim.x;
  int j = threadIdx.y + blockIdx.y * blockDim.y;

  // First read in the "interior" data, one value per thread
  // Note the offset by 1, to reserve space for the "left"/"bottom" halo

  f_old_tile[threadIdx.y+1][threadIdx.x+1] = f_old[IDX(i,j)];

  // Now read in the halo data; we'll pick the "closest" thread
  // to each element. When we do this, make sure we don't fall
  // off the end of the global memory array. Note that this
  // code does not fill the corners, as they are not used in
  // this stencil.

  if (threadIdx.x == 0 && i >= 1) {
    f_old_tile[threadIdx.y+1][threadIdx.x+0] = f_old[IDX(i-1,j)];
  }
  if (threadIdx.x == 15 && i <= N-2) {
    f_old_tile[threadIdx.y+1][threadIdx.x+2] = f_old[IDX(i+1,j)];
  }
  if (threadIdx.y == 0 && j >= 1) {
    f_old_tile[threadIdx.y+0][threadIdx.x+1] = f_old[IDX(i,j-1)];
  }
  if (threadIdx.y == 15 && j <= N-2) {
    f_old_tile[threadIdx.y+2][threadIdx.x+1] = f_old[IDX(i,j+1)];
  }

  // Synchronize all threads
  __syncthreads();

  float err = 0.0f;

  if (j >= 1 && j <= N-2) {
    if (i >= 1 && i <= N-2) {
      // Perform the read from shared memory
      f[IDX(i,j)] = 0.25f * (f_old_tile[threadIdx.y+1][threadIdx.x+2] + 
                             f_old_tile[threadIdx.y+1][threadIdx.x+0] + 
                             f_old_tile[threadIdx.y+2][threadIdx.x+1] + 
                             f_old_tile[threadIdx.y+0][threadIdx.x+1]);
      float df = f[IDX(i,j)] - f_old_tile[threadIdx.y+1][threadIdx.x+1];
      err = df * df;
    }
  }

  // Sum over threads in the warp
  // For simplicity, we do this outside the above conditional
  // so that all threads participate
  for (int offset = 8; offset > 0; offset /= 2) {
    err += __shfl_down_sync(0xffffffff, err, offset);
  }

  // If we're thread 0 in the warp, update our value to shared memory
  // Note that we're assuming exactly a 16x16 block and that the warp ID
  // is equivalent to threadIdx.y. For the general case, we would have to
  // write more careful code.
  __shared__ float reduction_array[16];
  if (threadIdx.x == 0) {
    reduction_array[threadIdx.y] = err;
  }

  // Synchronize the block before reading any values from smem
  __syncthreads();

  // Using the first warp in the block, reduce over the partial sums
  // in the shared memory array.
  if (threadIdx.y == 0) {
    err = reduction_array[threadIdx.x];
    for (int offset = 8; offset > 0; offset /= 2) {
      err += __shfl_down_sync(0xffffffff, err, offset);
    }
    if (threadIdx.x == 0) {
      atomicAdd(error, err);
    }
  }
}

__global__ void swap_data (const float*__restrict__ f,
                                 float*__restrict__ f_old) {
  int i = threadIdx.x + blockIdx.x * blockDim.x;
  int j = threadIdx.y + blockIdx.y * blockDim.y;

  if (j >= 1 && j <= N-2) {
    if (i >= 1 && i <= N-2) {
      f_old[IDX(i,j)] = f[IDX(i,j)];
    }
  }
}

    // We're doing this explicitly for pedagogical purposes, even though
    // in this specific application a std::swap would have been OK
    swap_data<<<grid, block>>>(d_f, d_f_old);

    cudaMemcpy(&error, d_error, sizeof(float), cudaMemcpyDeviceToHost);

    // Normalize the L2-norm of the error by the number of data points
    // and then take the square root
    error = sqrtf(error / (N * N));

    // Periodically print out the current error
    if (num_iters % 1000 == 0) {
      std::cout << "Error after iteration " << num_iters << " = " << error << std::endl;
    }

    // Increment the iteration count
    ++num_iters;
  }

  cudaDeviceSynchronize();
  auto end = std::chrono::steady_clock::now();
  auto time = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start).count();
  std::cout << "Average execution time per iteration: " << (time * 1e-9f) / num_iters << " (s)\n";

  // If we took fewer than max_iters steps and the error is below the tolerance,
  // we succeeded. Otherwise, we failed.

  if (error <= tolerance && num_iters < max_iters) {
    std::cout << "PASS" << std::endl;
  }
  else {
    std::cout << "FAIL" << std::endl;
    return -1;
  }

  // CLean up memory allocations
  cudaFree(d_f);
  cudaFree(d_f_old);
  cudaFree(d_error);
  free(f);
  free(f_old);

  // End wall timing
  double duration = (std::clock() - start_time) / (double) CLOCKS_PER_SEC;
  std::cout << "Total elapsed time: " << std::setprecision(4) << duration << " seconds" << std::endl;

  return 0;
