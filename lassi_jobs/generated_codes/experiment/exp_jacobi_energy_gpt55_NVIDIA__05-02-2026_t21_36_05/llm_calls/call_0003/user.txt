- **Memory access coalescing**: Arrange global memory accesses so consecutive threads in a warp read/write consecutive elements. Prefer struct-of-arrays over array-of-structs when threads access one field across many objects. Avoid strided patterns such as `arr[threadIdx.x * N + j]`; transpose layouts or loop order so accesses look like `arr[j * blockDim.x + threadIdx.x]`.  
  **Most impactful when** the kernel is memory-bound and DRAM traffic dominates energy, which is common on A100 for large HBM-resident datasets.

- **Shared memory use**: Use shared memory to stage data that is reused by multiple threads in a block, replacing repeated HBM accesses with low-energy on-chip SRAM accesses. Tile global memory loads cooperatively, then reuse the tile from shared memory. Avoid shared-memory bank conflicts by ensuring warp threads do not map heavily to the same bank.  
  **Most impactful when** there is spatial or temporal reuse within a thread block, such as stencil, matrix/tile, reduction, or repeated lookup patterns.

For A100, 128–256 threads per block is often a good starting point. Use the CUDA occupancy calculator or `cudaOccupancyMaxPotentialBlockSize`. Keep branch bodies small so the compiler can predicate them.

  **Most impactful when** kernels are bandwidth-bound, use temporary global-memory arrays, or perform simple producer-consumer stages with compatible launch configurations.

## 1. Overall Algorithm and GPU Resource Utilization Profile

### Algorithm
- The program solves a 2D relaxation problem using Jacobi iteration on an `N x N` grid, where `N = 16384`.
- Two device arrays are used:
  - `d_f`: current/new solution field.
  - `d_f_old`: previous iteration field.
- Each iteration performs:
  1. Reset global scalar error to zero with `cudaMemset`.
  2. Run `jacobi_step`:
     - Load a 16x16 tile plus halo into shared memory.
     - Update interior points using a 4-point stencil.
     - Accumulate squared update difference into a global error using reductions plus `atomicAdd`.
  3. Run `swap_data`:
     - Copy updated interior values from `d_f` back into `d_f_old`.
  4. Copy error back to host.
  5. Normalize error and check convergence.

### Resource Utilization Profile
- The computation is primarily **memory-bandwidth-bound**, not compute-bound.
- The stencil update performs only a small number of floating-point operations per grid point:
  - Four neighbor reads from shared memory.
  - Several additions.
  - One multiplication by `0.25f`.
  - One subtraction.
  - One square operation for the error.
- The arithmetic intensity is low, especially because each iteration also performs a full-grid copy in `swap_data`.

### Major Energy-Efficiency Bottlenecks
- The explicit `swap_data` kernel performs an additional full read/write pass over nearly the entire grid every iteration.
  - This is a major memory-traffic and energy cost.
  - Since the comments indicate pointer swapping would be valid for this application, replacing the explicit copy with pointer swapping would significantly reduce memory traffic and kernel-launch overhead.
- The global error accumulation uses one `atomicAdd` per thread block into a single scalar.
  - With grid size `1024 x 1024`, that is **1,048,576 global atomics per iteration** to the same memory location.
  - This creates severe serialization, high memory-system pressure, and poor energy efficiency.
  - A hierarchical reduction would be much more energy efficient.
- The device-to-host `cudaMemcpy` of the error every iteration causes a synchronization point.
  - This prevents overlap and forces the GPU/CPU to synchronize once per iteration.
  - Checking convergence less frequently, if algorithmically acceptable, would reduce synchronization overhead and improve energy efficiency.
- The problem size is very large:
  - Each full grid contains `16384 x 16384 = 268,435,456` floats.
  - Each array is approximately 1 GiB.
  - Two arrays require approximately 2 GiB of device memory, not counting overhead.

## 3. Global Memory Access Patterns

## `jacobi_step`

### Main Tile Load
Each thread loads one element:

- Access pattern: `f_old[IDX(i,j)]`
- `IDX(i,j)` maps to `i + j * N`, so `i` is the unit-stride dimension.
- `threadIdx.x` maps to consecutive `i` values.
- Therefore, consecutive threads along `x` access consecutive memory addresses.

However, because the block shape is `16 x 16`, a CUDA warp contains two rows of 16 threads each:
- Lanes 0–15 access one contiguous 16-float segment.
- Lanes 16–31 access another contiguous 16-float segment in the next row, separated by a stride of `N`.

This is still mostly coalesced, but not as ideal as a block layout where each warp covers 32 consecutive `i` values.

### Left and Right Halo Loads
Branches:
- Threads with `threadIdx.x == 0` load the left halo.
- Threads with `threadIdx.x == 15` load the right halo.

Access pattern:
- One thread per row performs the halo load.
- Addresses are separated by the row stride `N`.
- These accesses are **scattered/strided** across the warp and are not well coalesced.

Energy impact:
- Low total volume compared with the main tile load.
- Still inefficient at the memory-transaction level.

### Bottom and Top Halo Loads
Branches:
- Threads with `threadIdx.y == 0` load one halo row.
- Threads with `threadIdx.y == 15` load one halo row.

Access pattern:
- Threads along `x` access consecutive `i` values.
- These accesses are mostly **coalesced** within each 16-thread row segment.

### Stencil Store
Interior threads write:

- `f[IDX(i,j)]`

Access pattern:
- Consecutive `threadIdx.x` values write consecutive addresses.
- Mostly coalesced, again in 16-thread row segments because each warp covers two rows.

### Error Accumulation
- Each block eventually performs one `atomicAdd` to a single global scalar.
- Access pattern:
  - All blocks target the same address.
  - This is a highly contended global atomic access pattern.
- This is one of the most important energy-efficiency problems in the code.

### Potential Redundant Global Access
- The code writes the new value to `f[IDX(i,j)]` and then uses `f[IDX(i,j)]` immediately to compute the difference.
- A compiler may keep the computed value in a register, but source-level structure exposes a possible redundant global read.
- Energy-efficient form would compute the new value in a local variable, use it for the error, then store it once.

## `swap_data`

### Interior Copy
Each interior thread copies:

- From `f[IDX(i,j)]`
- To `f_old[IDX(i,j)]`

Access pattern:
- Mostly coalesced because `threadIdx.x` maps to consecutive `i` values.
- Boundary blocks have some inactive threads due to the interior-only condition.
- Interior blocks have all threads active and coalesced.

### Energy Impact
- The access pattern is good, but the kernel itself is expensive because it performs a full-grid memory copy every iteration.
- This is a prime energy-efficiency opportunity:
  - Avoiding this copy via pointer swapping would remove a full read/write pass over the grid per iteration.

## 4. Shared Memory Usage

## Current Shared Memory Usage in `jacobi_step`

### Tile Storage
- `f_old_tile[18][18]` stores:
  - A 16x16 interior tile.
  - One-cell halo on each side.
  - Corners are not filled because the 4-point stencil does not use them.

This reduces repeated global memory reads of neighboring values.

### Reduction Storage

### Shared Memory Footprint

## 5. Warp Divergence

## `jacobi_step`

### Halo Loading Branches
The following conditions cause divergence because only some threads in each block execute them:

- `threadIdx.x == 15 && i <= N-2`
- `threadIdx.y == 0 && j >= 1`
- `threadIdx.y == 15 && j <= N-2`

Divergence characteristics:
- These branches are executed by boundary rows or columns of each block.
- They are predictable and limited in scope.
- Divergence cost is modest, but the resulting memory accesses are partly non-coalesced.

### Interior Update Branches
The stencil update is guarded by:

- `j >= 1 && j <= N-2`
- `i >= 1 && i <= N-2`

Divergence characteristics:
- For blocks fully inside the domain, all threads take the same path.
- Divergence occurs only for blocks touching the global domain boundary.
- Since the grid is very large, the fraction of boundary blocks is small.
- Energy impact is minor.

### Reduction Branches
The reduction contains branches based on thread index:

- `threadIdx.x == 0`
- `threadIdx.y == 0`
- Nested `threadIdx.x == 0` inside the `threadIdx.y == 0` branch.

Divergence characteristics:
- These are intentionally selective branches.
- They cause warp divergence because only a subset of lanes participate.
- The cost is small relative to global memory and atomic overhead, but the reduction implementation is tightly coupled to the `16 x 16` block shape.

### Important Correctness/Efficiency Concern
- The final reduction executes a warp shuffle inside a branch where only `threadIdx.y == 0` participates.
- The shuffle uses a full warp mask while only a subset of lanes in the warp are active.
- On modern CUDA architectures, using a mask that names lanes not participating in the intrinsic can be unsafe.
- This should be reviewed carefully for correctness and portability.

## `swap_data`

### Interior Copy Branches
The copy is guarded by:

- `j >= 1 && j <= N-2`
- `i >= 1 && i <= N-2`

Divergence characteristics:
- Interior blocks have no divergence because all threads satisfy the condition.
- Boundary blocks have inactive boundary threads.
- Overall divergence cost is small because boundary blocks are a tiny fraction of all blocks.

// A multiple of thread block size
#define N 16384

#define IDX(i, j) ((i) + (j) * N)

void initialize_data (float* f) {
  // Set up simple sinusoidal boundary conditions
  for (int j = 0; j < N; ++j) {
    for (int i = 0; i < N; ++i) {

      if (i == 0 || i == N-1) {
        f[IDX(i,j)] = sinf(j * 2 * M_PI / (N - 1));
      }
      else if (j == 0 || j == N-1) {
        f[IDX(i,j)] = sinf(i * 2 * M_PI / (N - 1));
      }
      else {
        f[IDX(i,j)] = 0.0f;
      }

    }
  }
}

__global__ void jacobi_step (float*__restrict__ f, 
                             const float*__restrict__ f_old, 
                             float*__restrict__ error) {
  __shared__ float f_old_tile[18][18];

  int i = threadIdx.x + blockIdx.x * blockDim.x;
  int j = threadIdx.y + blockIdx.y * blockDim.y;

  // First read in the "interior" data, one value per thread
  // Note the offset by 1, to reserve space for the "left"/"bottom" halo

  f_old_tile[threadIdx.y+1][threadIdx.x+1] = f_old[IDX(i,j)];

  // Now read in the halo data; we'll pick the "closest" thread
  // to each element. When we do this, make sure we don't fall
  // off the end of the global memory array. Note that this
  // code does not fill the corners, as they are not used in
  // this stencil.

  if (threadIdx.x == 0 && i >= 1) {
    f_old_tile[threadIdx.y+1][threadIdx.x+0] = f_old[IDX(i-1,j)];
  }
  if (threadIdx.x == 15 && i <= N-2) {
    f_old_tile[threadIdx.y+1][threadIdx.x+2] = f_old[IDX(i+1,j)];
  }
  if (threadIdx.y == 0 && j >= 1) {
    f_old_tile[threadIdx.y+0][threadIdx.x+1] = f_old[IDX(i,j-1)];
  }
  if (threadIdx.y == 15 && j <= N-2) {
    f_old_tile[threadIdx.y+2][threadIdx.x+1] = f_old[IDX(i,j+1)];
  }

  // Synchronize all threads
  __syncthreads();

  float err = 0.0f;

  if (j >= 1 && j <= N-2) {
    if (i >= 1 && i <= N-2) {
      // Perform the read from shared memory
      f[IDX(i,j)] = 0.25f * (f_old_tile[threadIdx.y+1][threadIdx.x+2] + 
                             f_old_tile[threadIdx.y+1][threadIdx.x+0] + 
                             f_old_tile[threadIdx.y+2][threadIdx.x+1] + 
                             f_old_tile[threadIdx.y+0][threadIdx.x+1]);
      float df = f[IDX(i,j)] - f_old_tile[threadIdx.y+1][threadIdx.x+1];
      err = df * df;
    }
  }

  // Sum over threads in the warp
  // For simplicity, we do this outside the above conditional
  // so that all threads participate
  for (int offset = 8; offset > 0; offset /= 2) {
    err += __shfl_down_sync(0xffffffff, err, offset);
  }

  // If we're thread 0 in the warp, update our value to shared memory
  // Note that we're assuming exactly a 16x16 block and that the warp ID
  // is equivalent to threadIdx.y. For the general case, we would have to
  // write more careful code.
  __shared__ float reduction_array[16];
  if (threadIdx.x == 0) {
    reduction_array[threadIdx.y] = err;
  }

  // Synchronize the block before reading any values from smem
  __syncthreads();

  // Using the first warp in the block, reduce over the partial sums
  // in the shared memory array.
  if (threadIdx.y == 0) {
    err = reduction_array[threadIdx.x];
    for (int offset = 8; offset > 0; offset /= 2) {
      err += __shfl_down_sync(0xffffffff, err, offset);
    }
    if (threadIdx.x == 0) {
      atomicAdd(error, err);
    }
  }
}

__global__ void swap_data (const float*__restrict__ f,
                                 float*__restrict__ f_old) {
  int i = threadIdx.x + blockIdx.x * blockDim.x;
  int j = threadIdx.y + blockIdx.y * blockDim.y;

  if (j >= 1 && j <= N-2) {
    if (i >= 1 && i <= N-2) {
      f_old[IDX(i,j)] = f[IDX(i,j)];
    }
  }
}

  int num_iters = 0;

  dim3 grid (N/16, N/16);
  dim3 block (16, 16);

  cudaDeviceSynchronize();
  auto start = std::chrono::steady_clock::now();

  while (error > tolerance && num_iters < max_iters) {
    // Initialize error to zero (we'll add to it the following step)
    cudaMemset(d_error, 0, 4);

    // Perform a Jacobi relaxation step
    jacobi_step<<<grid, block>>>(d_f, d_f_old, d_error);

    // Swap the old data and the new data
    // We're doing this explicitly for pedagogical purposes, even though
    // in this specific application a std::swap would have been OK
    swap_data<<<grid, block>>>(d_f, d_f_old);

    cudaMemcpy(&error, d_error, sizeof(float), cudaMemcpyDeviceToHost);

    // Normalize the L2-norm of the error by the number of data points
    // and then take the square root
    error = sqrtf(error / (N * N));

    // Periodically print out the current error
    if (num_iters % 1000 == 0) {
      std::cout << "Error after iteration " << num_iters << " = " << error << std::endl;
    }

    // Increment the iteration count
    ++num_iters;
  }

  cudaDeviceSynchronize();
  auto end = std::chrono::steady_clock::now();
  auto time = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start).count();
  std::cout << "Average execution time per iteration: " << (time * 1e-9f) / num_iters << " (s)\n";

  // we succeeded. Otherwise, we failed.

  if (error <= tolerance && num_iters < max_iters) {

  }
  else {
    std::cout << "FAIL" << std::endl;
    return -1;

  // CLean up memory allocations
  cudaFree(d_f);
  cudaFree(d_f_old);
  cudaFree(d_error);
  free(f);
